FLProg OTA — блок v0.4

1. Скопируйте три библиотеки из папки Библиотека общего комплекта в
   portable/sketchbook/libraries реальной IDE FLProg. Перезапустите FLProg.
2. Импортируйте FLProg_OTA_Universal.ubi в пользовательские блоки FLProg.
   Это новая версия блока: замените старый OTA-блок, один блок на проект.
3. Настройте SPI и Ethernet обычными средствами проекта FLProg.
   Блок использует существующий сетевой интерфейс, а не создаёт свою сеть.
4. Входы:
   EN = true — разрешить OTA.
   NET_NUM = номер сети проекта (обычно 1).
   PASSWORD = строка, допускается пустая.
   VERSION = строка, например "1.0.0", максимум 31 байт UTF-8.
   Версию задавайте константой для каждой сборки.
5. Выходы: SUPPORTED, READY, BUSY, FAULT, STATE, ERR, RX_BYTES.
   READY=true означает готовность OTA. При недоступном интерфейсе блок ждёт сеть.

Сборка и выбор файлов
На вкладке менеджера «Плата и сборка» выберите точную плату и экспортированный
из FLProg файл .ino, затем «Собрать BIN и пакет». Менеджер соберёт приложение
по OTA-адресу, создаст .fwpkg и автоматически выберет его на вкладке «Прошивка».
Кнопка «Файлы платы» открывает build_tools/output/ИМЯ_ПЛАТЫ:
bootloader.bin — загрузчик; application.bin — приложение вашего проекта;
ИМЯ_ПЛАТЫ.fwpkg — пакет обоих файлов (появится после сборки приложения).

Предустановленные профили «нужен BIN проекта» содержат только загрузчик.
Наличие загрузчика не означает наличие приложения с настройками вашего ПЛК.
Для такого профиля выберите свой OTA BIN или соберите полный пакет из .ino.
Тестовые профили сохранены отдельно; их application.bin — тестовая программа.

Обнаружение и защита загрузчика
Модель передаётся из выбранной платы сборки, версия — со входа VERSION.
Это имя платы из конфигурации, не автоматическое определение модели корпуса.
Новый менеджер показывает их по запросу FLPINFO? на TCP 3233.
Для первой установки нужны совместимый загрузчик и приложение через SWD.
Дальнейшие OTA-обновления записывают staging, затем загрузчик переносит образ
в область приложения. Область самого загрузчика не стирается и не записывается.
Неверное смещение приложения запрещено при компиляции; менеджер проверяет
размер и адрес BIN, прошивка проверяет разметку, размер Flash и векторы.
После успешного OTA выполняется автоматический перезапуск.
Это не аппаратная защита от внешнего полного стирания через ST-Link.

Текущие STM32: F407 512/1024 KiB и F103 256/512 KiB, Ethernet W5500.
RMII и остальные семейства пока не реализованы этим STM32 OTA-блоком.
Загрузчики скомпилированы; проверка каждой новой платы на оборудовании нужна.
