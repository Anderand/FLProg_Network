# FLProg W5500 Тест v0.2

Блок получает существующий Ethernet-интерфейс по `NET_NUM` и раз в секунду
обновляет выходы диагностики. Он не настраивает SPI/Ethernet и не пишет в
консоль напрямую. Выходы можно передать блокам RT_HW Console, как в приложенном
проекте.

## Входы

- `EN` — разрешить обновление диагностических значений;
- `NET_NUM` — номер сетевого интерфейса FLProg, обычно `1` для
  `FLPROG_WIZNET_INTERFACE1`.

## Выходы

`FOUND`, `MODE`, `WIZNET`, `RMII`, `SPI_BUS`, `SPI_EFF_BUS`, `CS_PIN`, `CHIP`,
`CHIP_CODE`, `HW_STATUS`, `SPI_STATUS`, `SPI_TX`, `LINK`, `ETH_READY`, `IP`,
`IP_ASSIGNED`, `DHCP_STATE`, `DHCP_ERROR`, `DHCP_SERVER`, `NET_STATUS`,
`NET_ERROR`, `RESULT`, `SEQ`, `MS`, `LINE`.

`LINE` — короткая строка для проверки поднятия Ethernet: `found`, `chip`,
`spi` (SPI_STATUS), `tx` (счётчик SPI обменов), `link`, `ready`, `ip`, `dhcp`
(DHCP_STATE/DHCP_ERROR) и `net` (NET_STATUS/NET_ERROR). Её можно передать
напрямую в строковый вход RT_HW Console. Полные диагностические параметры,
включая SPI-пины, режим, DHCP-сервер и время, доступны на отдельных выходах.
При `EN=0` выходы сбрасываются.

`RESULT=1`, когда найден интерфейс, код чипа равен 55, Ethernet готов и IP
отличается от `0.0.0.0`. Если интерфейс не зарегистрирован, `FOUND=0`, а
остальные выходы сброшены.

## Использование

1. Импортируй `FLProg_W5500_Diagnostic.ubi` в пользовательские блоки FLProg.
2. Оставь настройку шины SPI, W5500, DHCP и обслуживание сети сетевым блокам
   FLProg. Добавь/настрой в схеме RT_HW Console.
3. Добавь `FLProg W5500 Тест`, подай `EN=1` и фактический `NET_NUM`.
4. Подключи `LINE` к строковому каналу консоли. При необходимости выведи и
   отдельные параметры на другие каналы консоли.

Блок регистрирует уже объявленные FLProg Wiznet-интерфейсы по их номерам,
чтобы прочитать выбранный через `NET_NUM` объект. В нём нет пользовательского
заголовка или собственной UART/консольной настройки. Используются только
`FLProg_Network` и существующая система RT_HW Console проекта.
