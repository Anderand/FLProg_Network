# FLProg STM32 OTA Manager v0.7.9

Запустите FLProg_STM32_OTA_Manager.exe. Переносите всю папку целиком.
Python отдельно не нужен. EXE Windows x64; Windows 7 отдельно не проверялась.
Для компиляции нужны Arduino IDE FLProg, ядро STM32 3.0.0 и обновлённая
FLProg_Network. Для записи через SWD — STM32CubeProgrammer и ST-Link.

## Плата и сборка

Перед компиляцией автоматически проверяются скетч, core3.0.0, заголовок
ID_webui.h, паспорт пакета и совместимость runtime. Кнопка «Проверить
совместимость» позволяет сделать это отдельно, без сборки или прошивки.
Укажите внешнюю папку libraries проекта. Старый пакет WebUI без паспорта
сначала пересоберите новым редактором. Подробнее: СОВМЕСТИМОСТЬ.md.

По умолчанию доступен проверенный профиль FLE4D-30MT. Каталог остальных
плат и профилей показывается по галочке непроверенных. К профилям с пометкой
«нужен BIN проекта» надо выбрать свой OTA BIN или собрать пакет из .ino.
«Выбрать профиль платы» переносит выбранную плату на вкладку «Прошивка».
«Файлы платы» открывает её каталог с bootloader.bin и результатами сборки.
Полный пакет с application.bin появляется после сборки вашего проекта.
Блок v0.4 с входом VERSION и инструкцией находится в FLProg_OTA_Block.

Выберите точную плату, папку IDE и экспортированный скетч FLProg с OTA-блоком.
SPI, CS, MAC, IP и DHCP задаются в проекте FLProg.

- «Собрать загрузчик» не требует скетч.
- «Собрать BIN и пакет» создаёт приложение и свежий загрузчик; пакет
  автоматически импортируется и выбирается на вкладке «Прошивка».
- В списке действий можно выбрать отправку по OTA или первую установку по
  SWD после успешной сборки. Для SWD показывается существующее подтверждение
  с конкретными файлами и адресами.
- «Собрать все загрузчики» собирает все 20 реализованных профилей.
- Одновременно собираются до трёх плат. Таблица показывает очередь, текущие
  платы, результат, длительность и размер каждого BIN. Общая полоса отражает
  долю завершённых плат, а не процент компиляции текущей платы.
- Счётчики «Готово» и «Ошибок» относятся только к текущему запуску.
  Ранее сохранённые BIN не засчитываются как новый успешный результат.
- Ошибка одной платы не останавливает остальные. Двойной щелчок открывает
  журнал платы. Итог сохраняется в build_tools/last_build_report.json
  и отображается при следующем запуске менеджера.
- Готовые загрузчики уже включены: build_tools/output/ИМЯ_ПЛАТЫ/bootloader.bin.
  Перечень, размеры и SHA256: bootloaders_catalog.json.

Повторные версии пакета имеют разные идентификаторы и подписи; новая сборка
не выбирает старое приложение с тем же названием платы.
Подробные журналы компиляции находятся отдельно: build_tools/logs/.

## Поиск OTA

Укажите подсеть, например 192.168.100.0/24, и нажмите «Найти OTA».
Есть прогресс, количество найденных устройств и остановка.
Двойной щелчок переносит IP на вкладку прошивки.

В список попадают только:
- устройства с ответом на read-only запрос FLPINFO? (новая FLProg_Network);
- устройства, объявившие Arduino OTA через mDNS.
- предположительно старые приёмники FLProg, ответившие ERR! на неверный
  заголовок (пометка «FLProg OTA? / legacy»; точная модель не определяется).

Открытый TCP-порт сам по себе не считается подтверждением OTA.
Для старого приёмника без mDNS применяется проверка неверным заголовком.
Она не передаёт образ и не стирает Flash, но увеличивает счётчик ошибок OTA
и может выставить otaError=5. Это диагностический эффект проверки, а не ошибка
записи прошивки. Ответ ERR! — признак совместимости, не строгая идентификация.
Запрос FLPINFO? не стирает Flash и не начинает обновление. Пароль для него
не требуется. mDNS-объявление показывает наличие сервиса, но не гарантирует
успешную авторизацию или совместимость выбранного BIN.

## Поддержка

Реализованы профили F407 512/1024 КиБ и F103 256/512 КиБ, W5500.
20 загрузчиков собраны и проверены по размеру, векторам и SHA256.
Новые варианты требуют испытаний на физических платах; компиляция всех
загрузчиков не означает аппаратную проверку всех плат.
Ранее полный цикл был проверен только на FLE4D/F407 1 МиБ.

F103 32/64/128 КиБ, F103xG 1 МиБ, другие STM32 и RMII здесь не добавлены.
Блок не защищает от полного стирания внешним программатором.
