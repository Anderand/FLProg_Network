# FLProg STM32 OTA Manager — первый прототип

Отдельная Windows-программа хранит пакеты платы и выполняет следующие операции:

- **Обновить по OTA** — передать приложение в staging через W5500/TCP 3233;
- **Первичная установка по SWD** — записать загрузчик и приложение через
  STM32CubeProgrammer CLI.
- **Перезапуск по SWD** — выполнить только MCU reset через ST-Link, без записи
  или стирания Flash.

Arduino IDE для выбора профиля при этих операциях не используется. Этот
прототип не собирает исходный проект: он использует собранные бинарные файлы из
выбранного пакета или выбранный BIN приложения. Сборка FLProg-проекта пока остаётся отдельным шагом.

## Первый профиль

В комплекте только проверочный профиль **FLE4D-30MT / STM32F407VG / W5500**.
Flash-разметка пакета:

| Область | Адрес | Размер |
|---|---:|---:|
| Загрузчик | `0x08000000` | 64 KiB |
| Приложение | `0x08010000` | 448 KiB |
| OTA staging | `0x08080000` | 512 KiB |

Это экспериментальная схема, её нельзя применять к другим STM32 без отдельного
профиля и испытаний.

## Запуск

1. Распакуй архив в обычную папку и запусти `FLProg_STM32_OTA_Manager.exe`.
2. Выбери профиль. Программа проверяет SHA-256 загрузчика и приложения из пакета.
3. Для своего приложения нажми **Выбрать BIN…** в строке **BIN приложения**.
   Программа проверит размер и адрес запуска по выбранному профилю. Этот BIN
   используется и для OTA, и для приложения при первичной установке по SWD.
   Кнопка **Из профиля** возвращает приложение из пакета. Выбранный путь сохраняется.
   Для OTA укажи IP, при необходимости пароль, и нажми **Обновить по OTA**.
   После успешной передачи перезапусти контроллер.
4. Для первой установки укажи `STM32_Programmer_CLI.exe`, подключи ST-Link и
   нажми **Первичная установка по SWD**. Программа отдельно спросит подтверждение,
   затем запишет загрузчик по `0x08000000`, а приложение по `0x08010000`,
   проверит запись и автоматически сбросит и запустит контроллер.
5. Над журналом есть кнопки **Копировать лог** (копирует весь журнал в буфер
   обмена) и **Очистить лог**. Вывод SWD-команд сокращён до MCU, Flash, адреса,
   результата проверки и времени; баннер и символы прогресса не выводятся.
   Результат операции отображается отдельной строкой над журналом и добавляется
   в конец журнала.
6. **Перезапуск по SWD** требует подключённый ST-Link и тот же путь к CLI. Эта
   операция не записывает и не стирает Flash.

Первичная установка и восстановление требуют SWD/ST-Link. Не отключай питание
во время записи. Сохраняй доступ к программатору после перехода на OTA.

## Добавление профилей

Импортируй файл `.fwpkg`. Это ZIP-пакет с тремя файлами в корне:
`profile.json`, `bootloader.bin`, `application.bin`. JSON хранит target MCU,
Flash-разметку, OTA-порт, ограничения размеров и SHA-256 обоих образов.
Пакет с неизвестными файлами, путями или неверными хешами не устанавливается.

Для следующей модели потребуется отдельный проверенный профиль. В перспективе
менеджер можно расширить сборкой через Arduino CLI, передавая профилю платы её
FQBN и параметры сборки, не переключая активную плату в окне Arduino IDE.

## Границы прототипа

- TCP-проверка подтверждает доступность порта, но не идентифицирует MCU.
- Перед OTA пользователь выбирает профиль вручную. Не отправляй пакет, если
  физическая модель контроллера отличается от выбранного профиля.
- Для FLE4D бинарники берутся из текущих каталогов `_build_OTA_*` проекта.
  После изменения исходников пакет нужно пересобрать кнопкой сборки менеджера.
- Сетевой OTA-протокол использует общий секрет из прошивки; пароль можно
  оставить пустым, если так собрана установленная OTA-программа.
