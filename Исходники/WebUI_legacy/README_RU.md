# FLProg Web UI Designer — прототип 0.1

Это первый исполняемый макет будущего конструктора web-интерфейсов для FLProg.
Он намеренно не изменяет `FLProg_Network` и не требует Node.js, npm или установки
пакетов: интерфейс запускается локально в браузере, а данные сохраняются в JSON-
файле `.flpui`.

## Запуск

Дважды щёлкните `launch_designer.cmd` либо выполните:

```powershell
python .\server.py
```

Затем откройте <http://127.0.0.1:8765>. Остановить сервер можно сочетанием
`Ctrl+C` в его консоли.

## Что уже работает

* проект, профиль устройства и страницы;
* виджеты: индикатор, переключатель, ползунок, текст;
* привязки каналов чтения и записи (например, `relay.light`);
* просмотр фактического JSON-контракта;
* сохранение в `projects/*.flpui`.
* экспорт `exports/*_generated.h`: статического описателя для прошивки без
  JSON-парсера и без добавочной нагрузки в runtime.
* «Установить в библиотеку»: записывает проект в
  `FLProg_Network/src/flprogWebUiProject.h`; следующий скетч с блоком Web UI
  Core использует эти виджеты без стандартного web-интерфейса FLProg.
* импорт штатного списка переменных FLProg `.fvl`; выбранная переменная
  привязывается к виджету без ручного ввода идентификатора.
* экспорт переменных `.fvl` из созданного Web UI проекта для последующего
  импорта в FLProg.
* экспорт одного типизированного пользовательского блока `.ubi` для проекта:
  входы публикуют значения в web-интерфейс, выходы `NEW_*`/`VALUE_*` передают
  действия браузера в FBD-схему.

### Привязка переменных

Основной путь: задайте привязки виджетов, нажмите «Экспорт переменных .fvl» и
импортируйте файл из `exports` в FLProg. В конструкторе также можно выбрать
существующий `.fvl` в секции «Переменные FLProg» для обратной синхронизации.
Для `indicator` и `text` она становится каналом чтения; для `switch` и `slider`
— каналами чтения и записи. После этого нажмите «Установить в библиотеку».

Экспорт использует штатные классы типов FLProg: `BooleanDataType` для
переключателя, `IntegerDataType` для ползунка, `FloatDataType` для индикатора
и `StringDataType` для текста. У переменной создаётся детерминированный UUID:
повторный экспорт того же имени не порождает дубликат идентификатора.

### Проектный блок `.ubi`

Нажмите «Экспорт блока `.ubi`» и импортируйте полученный блок в FLProg.
Например, для `sensors.temperature` и `relay.light` он создаёт входы
`SENSORS_TEMPERATURE`, `RELAY_LIGHT` и выходы `NEW_RELAY_LIGHT`,
`VALUE_RELAY_LIGHT`. Имена HTTP-каналов остаются внутри блока — в FBD их
вводить не нужно. Используйте оба входа для передачи текущих значений; при
нажатии пользователем переключателя обработайте `NEW_RELAY_LIGHT` и
`VALUE_RELAY_LIGHT` в вашей схеме.

Файл `.ubi` формируется в UTF-16LE с BOM и XML-декларацией `utf-16`: именно
такую кодировку используют штатные пользовательские блоки FLProg, поэтому
русские подписи при импорте не повреждаются.

## Граница прототипа

Экспортированный `.h` уже содержит список страниц, виджетов и имён каналов.
Следующим слоем будет `Web UI Core` в `FLProg_Network`: он примет этот
сгенерированный контракт, сопоставит имена каналов с входами/выходами блока и
отдаст интерфейс через текущий HTTP runtime.

В установленной версии FLProg не обнаружен публичный API для добавления вкладки
или команды в редактор. Поэтому сейчас это отдельное локальное приложение.
Открытие кнопкой из FLProg станет возможным через официальный API расширений либо
изменение самого FLProg; формат `.flpui` и запускатор к этому готовы.
