# FLProg Web UI — пользовательские блоки 0.1

Импортируйте три файла `.ubi` в редактор пользовательских блоков FLProg.

1. **FLProg Web UI Core** — один экземпляр. Создаёт общий реестр и собственный
   HTTP-сервер на порту 80. Стандартный Web Interface FLProg не используется.
2. **FLProg Web UI Value** — экземпляров сколько угодно. Входы: `EN`,
   `CHANNEL`, `VALUE`; публикует текстовое значение по каналу.
3. **FLProg Web UI Command** — экземпляров сколько угодно. Входы: `EN`,
   `CHANNEL`; выходы: `NEW`, `VALUE`. Принимает команду браузера ровно один раз.

Для начала добавьте Wi-Fi-интерфейс FLProg, затем Web UI Core, Value для `sensors.temperature` и Command для
`relay.light`. Имена `CHANNEL` должны буквально совпадать с привязками в
экспортированном заголовке `.h` редактора.

Для каждого канала, которым браузер управляет через Command, также добавьте
Value с тем же `CHANNEL`: он публикует фактическое состояние исполнительного
механизма и одновременно регистрирует разрешённый канал до первого HTTP-запроса.

Ограничение первого прототипа: блоки используют строковые значения. Это
осознанно — один и тот же `switch`, `slider` и индикатор не требуют отдельных
несовместимых типов. Следующий выпуск может добавить типизированные оболочки.
