# Модель и версия в диагностике устройства

25.10.2026. Проверено на FLE4D-30MT / STM32F407VG / W5500 с DHCP,
STM32 core 3.0.0, IP 192.168.100.12. Установлена по OTA **1.0.17-IDENTITY**.

## Соответствие нашей концепции

Сохранены сетка из 12 колонок, именованные группы и типизированные каналы.
Модель и версия уже заданы в OTA-блоке: веб использует этот источник,
без повторного ввода настроек и дополнительных постоянных буферов строк.
SPI и Ethernet по-прежнему задаются проектом FLProg.

«+ Диагностика» теперь добавляет семь каналов API: пять сетевых и два
текстовых поля device_model / firmware_version в группе «Устройство».
Повторное нажатие сохраняет существующую страницу. Старые страницы не
мигрируют автоматически. Обновлён пример projects/network_diagnostics_example.flpui.

## Источник и защита

FLProgNetworkInterface получает const char* из первого подключённого
managed service, предоставляющего identity. OTA STM32/W5500 возвращает
свои существующие строки. Неподдерживаемый сервис возвращает nullptr;
отсутствующий источник или пустая строка показываются как «Не задано».
Пара выбирается из одного сервиса; указатели не сохраняются после вызова.
При удалении сервиса источник исчезает из существующего registry.

Оба канала только для чтения. HTTP-запись отвергается даже при ошибочном
duplex-контракте; симулятор использует ту же защиту. В симуляторе можно
задавать локальные фактические значения через панель моделирования.
Это не отправка команды на устройство.

Нужны обе обновлённые библиотеки из этого набора. В старой Network без
identity API значения остаются неизвестными. На ESP и иных сервисах пока
нет проверенного provider: модель/версию не выдумываем.

## Проверка

- 49 автоматических тестов: каталог, readonly, placeholder, диагностика,
  сохранение старого проекта и предыдущие функции.
- Статическая проверка пакета и ресурсов; 25 gzip-ресурсов сверены побайтно
  с исходниками после OTA, заголовки длины и кеширования проверены.
- Веб state и TCP FLPINFO? совпали: FLE4D-30MT / STM32F407VG,
  версия 1.0.17-IDENTITY. Попытки записи обоих каналов получили HTTP 422;
  последующее чтение подтвердило неизменность.
- Встроенный браузер показал модель и версию в группе «Устройство»;
  ошибок JS в проверенной вкладке нет. GUI создал семь каналов API.
- Сеть, шлюз и маска сохранились; 144 C++-проверки шаблонов проходят.

Проверка HTTP встретила отказ соединения при параллельном опросе браузером:
ограничение одного HTTP-клиента сохраняется. Повтор GET завершился успешно;
команды автоматически не повторялись. Длительный замер heap в этом этапе
не проводился; отключение identity provider аппаратно не проверялось.
