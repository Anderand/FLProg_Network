# Контракт входов, выходов и настроек виджетов Web UI

Статус: проектная спецификация 1.0, 12.10.2026.

## Термины FBD

Один номер `CHANNEL` связывает виджет с универсальными блоками FLProg.

| Направление | Блок в FBD | Смысл |
|---|---|---|
| `PUBLISH` | `Publish Bool / Int / Float / Text` | Контроллер передаёт значение в Web UI. Это **вход виджета**. |
| `COMMAND` | `Command Bool / Int / Float / Text` | Браузер передаёт действие контроллеру. `NEW` — импульс нового действия, `VALUE` — значение. Это **выход виджета**. |
| `DUPLEX` | оба блока на одном `CHANNEL` | Виджет получает текущее значение и передаёт изменённое. |

`EN` включает соответствующий блок. `CHANNEL` — номер из левой панели
редактора: API `0…100`, пользовательские `101…255`.

## Единый минимум

Сейчас каждый виджет имеет один основной `CHANNEL`. Для показаний это вход,
для управления — выход, для duplex-виджетов — оба направления. Цвет, подпись,
расположение, диапазон и options — настройки descriptor, они не требуют
дополнительных FBD-проводов.

## Многоканальный контракт 1.1 — обязателен для развития

Текущий runtime хранит `channel` как одну строку. Для виджетов, отмеченных
**несколько входов**, нужен единый массив `bindings`, не набор случайных
полей `channel2`, `channel3`:

```json
"bindings": [
  {"role":"value", "channel":"demo_progress"},
  {"role":"setpoint", "channel":"target"},
  {"role":"alarm", "channel":"alarm_active"}
]
```

Правила:

1. `role` определяет смысл, а не порядковый номер.
2. Один и тот же канал разрешён в нескольких ролях только сознательно.
3. `value` — основной обязательный binding для виджетов отображения.
4. Для command-виджетов основной binding имеет роль `command`.
5. Пакетный генератор и runtime должны проверять тип и направление каждого
   binding до генерации descriptor.

Первые кандидаты на реализацию `bindings`: `Тренд` (до 4 серий), `Столбцы`
(до 8 значений), `Секторный прибор` (`value`, `setpoint`, `alarm`) и
`Кнопка` (`command`, `busy`, `result`). Пока 1.1 не реализован в runtime,
дополнительные строки выше являются контрактом развития, а не активными
портами редактора.

## Рекомендации по FBD

* Один счётчик/датчик → `Publish` и виджет отображения.
* Уставка/ползунок → `Publish` + `Command` на том же пользовательском канале.
* Действие без значения (перезапуск, применить настройки) → `Command Bool`;
  использовать `NEW`, а не удерживать `VALUE`.
* Секреты → `Command Text`; не создавать для них `Publish`.
* Системные Wi‑Fi/AP параметры использовать только из API диапазона `0…100`.
* Пользовательские сигналы создавать от `101`.
