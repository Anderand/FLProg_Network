# Дорожная карта FLProg Web UI

Актуализировано 25.10.2026 по локальному комплекту FLProg Network r11:
порционная выдача и уведомления проверены на FLE4D.
GitHub обновляется только по отдельной команде пользователя.

## Текущее состояние

| Этап | Результат |
|---|---|
| Связь и команды | Статус свежести, подтверждение команды, блокировка повторов, русские busy/result |
| Поля | Типы, ограничения, черновик, явное применение, состояния поля и последнее значение ПЛК |
| Группы | Именованные группы с независимой сеткой |
| Перезапуск и восстановление | Полное чтение состояния, обновление чистых полей, сохранение черновиков без автоматической отправки |
| Проверка проекта | Типы и направления каналов, отсутствующие связи, пересечения, переход к проблемному виджету, защита сборки |
| Предпросмотр | Настоящий веб-интерфейс с локальной моделью каналов; offline/reconnect, restart, ручной и автоматический busy/result |
| Демо | Одна кнопка открывает уставку и busy/result и запускает предпросмотр |
| Порционная выдача Flash | Проверены 128 КиБ, gzip, медленный клиент и обрывы; RAM/контекст без роста, код +280 байт Flash относительно gzip r9 |
| Комплект | Переносимый EXE, инструкции Markdown, исходники, три библиотеки, блоки и OTA-менеджер в общем архиве |

На FLE4D-30MT / STM32F407VG / W5500 проверена прошивка 1.0.7:
уставка, команды, busy/result, восстановление связи и синхронизация после
перезапуска. Изменения редактора r7/r8 не требуют новой прошивки.
В r8 проходят 24 автоматических теста; кнопка демо проверена в EXE.
Предпросмотр не исполняет FBD и не заменяет аппаратные испытания.

## Все идеи из разбора K-WEB — состояние на r8

Источник: [разбор четырёх предоставленных файлов от 24.10.2026](specification/KWEB_REVIEW_RU.md),
разделы 2–5. Ниже учтены и основные предложения, и уточнения к ним.
Статус **«Запланировано»** означает оставшуюся работу в карте, а не
утверждённый срок. **«Отложено»** — отдельная проработка после основных
этапов. Частично готовые идеи разделены на выполненную и оставшуюся части.

| Идея | Статус | Что есть / что осталось |
|---|---|---|
| Небольшие статические ответы из Flash | Сделано | PROGMEM, разделённые ресурсы, контроль полного HTTP-ответа; это ещё не потоковая выдача большого файла |
| Порционная выдача большого неизменяемого ресурса | Сделано, проверено на FLE4D | 128 КиБ, gzip, медленное чтение, обрывы и зависший получатель; курсор переиспользует строку запроса, контекст 6120 байт без роста. [Отчёт](FLASH_STREAM_RU.md) |
| Предварительный gzip HTML/CSS/JS | Сделано, проверено на FLE4D | Опциональная сборка: Flash −6184 байта, статическая RAM без изменений; клиенту без gzip — 406, для identity есть обычная сборка. [Отчёт](GZIP_RU.md) |
| Обновления revision/since и опрос выбранной страницы | Сделано | Контракт сохранён; после сбоя и перезапуска выполняется полное чтение |
| Настраиваемые интервалы и пауза фонового опроса | Запланировано | Сейчас интервал опроса фиксированный; дополнительно определить поведение скрытой вкладки и устаревших данных |
| Постоянный online/offline/stale и возраст данных | Сделано | Индикатор свежести, запрет управления без свежих данных |
| Ожидание и подтверждение команды | Сделано | Отправка, подтверждение приёма, ошибки и неопределённый результат; выполнение отдельно через busy/result |
| Toast-уведомления | Сделано, проверено на FLE4D | Отправлено, принято и подтверждено свежими данными; отмена и ошибки, защита от старого result, без автоматического повтора. [Отчёт](NOTIFICATIONS_RU.md) |
| Числовые/текстовые поля: диапазон, шаг, длина, единицы | Сделано | Настройки descriptor, проверка ввода и серверные проверки; длина текста учитывается в UTF-8 |
| Enter, Escape, ошибка у поля и черновик | Сделано | Явное применение, отмена к последнему значению ПЛК, состояния поля, сохранение черновика при опросе/сбое |
| Regex и настраиваемый текст ошибки | Запланировано | Отдельные параметры descriptor и согласованная проверка на обеих сторонах; текущие штатные ограничения не считаются regex |
| Отправка по blur/после паузы | Отложено | Сейчас явное применение; автоматические режимы должны быть опциональными и не повторять команду после восстановления связи |
| Отдельный числовой spinner/цифровая клавиатура | Отложено | Сейчас стандартные HTML-поля; специальный компонент не реализован |
| blocked/enabled как отдельный контракт виджета | Запланировано | Блокировка по связи и busy есть; независимого входа разрешения/блокировки пока нет |
| Группы с заголовком и адаптивной сеткой | Сделано | Именованные группы, независимая сетка; мобильная компоновка |
| Настраиваемые рамки, общие отступы, контейнеры строка/столбец | Запланировано | Текущую группу не считать полной реализацией всех вариантов контейнера |
| Дополнительное оформление индикаторов и анимация прогресса | Отложено | Цвета и стандартные индикаторы есть; отдельные новые эффекты и анимация requestAnimationFrame не внедрялись |
| Ленивая загрузка descriptor виджетов страницы | Сделано | Виджеты страницы загружаются по требованию, остальные страницы не требуют загрузки всех виджетов сразу |
| Восстановление последней открытой страницы | Запланировано | Не путать с сохранённым режимом фокуса редактора: выбранная страница runtime не восстанавливается из localStorage |
| Повтор загрузки меню/виджетов после ошибки | Запланировано | Полный повтор чтения состояния уже есть; отдельное восстановление незагруженного descriptor/меню ещё нужно |
| Явное применение сетевых настроек | Сделано | Есть публичные Wi-Fi/AP-каналы и команды применения; это не общий механизм постоянного хранения |
| Разделение оперативных и сохраняемых параметров | Запланировано | Общий контракт хранения, признак изменения, подтверждение сохранения |
| Накопление изменений и отложенная запись | Запланировано | Без записи Flash при каждом изменении; определить задержку, обработку ошибки и принудительное сохранение |
| Backend хранения для разных платформ | Запланировано | Для STM32 согласовать область вне загрузчика, приложения и staging OTA; ESP-хранилище не переносить напрямую |
| Единая диагностическая страница | Запланировано | Отдельные сеть/OTA/диагностические элементы уже есть; собрать версию, модель, uptime, причину старта, сетевые ошибки и память где доступно в один контракт |
| SSE/event-stream | Отложено | Отдельный экспериментальный backend: бюджет сокетов/клиентов W5500, ограниченная очередь, медленный клиент и восстановление полного снимка |
| Файловый менеджер | Отложено | Только опциональная административная функция после определения хранилища и проверки доступа до открытия/записи/удаления |
| Веб-OTA | Отложено | Не путать с готовым внешним STM32 OTA-менеджером; нужны проверка доступа до первой записи, проверка образа и подтверждение запуска версии |
| Авторизация и серверные сессии административных функций | Отложено | Серверное ограничение попыток, срок сессии, явные операции записи и ограничение тела; не копировать схему пароля в URL/localStorage из примера |
| Необязательная GyverDB/подсистема хранения | Отложено | Оценить только после контракта хранения; не делать обязательной зависимостью STM32/W5500 |

### Что из K-WEB не переносим напрямую

- Динамический кэш всей HTML-страницы с резервированием около 40 КБ:
  сохраняем descriptor и небольшие ответы вместо такого расхода RAM.
- ID по адресу C++-переменной: сохраняем устойчивые CHANNEL и направления
  Publish/Command/Duplex.
- Обязательные AsyncTCP/ESPAsyncWebServer и ESP LittleFS для STM32:
  сохраняем наш транспорт FLProg_Network. TFT-шрифты из примера не относятся
  к этому Web UI.
- Запись настроек на каждом событии и проверку доступа только после
  загрузки файла: заменяем проектированием отложенного хранения и отказом
  до первой операции записи.
- Буквальное копирование чужих исходников: сначала выяснить условия
  лицензии K-WEB и зависимостей. Включение исходного разбора в документацию
  не означает включение стороннего кода в библиотеку или релиз.

### Очередь оставшихся работ по разбору

1. **Gzip и порционная выдача проверены.** Новое API обслуживает большой
   ресурс из Flash через прежнюю очередь 2048 байт. Существующие bounded-ответы
   сохраняют прежний лимит полного ответа; большие ресурсы требуют нового API.
2. **Интерфейс и навигация:** toast проверен; остаются опрос фоновых вкладок,
   восстановление страницы, повтор descriptor, оставшиеся настройки полей
   и контейнеров, единая диагностика. Внутренний порядок пока не утверждён.
3. **После — сохраняемые параметры:** общий контракт, отложенная запись
   и платформенные backend.
4. **Отдельно, позднее — SSE и администрирование:** авторизация,
   файловые операции и веб-OTA с соответствующими проверками.

Проверка проекта и офлайн-предпросмотр r7/r8 — последующие улучшения нашего
редактора; не выдаём их за пункты исходного разбора K-WEB. Дополнительные
идеи ниже также отделены от восстановленного списка.

## Этап gzip — выполнен на FLE4D

25.10.2026 выполнены две сравнимые сборки и аппаратная проверка gzip по OTA.
Flash: 137040→130856 байт; статическая RAM: 16112→16112 байт.
[Измерения, проверки и ограничения](GZIP_RU.md). Режим пока опциональный,
общий r9 уже включает gzip. Позднее реализована и проверена порционная выдача
([отчёт](FLASH_STREAM_RU.md)); она пока не включена в новый общий архив.
Ниже сохранён контрольный список этапа; новый выпуск — отдельной командой.

1. Измерить исходный и сжатый размер HTML/CSS/JS, оценить расход Flash
   и объём передачи на текущем наборе ресурсов.
2. Проверить и при необходимости добавить отправку двоичных данных из
   Flash с точной длиной и заголовком `Content-Encoding: gzip`.
   Текущий вызов `sendProgmem` для текстовых строк сам по себе gzip не даёт.
3. Сжимать статические ресурсы на компьютере при подготовке библиотеки,
   без компрессора и дополнительного рабочего буфера на STM32.
4. Проверить согласование `Accept-Encoding`, заголовки, корректную
   обработку клиента без gzip и распаковку каждого ресурса до исходных байтов.
5. Сохранить ограничение bounded-ответа 2048 байт вместе с заголовками и
   текущий бюджет маршрутов. Новый stream API допускает большее полное тело
   через тот же буфер. Не увеличивать RAM-буфер ради сжатия.
6. Проверить загрузку веба, команды, поля, группы и синхронизацию на FLE4D.
   Сравнить размер BIN и расход RAM с прежней сборкой, а не только размер JS.
7. После проверки подготовить новый EXE/общий комплект по команде
   пользователя. GitHub — только по отдельной команде.

Изменение ресурсов в прошивке потребует пересборки и обновления ПЛК.
Один новый EXE редактора не включает gzip на уже прошитом контроллере.

## Идеи после gzip — порядок не утверждён

1. **Повторяемые сценарии предпросмотра**: сохранить набор значений каналов,
   восстановить его, повторить последовательность связи и команд.
2. **Работа с макетом**: выделение нескольких элементов, выравнивание,
   распределение и совместное перемещение.
3. **Отчёт контракта проекта**: таблица каналов, направлений и связей
   виджетов для подключения универсальных блоков во FLProg.

Эти пункты пока не реализованы; их порядок не утверждён. Они отделены от
транспортных задач исходного разбора K-WEB.

## Правила архитектуры

- `FLProg_Network` содержит только разработческий сетевой API.
- `FLProg_WebUI` содержит общий runtime и адаптеры.
- `.flpui` хранит только дизайн и контракт конкретного проекта.
- project package содержит descriptor и конфигуратор конкретного проекта.
- Изменение layout/темы не меняет FBD-схему; изменение канала является изменением контракта.

## Базовый этап 1.0 — история

1. **API-интеграция FLProg_Network** — каталог публичных API и генерация
   Wi-Fi/W5500 HTTP выполнены. W5500 использует проверенные в generated sketch
   макросы `FLPROG_WIZNET_INTERFACE1` и `FLPROG_WIZNET_INTERFACE2`.
2. **Модель дизайна** — выполнена: `theme`, `layout`, `x/y/w/h`, цвета,
   иконки, min/max/step.
3. **Редактор** — выполнен: 12-колоночная сетка, свойства, color picker,
   drag, точное изменение размеров, text input, мобильный предпросмотр,
   выделение пересечений, дублирование и отмена изменений.
4. **Runtime Web UI** — выполнен: descriptor-метаданные, CSS-grid, цвета
   виджетов, indicator/switch/slider/text-input и безопасная очередь команд.
   Страница разделена на компактные HTTP-ресурсы.
5. **FLProg blocks** — выполнен единый `.ubl` для Publish/Command Bool,
   Int32, Float и Text; XML проверен статически.
6. **Сборка и установка** — выполнены generator package, автоматическая
   установка в sketchbook и корректные Arduino metadata.
7. **Регрессия** — статическая и очная ESP8266 Wi-Fi проверка выполнены.
   Позднее выполнена аппаратная проверка STM32F407VG/W5500 на FLE4D-30MT
   (см. текущее состояние выше). Аппаратные испытания остальных плат не
   считаются выполненными; рабочие ESP .116/.117 для испытаний не используются.
8. **Передача** — выполнены RU/EN README, demo-проект и чистый архив передачи.

## Критерий завершения

Пользователь создаёт проект в редакторе, выбирает публичный транспорт
FLProg_Network, раскладывает виджеты на сетке, экспортирует package/UBL,
связывает универсальные блоки в FLProg и получает адаптивный интерфейс после
прошивки без ручного C++-кода.
