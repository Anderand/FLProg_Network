# Диагностика сети — улучшение существующей страницы

25.10.2026. FLE4D-30MT / STM32F407VG / W5500, STM32 core3.0.0.
На контроллер по OTA установлена **1.0.16-NETDIAG**, IP **192.168.100.12**.
Git, EXE, IDE и опубликованный r13 не изменялись.

## Сначала сравнение с нашей концепцией

У нас уже есть типизированные каналы, группы, кнопка диагностики,
автоматическая публикация сети и отображение uptime в протоколе state.
Поэтому отдельную диагностическую подсистему не создавали.

Найденные проблемы старой кнопки: фиксированное имя KC868-A16/RMII,
порты тестового echo, пользовательские счётчики без автоматического источника,
ссылка /api/status, которой общий runtime не предоставляет, и полная замена
ранее созданной страницы при повторном нажатии.

## Что теперь делает кнопка

«+ Диагностика» создаёт страницу «Диагностика сети» на нашей сетке и группе:
IP-адрес, подключение сети, MAC-адрес, активные шлюз и маска подсети.
Это пять readonly-каналов API №0–100, без дополнительных Publish-блоков FBD.
Настройки SPI/Ethernet остаются в проекте FLProg.

Повторное нажатие открывает существующую страницу без замены её элементов,
подписей, оформления и каналов. Старые тестовые страницы автоматически
не переделываются; их можно отредактировать обычными средствами редактора.
При совпадении пользовательского ID канала с иным контрактом или нехватке
номеров API операция отклоняется целиком, исходный проект не меняется.
Совпадения ID виджетов на других страницах обрабатываются уникальным суффиксом.
Корректные уже имеющиеся каналы API переиспользуются.

Пример: projects/network_diagnostics_example.flpui.

## Активные адреса и настройки — разные данные

При проверке на FLE4D выяснилось: gateway() и subnet() возвращают настройки,
а не активную DHCP-аренду. Старое gateway() давало0.0.0.0.

Добавлены readonly API:

- activeGateway(): шлюз готового маршрута по умолчанию.
- activeSubnet(): маска готового маршрута по умолчанию.
- Без готового маршрута возвращается0.0.0.0.

Для W5500 DHCP читаются кешированные поля аренды; при статическом режиме —
регистры оборудования. Для Wi-Fi/RMII предусмотрены соответствующие getter
активного интерфейса. gateway()/subnet() и их setter не изменялись.
Размер объекта интерфейса и HTTP-буферы не увеличены.

FLProg_WebUI использует новый API для network_gateway/network_subnet только
при наличии этих каналов. Для активных данных нужны обе новые библиотеки.
При сборке с прежней Network сохранён совместимый fallback на прежние getter.
Признак API: FLPROG_NETWORK_HAS_ACTIVE_IP_INFO.

- 47 тестов и verify_release.py прошли. Планирование страницы атомарно;
  проверены повтор, конфликты, занятые индексы, совпадения ID и сборка package.
- В GUI: изменённая подпись «IP моего ПЛК» осталась после повторного нажатия;
  виджетов6, каналов5, дублей нет, проверка проекта без ошибок.
- OTA с автоматическим запуском. 25 gzip-ресурсов совпали с исходниками,
  прежние14 маршрутов; C++-проверок шаблона144.
- На реальном FLE4D: IP192.168.100.12, ready=true, MAC78:AC:C0:40:A3:3C,
  шлюз192.168.100.1, маска255.255.255.0. MAC совпал с ARP на компьютере.
- Прямая запись в network_ip отклонена HTTP422, IP не изменился.
- В вебе данные отображаются на существующей странице диагностики.
  Исходные тестовые разделы сохранены; ошибок JS в проверенной вкладке нет.
- Аппаратно проверен W5500 с DHCP. Wi-Fi/RMII и статический режим в этой
  серии аппаратно не испытывались. Методы Wi-Fi сверены с локальными headers.

## Границы этапа

Готов сетевой блок диагностики, а не весь будущий универсальный контракт.
Uptime уже есть в state и тестовом канале — второй счётчик создавать не нужно.
Модель/версия уже известны OTA; для веба ещё надо согласовать переиспользование
этих данных. Причина старта и память зависят от платформы; недоступные значения
нельзя выдавать за нулевые показатели. Эти пункты остаются в дорожной карте.
Пауза hidden/show также остаётся с прежним ограничением IAB.
