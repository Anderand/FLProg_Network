# Разрешение управления enabled

25.10.2026. Проверено на FLE4D-30MT / STM32F407VG / W5500, STM32 core3.0.0.
На ПЛК **1.0.13-ENABLED**, адрес **192.168.100.12**. Git, EXE и общий r13
не изменялись. Новый runtime требует пересборки и обновления приложения ПЛК.

## Настройка в редакторе и FLProg

1. Добавьте bool-канал направления Publish (из FBD) или Duplex.
2. В свойствах поля/команды откройте «Данные». Дополнительная связь:
   «Разрешение (bool из FBD)», этот канал, направление «Из FBD».
3. Передавайте разрешение из логики FLProg через существующий блок Publish Bool
   с номером выбранного канала. Дополнительная библиотека/особый блок не нужны.
4. true разрешает управление, false блокирует. Пока значения нет, браузер
   также блокирует управление. На ПЛК bool по умолчанию false. Отсутствующий,
   неверного типа или command-only канал разрешения тоже даёт запрет.

JSON: `{"role":"enabled","channel":"permit","direction":"publish"}`.
Роль доступна только командным виджетам; проверка проекта отвергает неверный
тип, отсутствующий канал, повтор роли и неподходящее направление. Для
инверсного сигнала блокировки сформируйте разрешение в FBD; отдельной роли
blocked нет. Без enabled поведение существующих проектов сохраняется.

Виджет показывает «Разрешение ПЛК: да/нет/нет данных». Блокировка по связи,
синхронизации и busy действует дополнительно. Черновик поля сохраняется;
возврат разрешения его не отправляет — нужно явное «Применить».

ПЛК проверяет разрешение перед постановкой команды в очередь. Подстановка
другого widget либо отсутствие widget в URL не обходят запрет. Если несколько
виджетов управляют одним командным каналом, запрет любого из них блокирует
запись в этот канал; согласуйте их разрешения в проекте. Снятие разрешения
не отменяет уже принятую FBD-команду. Это разрешение управления, не авторизация.

## Пример

`projects/enabled_controls.flpui` открывается через «Открыть». Доступен и
офлайн-предпросмотр с локальным переключателем разрешения. В тестовом BIN
переключатель «Разрешить управление (RAM-тест)» меняет bool в памяти,
не физические выходы. Для обычного проекта сигнал задаёт ваша FBD-логика.

## Проверено

- 36 тестов и verify_release.py. Проверены запрет false/нет данных/неbool,
  независимость busy, потеря разрешения во время подтверждения и в очереди
  HTTP до отправки; совместимость без новой связи, генерация descriptor,
  проверка проекта и gate в офлайн-симуляторе.
- В GUI редактора: пример без ошибок, роль enabled в списке, связь сохранена,
  предпросмотр блокирует/разблокирует уставку и кнопку.
- OTA-загрузка с автоматическим запуском 1.0.13 на FLE4D. 23 gzip-ресурса
  прочитаны с ПЛК и совпали с исходниками; прежние 14 маршрутов/2048 байт.
- На ПЛК: без разрешения четыре прямых POST (с widget, без него, с другим
  widget; поле и кнопка) получили HTTP409. Уставка, actual и счётчик не изменились.
- В браузере: черновик33 сохранён при снятии разрешения (ПЛК25); возврат
  разрешения не отправил его. Явное применение установило33 с подтверждением.
- Разрешение снято отдельным RAM-запросом при открытом диалоге команды;
  после «Отправить» показано «Нет разрешения ПЛК», счётчик остался0.
- С разрешением выполнен один RAM-цикл: busy=true → false, result=true,
  счётчик1, подтверждение данными. Физические выходы не менялись.
- Найден и исправлен поиск в разреженном массиве лениво загруженных виджетов.
  Добавлен регрессионный тест. После повторной OTA — восстановление диагностики
  при reload и переход к управлению прошли. В новой вкладке ошибок JS нет.
  Журнал прежнего документа с первоначальной ошибкой сохранён отдельно.
