# FLProg Web UI 1.0

Это отдельный штатный конструктор Web UI для FLProg. Он не заменяет и не
засоряет `FLProg_Network`: библиотека сети предоставляет только публичный
транспорт, а каждый проект хранит свой дизайн в файле `.flpui` и получает
собственный пакет `FLProg_WebUI_Project_<id>`.

## Базовые элементы и сетевая диагностика

Конструктор разделяет содержание и данные:

* **Простой текст** — статическая подпись или пояснение. Канал не требуется,
  поэтому элемент не занимает FBD-канал и не создаёт RAM-слот на контроллере.
* **Вывод значения** (`Текст`) показывает текстовый канал из FBD.
* Индикатор, числовые приборы и прогресс отображают publish-каналы.
* Поля ввода, переключатели, кнопки и ползунки записывают command/duplex
  канал, принимаемый соответствующим пользовательским блоком FLProg.

Кнопка **«+ Диагностика»** создаёт страницу в стиле аппаратного RMII gate:
IP, состояние сети, MAC, link RMII и счётчики TCP/UDP. IP/сеть/MAC берутся
из публичного API `FLProg_Network`; остальные счётчики создаются как
пользовательские publish-каналы и заполняются из FBD. Поэтому шаблон не
привязан к одной тестовой прошивке.

## Состав

* `runtime/FLProg_WebUI` — общий runtime, устанавливается один раз.
* `editor/` — локальный редактор: `python server.py`, затем
  `http://127.0.0.1:8766`.
* `projects/` — дизайны конкретных проектов. Их можно хранить вместе с FBD.
* `project_packages/` — генерируемые пакеты, отдельно от `FLProg_Network`.
* `user_blocks/FLProg_WebUI_Universal_Blocks.ubl` — единый импортируемый
  комплект Publish/Command для Bool, Int32, Float и Text.

Полная матрица портов, типов, настроек и будущих многоканальных bindings:
[`specification/WIDGET_IO_CONTRACT_RU.md`](specification/WIDGET_IO_CONTRACT_RU.md).

## Рабочий процесс

1. В редакторе выбрать Wi-Fi HTTP, создать каналы и виджеты.
2. Сохранить `.flpui`; макет, цвета и положение хранятся в нём.
3. Нажать «Собрать и установить». Пакет будет автоматически скопирован в
   sketchbook `libraries` как отдельная библиотека проекта.
4. Импортировать из пакета `FLProg_WebUI_Configure_<id>.ubi` и добавить
   конфигуратор в FBD вместе с обычным Wi-Fi интерфейсом FLProg. При первом
   переходе на runtime 1.2 заменить прежний конфигуратор этим блоком: он
   включает порционный HTTP-транспорт.
5. Импортировать единый `.ubl`, соединить каналы с универсальными блоками,
   скомпилировать и прошить.

Оформление, сетка, X/Y/W/H и подписи не требуют новых FBD-блоков. Изменение
списка каналов — это изменение контракта и требует обновить связи блоков.

Карточку можно перемещать за область `⠿`, менять размер кнопками `W/H` или
точными полями `X/Y/W/H`. Редактор выделяет пересекающиеся виджеты янтарной
рамкой и сообщает их номера, поддерживает «Дублировать» и «Отменить»
(последние 40 изменений). Все эти операции меняют только `.flpui`.

Номер `№N` / `INDEX = N` рядом с каналом — это именно значение параметра
`CHANNEL` в универсальных блоках FLProg. Он начинается с нуля и показывается
также в выпадающем списке виджета, поэтому его не требуется вычислять вручную.

## Публичная интеграция

Runtime использует только `FLProgNetworkInterface` и
`FLProgNetworkHttpServer`. Каталог `integration/flprog_network_api_catalog.json`
является машиночитаемым соглашением редактора. W5500 поддержан адаптером и
генератором через опубликованные FLProg макросы `FLPROG_WIZNET_INTERFACE1` и
`FLPROG_WIZNET_INTERFACE2`. В редакторе они показаны как «W5500 / Ethernet
#1» и «#2». Пример — `projects/demo_w5500.flpui`.

## Порционный HTTP

`FLProg_Network` намеренно ограничивает размер одного HTTP-ответа. Runtime
1.2 не увеличивает этот лимит и не использует динамическую память. Браузер
получает метаданные один раз, описание каждого виджета отдельным запросом и
при опросе читает только каналы открытой страницы. Поэтому общий размер
layout/config больше не ограничивает число виджетов и страниц.

Рабочий буфер Web UI — 1024 байта; отдельное свойство виджета ограничено
180 байтами. `GET /flprog-webui/meta` сообщает runtime `1.2.0-20261011`.
