# Память, системные каналы и восстановление редактора

25.10.2026. По OTA на FLE4D-30MT / STM32F407VG / W5500 установлена
**1.0.19-MEMORY**, IP **192.168.100.12**, STM32 core 3.0.0.
Git, EXE, общий архив r13, IDE и загрузчик не изменялись.

Сначала сохранили нашу сетку из 12 колонок и именованные группы.
Диагностика расширена в существующем макете, настройки SPI/Ethernet не дублируются.
По замечанию пользователя убраны подписи «куча/арена», добавлены общие объёмы,
занятость и пояснения источников. Все служебные поля — системные №0–100.

Оценка свободной ОЗУ учитывает linker _Min_Stack_Size и текущий MSP.
Это сумма доступного места, не гарантия размера крупнейшего блока и не
измерение пиков стека. Для RTOS с PSP оценка не выдаётся. Backup SRAM/OTP
не включены в обычную память программы. Можно отключить платформенные
измерения FLPROG_WEBUI_DISABLE_PLATFORM_DIAGNOSTICS при своём allocator/RTOS.
На неизвестной платформе/при недоступных linker symbols показывается
«Недоступно», а не нулевой объём. Аппаратно проверен только F407VG.

## Флаги сброса

Предусмотрено readonly-чтение доступных CSR-флагов F1/F4 без их очистки.
Накопленные флаги не выдаются за единственную причину последнего запуска.
На этом FLE4D маска0: «Флаги не сохранены». Найдена точная причина ограничения:
установленный загрузчик вызывает HAL_RCC_DeInit(), а его реализация
STM32 core 3.0.0 в stm32f4xx_hal_rcc_ex.c устанавливает RCC_CSR_RMVF.
Приложение не восстанавливает уже стёртые данные. Для сохранения причины
через загрузчик нужен отдельный контракт передачи; загрузчик в этом этапе
не изменён, чужие backup-регистры/резерв RAM не заняты.

## Каналы и редактор

[Таблица и схема передачи системных каналов](SYSTEM_CHANNELS_RU.md).
Время работы переведено из тестового пользовательского uptime в
системный system_uptime. Тестовые счётчики — №98/99.
Числовой номер сохраняется в проекте, в HTTP ключом значения служит ID.
Существующие пользовательские страницы автоматически не перестраиваются.
Новая диагностика создаёт 23 канала API; текущий полный тест содержит ещё
два системных тестовых счётчика и девять пользовательских каналов.
Готов макет fle4d_current.flpui, совпадающий с контрактом прошитого теста.

Исправлена потеря открытого проекта после F5: локальный черновик, выбранная
страница, безопасные ошибки хранения. [Как работает](EDITOR_DRAFT_RU.md).
Проект открыт пользователю в текущем браузере на http://127.0.0.1:18836/.
Это локальный конструктор, http://192.168.100.12/ — интерфейс самого ПЛК.

## Проверка

- 54 автоматических теста и статическая проверка пакета.
- Пять синтаксических ветвей ARM GCC -Wall/-Wextra/-Werror: unsupported,
  F1, F4, другой STM32, disabled. Это не аппаратное испытание этих плат.
- На FLE4D 19 C++-проверок декодера/readonly/чтения памяти, 144 проверки полей.
- 25 gzip-ресурсов совпали с исходниками после OTA, длина и кеш проверены.
- Размер образа и статическая RAM совпали с BIN/компилятором, арифметика
  занято/свободно и system_uptime проверены через HTTP.
- POST для 16 диагностических ID отвергнуты HTTP422. Команды не повторялись.
- 60 снимков памяти: динамически занято 7136–7136 байт.
  Роста в короткой серии нет; длительного испытания на утечки не проводилось.
- Все служебные номера <=100, пользовательские >=101; SYSTEM_CHANNELS.json.
- GUI/F5 восстановили текущий проект и страницу; проверка проекта без ошибок.
  Ограничение одного HTTP-клиента сохраняется, параллельный опрос мешает
  тестовым TCP-подключениям; для ресурсной проверки лишняя вкладка закрывалась.
