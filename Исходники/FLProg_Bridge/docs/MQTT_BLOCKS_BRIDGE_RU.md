# Штатные MQTT-блоки через TCP-транспорт ESP

Кандидат от 29.10.2026. Проверен программно; FLE4D и ESP по этой задаче не прошивались. Установленная библиотека и общий релиз не заменялись, Гит не обновлялся.

## Что изменилось

Используется тот же `FLProgNetworkMqttClient`, что обслуживает стандартные Core, Publish и Subscribe. Добавлен сменный кооперативный TCP-транспорт `beginExternal()`. MQTT-пакеты, авторизация, фильтры подписок, reconnect, keepalive и сообщения обрабатываются **в ПЛК**. ESP выполняет только OPEN/WRITE/READ/CLOSE через службу5 общего UART-протокола.

В Core появился режим **NET_KIND=3**, а **NET_NUM** выбирает зарегистрированный UART-транспорт 1..8. Режимы 0=реестр, 1=Wiznet, 2=Wi-Fi сохраняются. Publish/Subscribe используются как прежде. Подготовлены Basic и Professional — всего шесть UBI.

Ошибка19 означает отсутствие выбранного интерфейса или незарегистрированный транспорт. При ошибочном выборе нет скрытого перехода к локальному Ethernet/Wi-Fi. Ошибки авторизации возвращает сам MQTT-клиент, например ERR10 при отказе CONNACK.

## Подключение

1. Используйте **библиотеку кандидата FLProg_Network** из комплекта. Старый релиз не содержит `beginExternal()` и адаптера. Штатные RT_HW_00_BASE, Flprog_Utilites, Wire и другие библиотеки не заменяются.
2. Импортируйте актуальные Core/Publish/Subscribe из Basic либо Professional. Импорт в живой FLProg ещё не проверен; XML, восстановленный код обоих форматов и сборка C++ проверены.
3. В проекте должен уже работать UART-мост с общим `flprog_bridge::Server`. UART, пины и скорость берутся из проекта, новый адаптер их не меняет.
4. Объявите один адаптер с постоянным временем жизни:

```cpp
#include <FLProgMqttBridgeTransport.h>
FLProgMqttBridgeTransport mqttTransport;
```

5. Один раз после создания Server зарегистрируйте его:

```cpp
bool ok = mqttTransport.attach(bridgeServer, 1);
```

Для проекта с автоматической привязкой редактора вместо `bridgeServer` используется `flprog_bridge_selected::binding().server`. Проверяйте `ok`: один и тот же Server нельзя повторно занять службой5, а номер транспорта должен быть свободен. На один UART/ESP сейчас один исходящий TCP-сокет.

6. В Core установите NET_KIND=3, NET_NUM=1. **Broker, Port, ClientID, User, Password задавайте в Core ПЛК**, Topic/Message — в обычных Publish/Subscribe. EN/CON/DIS и POLL_MS работают как раньше. Все блоки вызывайте каждый цикл: фактический обмен ограничен таймерами и бюджетами.
7. На ESP требуется Universal0.10 и режим «TCP-клиент ПЛК через ESP». В настройках ESP нет MQTT-брокера, авторизации или тем. Сеть Wi-Fi/LAN и UART остаются настройками транспорта.

В этом кандидате режим TCP-клиента занимает UART целиком: параллельный веб ПЛК/Modbus ещё не объединён с ним. Панель настроек самой ESP8080 остаётся доступна. См. [контракт TCP-клиента](PLC_TCP_CLIENT_RU.md).

## Семантика обмена

Адаптер сообщает MQTT о записанных байтах только после подтверждения TCP-операции ESP, а не при помещении данных в локальный буфер. Это позволяет корректно дослать MQTT DISCONNECT перед закрытием. При ошибке и отмене несданный буфер удаляется; публикации QoS0 не воспроизводятся после reconnect. Подтверждение TCP не означает подтверждения обработки брокером: QoS0 не имеет PUBACK.

Переподключение и восстановление подписок выполняет MQTT-клиент ПЛК. ESP не сохраняет задания между соединениями. Переход обратно на обычный сетевой режим снимает привязку внешнего транспорта. Внутренний TCP-клиент не открывается при работе через ESP.

## Программные проверки

- Компилируется **полный исходник MQTT-клиента кандидата**, без переписывания парсера в тест. Нативные сетевые/Arduino-зависимости заменены моделями; путь через ESP использует настоящие `FLProgMqttBridgeTransport`, службу5, COBS/CRC и ESP-прокси.
- Код извлечён из Basic UBI и восстановлен из тегов Professional UBI. Проверены оба варианта Core/Publish/Subscribe.
- Реальный localhost TCP и модель брокера: CONNECT с авторизацией из ПЛК, CONNACK, SUBSCRIBE/SUBACK, PUBLISH400байт, входящее сообщение и MQTT DISCONNECT — PASS.
- Разрыв брокера, новый CONNECT, автоматическое восстановление подписки, отсутствие повторной старой публикации — PASS для обоих вариантов.
- Отказ авторизации CONNACK5 даёт ERR10 — PASS.
- Семь подписок при SUB_LIMIT=0 — PASS. Лимит4 не вводится.
- Отсутствующий транспорт даёт ошибку19; обычный Native TCP-путь сохраняется — PASS.
- Контрольная сборка Generic STM32F407VG / STM32 core3.0.0 выполнена отдельно, без загрузки в устройство. Это не испытание реального UART и не OTA-образ профиля FLE4D.

Контрольная сборка STM32F407VG: Flash59736/RAM12672байт. Это отдельный минимальный скетч, не размер программы профиля FLE4D. BIN не предназначен для OTA и в комплект не включён.
