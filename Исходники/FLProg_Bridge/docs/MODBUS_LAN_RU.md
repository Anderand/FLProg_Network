# Modbus через Bridge и подключение Wi-Fi/LAN — программный прототип

29.10.2026. Два компонента: PLC-адаптер службы2 и сетевой Modbus TCP→Bridge UART шлюз. Реальные устройства не прошивались, COM не открывался, Гит и готовый общий релиз не менялись.

## Схема и статус

Modbus TCP клиент → Wi-Fi либо Ethernet ESP → общий UART Bridge → служба2 ПЛК → банки регистров приложения.

ESP не содержит проект ПЛК и таблицу физических выходов. Новый PLC-адаптер подключается явно: FLProgModbusBridge::attach(server). В HELLO служба2 появляется только после регистрации. Уже установленная прошивка ПЛК не получает её автоматически. Службы WebUI1 и ресурсы4 сохраняются.

Прототип реализован отдельным примером BridgeModbusLanPrototype. Внутри примера выбирается один режим: Modbus TCP либо прозрачный Bridge TCP. Он не заменяет универсальный BIN0.7: перенос LAN-настроек в его веб-форму и единая аппаратная проверка WebUI+Modbus ещё впереди. Новый шлюз принимает внешний признак uartFree: при занятой линии возвращает Modbus Busy, не смешивая кадры и не ставя запись в очередь. В нативном тесте также чередуются настоящие WebUI и Modbus клиенты на одном Server/UART, со свежимHELLO после смены владельца. Это программная проверка арбитража; непрерывный совместный веб+Modbus на ESP ещё не испытывался.

## LAN из нашей библиотеки

Используется FLProg_Network из общегоr17, собственные драйверы не дублируются. BridgeNetworkEndpoint работает через FLProgNetworkTcpServer и фиксированный маршрут выбранного интерфейса.

| Выбор конфигурации | Драйвер/маршрут |
|---|---|
| Wi-Fi | штатный Wi-Fi backend FLProg_Network, ROUTE_WIFI |
| Wiznet SPI | W5100/W5100S/W5200/W5500, автоопределение библиотекой, ROUTE_WIZNET |
| RMII LAN8720 | внутренний EMAC классической ESP32 и RMII backend библиотеки, ROUTE_RMII |

Наличие драйвера/успешная компиляция не означают, что каждый чип физически испытан на этой ESP. W5500 ранее проверен на FLE4D. Переиспользование драйвера не переносит автоматически аппаратный статус на новое подключение ESP. W6100, ENC28J60 и другие не добавлены на основании одного имени/резерва enum.

По умолчанию Ethernet получает IP по DHCP. Пины SPI/CS либо MDC/MDIO/PHY/clock/power/reset задаются конфигурацией; проверяются пересечения с UART и фиксированными RMII сигналами. Значения примера32/33UART,18/19/23SPI,CS5 — только пример, подключение ещё не согласовано. LAN8720 требует соответствующую плату/EMAC/тактирование; это не универсальный вариант для любойESP32/S3/C3.

В отдельном примере параметры читаются из отдельного NVS namespace flpbridge-lan. network0=WiFi,1=Wiznet,2=RMII; SPIполяsck/miso/mosi/cs, UART rx/tx/baud, RMII mdc/mdio/power/reset/phy/clock. Поляssid/password нужны толькоWi-Fi. Пример ничего не пишет в NVS и не меняет прежние настройки0.7. Графический редактор этих новых параметров ещё не добавлен. NVSservice1 выбирает ModbusTCP/порт502,service0 выбирает прозрачный Bridge/порт3234. Один режим на запуск, автоматического переключения сети/режима после обрыва нет. Порты8080/8081 зарезервированы. В BIN нет пользовательских сетевых реквизитов.

В прозрачном режиме PC Bridge сможет использовать tcp://LAN_IP:3234, как ранее tcp://ESP_WIFI_IP:3234, и получать веб из Flash ПЛК. Самостоятельный HTTP/WebUI8081 через LAN пока не перенесён: в этом примере HTTPсервера нет. Встроенная веб-форма0.7 пока по-прежнему Wi-Fi. Не выдавать этот прототип за готовое LAN-обновление всей программы.

## Modbus

Поддержаны функции1/2/3/4/5/6/15/16. Адреса в PDU с нуля, числа big-endian; это отдельное пространство, не номера WebUIканалов. Чтение до2000бит/125регистров, запись до1968бит/123регистров. Unit1..247, broadcast0 в этом прототипе отклоняется. См. [официальную спецификацию Modbus](https://modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf).

Служба2/op1: payload=UnitID+PDU без MBAP/RTUCRC. Ответ Bridge содержит свой статус и UnitID+PDU. MBAP transactionID сохраняется шлюзом. Неверный protocolID/length закрывает TCP без отправки UART. Максимум ADU260байт, один незавершённый запрос, работа до64байт заpool, безdelay/flush в прошивке. Таймаут UART1500мс, TCP-сеанса/обработки3000мс; проверка выполнена на программной модели, реальные низкие скорости требуют отдельной оценки.

Банки coils/discrete/holding/input принадлежат приложению; адаптер хранит указатели, не копирует банки. Неполные/неверные multi-write проверяются до изменения данных. Без WritePolicy запись закрыта. Callback WritePolicy(function,address,quantity,unitAndPdu,length) получает исходные байты и должен проверять разрешённые адреса, значения, диапазоны/режим/занятость; мост не предоставляет прямой доступ к произвольной памяти ПЛК. Запись в банк не доказывает физическое срабатывание выхода.

При занятом UART исключение06, при невозможности пути0A, при таймауте ответа0B. После таймаута записи результат неизвестен; шлюз её не повторяет. Повторная запись, отправленная самим внешним Modbus-клиентом, является новым запросом: стандартный transactionID не глобальный уникальный номер команды. Нельзя обещать exactly-once через переподключение TCP. Для неидемпотентных действий приложению нужен собственный номер команды и подтверждение.

## Проверки

Нативные тесты используют настоящий Server/службу2/клиент/MBAP-парсер, короткие read/write и ограниченные бюджеты. Проверены все8функций, максимальные пакеты, endian, некорректный MBAP/размер/адрес/ответ ПЛК, политика записи, неверныйUnit, busy, потерянныйACK без повтора. КлиентModbus616байт и TCPsession288байт в нативной сборке; это не измерение RAM наESP. Прежний WebUIклиент остаётся424байта, тесты его чтения/команд проходят.

Настоящий localhost TCP: запрос по одному байту, несколько запросов одним send, большие запросы/ответы, неверныйMBAP, reconnect, readonly и явный режим виртуальной записи. Проверка NetworkEndpoint с API-double подтверждает маршруты, DHCP, пины, одного клиента и lifecycle. Она не заменяет реальный драйвер; настоящий FLProg_Network проверяется отдельно компиляцией ESP32.
