# ESP Universal 0.7 — команды WebUI

Статус: программный прототип от 29.10.2026. Устройства не прошивались, COM и реальная сеть ПЛК не использовались, Гит и общий релиз r17 не менялись.

## Что добавлено

Полный проект по-прежнему приходит из Flash ПЛК порциями через ESP. PC Bridge не нужен. Помимо чтения доступны типизированные команды WebUI: bool, int32, конечный float и UTF-8 текст до63байт. Изменения находятся в универсальном мосте, без вшитого проекта/SSID/паролей. Политика ПЛК остаётся окончательным решением: канал publish, системный номер0..100, busy и отказ WritePolicy не обходятся.

На странице8081 нажмите «Включить управление». Разрешение действует только для текущего UART-сеанса, по умолчанию запись закрыта. НастройкиESP остаются на8080. Включение управления не меняет NVS. При новомHELLO/утратеUART-сеанса требуется включить заново. «Отключить управление» запрещает новые команды, но не отменяет уже отправленную.

## Подтверждение и отсутствие повторов

Браузер проверяет виджет/канал, свежий сеанс из X-FLProg-Session, enabled/busy, тип, диапазон/шаг и ограничения текста. Затем отправляет одну команду. ESP проверяет cookie/token, UART-владение, разрешение текущего сеанса и монотонный requestId. Повторный или меньший номер, в том числе с изменённым значением, отклоняется без UART. Одинjob, без очереди.

Полученный OK означает «принято ПЛК в очередь», ответ WebUI202 содержит queued=true и confirmed=false. Подтверждение данными показывает существующий renderer после чтения. Это подтверждение значения, не доказательство физического срабатывания выхода. Отдельное выполнение FBD подтверждается его связями busy/result; мост не придумывает успешный результат.

При таймауте после отправки интерфейс сообщает: «Результат команды неизвестен. Повтора не было; проверьте данные ПЛК». Запись локально отключается. Автоматического повтора команды, включая повтор послеHELLO/восстановления сети, нет. Повторение requestId запрещено в пределах запускаESP; после перезапускаESP старый UART-сеанс недействителен. Перезагрузка страницы сама по себе команду не отправляет.

## Программные испытания

Рабочая папка: E:\SAI\FLProg_Network\_work\esp32_commands_20261029.

Используются настоящие C++HTTP-обработчики ESP и Server/WebUI/Resources с моделью FLE4D. Не эмуляция радио/UART ESP. Все значения синтетические, сверху страницы DEMO. Аппаратная проверка ESP↔FLE4D остаётся впереди.

- Браузер: явное включение, AO0=1234, подтверждение диалога, readback1234 и уведомление «Подтверждено данными». DO1 false→true также подтверждён чтением.
- Native HTTP: запись по умолчанию запрещена; неверныйCSRF/старыйсеанс/повторныйномер/изменённыйповтор отклонены.
- Реальная модель WritePolicy: уставка20000 при диапазоне0..10000 отклонена ПЛК; число принятых команд не выросло.
- Потерянный ACK: ПЛК принял ровно1команду; ESP дошла доtimeout. Повторное чтение результата не передаёт команду; старый номер послеHELLO также отклонён.
- НовыйHELLO выключает разрешение, сбросServer даёт Session и не принимает команду.
- Типы:63байта текста/пустойтекст/bool; NaN, системныйканал, неверныйbool, NUL и невернаядлина отклоняются.
- Прежние тесты чтения, UARTбюджетов/CRC/таймаутов, владения/lease, конфигурации и SHA/gzip проходят.

CHECKS.json, COMMAND_CHECKS.json, BUILD.json и снимок COMMANDS_PREVIEW.png содержат результаты. BIN только собран, не установлен. Долгий heap-тест, физические выходы, Wi-Fi/ESP/UART и аппаратные busy/result в этом этапе не проверялись. Дополнительные службы Modbus/MQTT ещё не реализованы.

## HTTP API для интеграции

Все запросы требуют авторизованную cookie настроекESP. Токен viewer получают на8081, он отличается от токена настроек8080.

1. GET /plc-api/session → token, ready, session(16символовhex), readOnly. readOnly отражает разрешение записи для этого endpoint.
2. POST /plc-api/start (form-urlencoded): token, op=hello, channel=0. GET /plc-api/result?ticket=... читает результат, не создавая новый UART-запрос.
3. POST /plc-api/control: token, enable=1, session. Возвращает enabled и nextId. enable=0 запрещает последующие команды.
4. POST /plc-api/start: token, op=write, session, requestId=nextId, payload=hex. Возвращает202/ticket при начале передачи. requestId увеличивать; переполнение требует нового запускаESP, номер0непринимается.
5. GET /plc-api/result?ticket=... → state, status, payloadHex, session. state3=OKприёма,4=timeout/неизвестныйрезультаткоманды,5=отказПЛК,6=отмена. При потере самого HTTP-ответа нельзя автоматически повторять команду.

payload: байтномераканала + байттипа (0bool/1int32/2float/3text) + значение. Числа LE32, bool0/1, текст UTF-8 до63байт безNUL. Например AOканал135/int32/1234: 8701d2040000. Этот пример относится только к модели FLE4D и не должен автоматически отправляться физическому устройству.

400=неверныепараметры,403=авторизация/записьзакрыта,409=UARTзанят/устаревшийсеанс/повторномера,503=нетсети/исчерпаниетикетов. ESP не хранит каталог правил проекта: проверки виджета в браузере помогают пользователю, а разрешение/диапазоны/занятость должны обеспечиваться WritePolicy ПЛК.
