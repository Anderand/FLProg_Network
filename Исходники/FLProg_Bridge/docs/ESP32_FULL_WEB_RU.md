# Полный веб из Flash ПЛК через ESP — Universal 0.6

Статус: программный прототип, 29.10.2026. На устройства не устанавливался. Реальная ESP остаётся на 0.4; UART ESP–FLE4D ещё не испытан.

## Как работает

Браузер → HTTP ESP:8081 → ограниченный UART-протокол → служба ресурсов 4 в ПЛК. PC Bridge для этого режима не нужен. Универсальный BIN ESP не содержит проект FLE4D, его ID, SSID или пароли. Один и тот же мост получает проект от подключённого ПЛК.

1. HELLO проверяет протокол и доступность службы 4.
2. ESP запрашивает паспорт пакета: gzip, размер, SHA-256, размер порции.
3. Браузер получает пакет порциями до 224 байт с проверкой смещения и длины. Видит прогресс.
4. В браузере проверяются SHA-256 пакета, gzip, размеры, состав файлов, SHA каждого файла, ID проекта, webApi и webHash из HELLO.
5. Только после проверки открываются исходный интерфейс и все страницы проекта.
6. Чтение каналов идёт через batch службы WebUI; максимум 16 номеров в запросе, частичный ответ дочитывается следующей порцией.

Распаковка и хранение пакета происходят в памяти браузера. На ESP нет полного пакета в RAM, нет распаковки и записи LittleFS/NVS. Небольшие HTTP-строки создают временные выделения; это не утверждение об отсутствии любых динамических выделений. Расход heap под Wi-Fi и HTTP требует аппаратного замера.

## Порты и запуск после будущей установки

- 8080 — прежняя защищённая страница настроек ESP.
- 8081 — полный веб ПЛК. Сначала войти на 8080, затем открыть ссылку «Веб из Flash».
- 3234 — прозрачный TCP/UART, если не изменён настройками.

Порты 8080/8081 запрещены для TCP-моста. Формат NVS остаётся прежним. Для viewer используется отдельный CSRF-токен; токен настройки сети ему не передаётся. Страницы работают в обычной локальной HTTP-сети; нужен браузер с DecompressionStream('gzip'), без CDN. SHA-256 обеспечивает целостность, но не является подписью или шифрованием. См. [стандарт Compression Streams](https://compression.spec.whatwg.org/).

Один UART обслуживает одного владельца: TCP либо HTTP. На время запросов viewer удерживает право чтения, после 5 секунд без активности освобождает его. Параллельные запросы получают явный отказ, очереди и автоматического повтора команд нет. Таймаут кадра — 1500 мс; аппаратная проверка разных скоростей UART ещё нужна.

## Ограничения этапа

Полный макет и чтение каналов реализованы. Запись команд, DO/AO, дополнительные API (например сканирование) через этот viewer ещё не реализованы. Элементы управления отключены, запросы записи отклоняются. Это не готовая замена всех возможностей PC Bridge. При смене проекта проверяется новый контракт; при изменении сеанса требуется свежее чтение. Ошибка целостности останавливает загрузку до исполнения проекта, повтор запускает пользователь кнопкой.

Пределы прототипа: сжатый пакет до 2 МиБ, распакованный до 8 МиБ. Поддержан текущий экспорт flprog.bridge/1, flprog.webui/1.0, webApi1. Аппаратная скорость, Wi-Fi, отсутствие утечек при долгой работе и ресурс heap пока не измерены.

## Программная проверка

Рабочая папка: E:\SAI\FLProg_Network\_work\esp32_full_web_20261029.

Стенд использует реальные C++ обработчики HTTP ESP, кооперативный клиент, Server/WebUI/Resources и скомпилированный пакет FLE4D-30MT. Python предоставляет только локальный HTTP-адаптер этих обработчиков: приложение PC Bridge не участвует. Модель значений синтетическая и явно помечена DEMO. Это не эмуляция радио ESP и не аппаратное испытание.

Пакет: 15 438 байт gzip, 72 634 байта после распаковки, 69 порций. В браузере проверены Главная, Диагностика, Входы и Выходы. Повреждение gzip останавливается по SHA-256, подмена projectId — по контракту. Нативно проверены токены, занятость TCP, истечение lease и переполнение millis, запрет команд, пределы порций, batch. Отдельно пройдены прежние тесты HTTP-клиента/маршрутов/конфигурации и тесты SHA/gzip/манифеста.

См. CHECKS.json, NATIVE_TRANSFER.json и BUILD.json в рабочей папке. BIN собран только для проверки компиляции; автоматически не устанавливать. Гит и общий релиз r17 не изменялись.
