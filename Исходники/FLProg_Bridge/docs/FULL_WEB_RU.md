# Полный веб через COM

Мост — самостоятельная программа FLProg Network. Ethernet для передачи
страницы и значений через COM не нужен. Редактор нужен только для подготовки
проекта, а не для его повседневной работы.

1. Откройте свой проект в редакторе и нажмите **Экспорт для моста**.
2. Экспорт создаёт `bridge_web`: страницу, описание каналов и паспорт SHA-256.
   В библиотеке проекта создаётся `<ID>_bridge.h`; подключите этот заголовок
   в прошивке, использующей UART-адаптер моста. Простой стартовый Web-блок сам
   по себе UART-транспорт не добавляет.
3. Соберите согласованную прошивку. Если макет изменился, старый BIN и новый
   экспорт не совместимы — мост покажет ошибку хеша вместо чужого интерфейса.
4. Запустите `FLProg_Bridge.exe`, выберите COM, скорость и папку `bridge_web`.
   Для проверенного FLE4D UART6: PC6 TX, PC7 RX, 115200 бод. Этот UART нельзя
   одновременно использовать для текстовой консоли и Modbus RTU.
5. Подключитесь и откройте показанный локальный адрес `http://127.0.0.1:.../`.
   Адрес и порт могут меняться при запуске; использовать адрес из старого
   снимка экрана не требуется.

Доступны те же страницы, поля, подтверждения и уведомления, что в Ethernet-вебе.
Чтения объединяются в ограниченные пакеты UART. «Принято» означает постановку
команды в очередь ПЛК; подтверждение значения получается последующим чтением.

Запись разрешается отдельно в программе и политике прошивки. Для профиля стенда
FLE4D дополнительно включается режим управления выходами; AO ограничены
диапазоном 0–10000 мВ. После разрыва UART управляющий сеанс истекает, режим
моста отключается, а исходная логика ПЛК снова получает управление.

После сброса или потери COM программа может восстановить соединение автоматически.
Поля перечитываются в новом сеансе; старые команды автоматически не отправляются.
На компьютере приложение держит неизменяемую копию выбранного экспорта, поэтому
перезапись файлов редактором не меняет интерфейс уже работающего сеанса.

Подписи и значения строковых виджетов разделены отступом. Длинные строки
переносятся; экспорт и предпросмотр используют те же базовые стили, что веб ПЛК.

Это руководство описывает локальную разработку 0.2.0. Результаты аппаратных
испытаний и точные версии BIN фиксируются отдельно; наличие функции в коде
не означает, что проверены все контроллеры и интерфейсы.
