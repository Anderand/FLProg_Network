# FLProg Bridge UART v0.1

Два пользовательских блока с одинаковой логикой: Basic/FLProg_Bridge_UART.ubi и Professional/FLProg_Bridge_UART_Professional.ubi. Второй — настоящий Code Professional с тегами входов/выходов; не переименованный Basic.

## Назначение и границы этапа

Блок управляет свободным аппаратным UART: включает, обслуживает порциями и отключает его; показывает готовность, активность сеанса и счётчики. Пины RX/TX задаются в настройках платы FLProg. SPI, Ethernet и DHCP блок не перенастраивает. Сайт и каналы берутся из подготовленного проекта и зарегистрированных служб.

Это пока блок транспорта, а не автоматический старт любого проекта по ID. Он требует настроенного объекта flprog_bridge::Server и зарегистрированных служб WebUI/ресурсов. Выбор проекта по ID и автоматическое связывание служб в экспорте — следующий отдельный шаг. Наличие блока само по себе не добавляет OTA, Modbus или MQTT.

## Подключение

1. Для этой рабочей версии используйте согласованную FLProg_WebUI из папки libraries комплекта: общедоступная точка входа src/flprogBridgeUserBlocks.h, остальные заголовки находятся в src/bridge. Штатные RT_HW_00_BASE и Flprog_Utilites не заменяются. В IDE ничего автоматически не копируется.
2. В проекте оставьте один UART-блок: Basic или Professional. Его нужно вызывать каждый цикл логики.
3. Выделите свободный UART в настройках FLProg. Уберите с него консоль, Modbus RTU и другие потребители; не вызывайте отдельно Serial.begin()/RT_HW_Base.uartBegin() для этого порта.
4. В пользовательских объявлениях после создания настроенного сервера добавьте:

```cpp
#define FLPROG_BRIDGE_SERVER bridgeServer
```

Имя bridgeServer — пример: это существующий объект Server вашего проекта. Регистрация служб и модель WebUI остаются в проектном адаптере. Без этого определения сборка остановится с понятной ошибкой, вместо открытия порта без нужного проекта.
5. Для FLE4D: EN=true, UART=6, BAUD=115200, BUDGET=64. PC6 TX и PC7 RX задаются проектом; ST-Link VCP/USB-UART подключается с общей землёй и совместимыми уровнями.
6. В программе FLProg Bridge выберите соответствующий COM и ту же скорость. Режим передачи8N1; ROM-прошивка STM32 черезUART — другой сценарий и к этому блоку не относится.

## Входы

| Вход | Значение |
|---|---|
| EN | Разрешение транспорта. false закрывает только порт, открытый этим блоком, и сбрасывает сеанс и недоотправленный ответ |
| UART | Номер аппаратного UART по RT_HW, фактическая доступность проверяется для платы |
| BAUD | 1200..1000000, обычно115200; поддержка конкретной скорости зависит от UART |
| BUDGET | 1..128 байт за вызов в каждом направлении, обычно64 |

Менять UART/BAUD следует при EN=false, затем включать заново. При изменении на ходу ERR=6, новое значение не применяется и чужой порт не открывается. При недопустимой порции обработка приостанавливается до исправления параметра. Занятый порт блок не закрывает и не перехватывает. Если перестать вызывать блок, он не сможет исполнить EN=false: вызов должен оставаться в каждом цикле.

## Выходы

| Выход | Значение |
|---|---|
| READY | Блок открыл UART, параметры корректны; это не подтверждение подключённого PC |
| CONNECTED | Валидный сеанс с запросами за последние3,5с; это не мгновенный датчик USB-кабеля |
| ERROR / ERR | Ошибка конфигурации/запуска и её код |
| RX_BYTES / TX_BYTES | Число реально принятых/отправленных байтов UART, включая кадрирование |
| BAD_FRAMES | Ошибки кадров/CRC протокола; не число отклонённых команд |

Счётчики не обнуляются от EN; выход Long показывает младшие31бит, после2147483647 будет0. Значение Connected исчезает по таймауту, а не сразу при закрытии браузера. Блок не выполняет физические команды сам: их разрешает и обрабатывает политика проекта.

ERR:0=нет ошибки;1=недоступный UART;2=скорость вне диапазона;3=недопустимая порция;4=ошибка запуска;5=UART занят;6=смена UART/скорости при EN=true.

## Проверки

- XML обоих UBI: уникальность идентификаторов и только обратные ссылки.
- Из обоих файлов восстановлен код: логика совпадает; оба варианта скомпилированы и исполнены с тестовым RT_HW.
- Реальный C++ транспорт с аппаратной заглушкой: границы параметров, владение портом, очистка неудачного запуска, RX/TX budget, HELLO, таймаут, заполненный TX, выключение/новый сеанс и ошибки кадров.
- Служба ресурсов с обновлённым протоколом:3 теста, PASS.
- Аппаратный импорт UBI в FLProg и прошивка блока на плату пока не выполнялись. Сборка F407 фиксируется отдельно в BUILD.json/BUILD.log.

На реальном контроллере остаётся1.0.10-BRIDGE-LINK. GitHub, готовые архивы и открытые EXE не менялись.
