# TCP-клиент ПЛК через ESP — Universal 0.10

## Разделение обязанностей

Адрес TCP-сервера и порт задаёт **ПЛК** при открытии соединения. MQTT-клиент, имя клиента, авторизация, темы, подписки, keepalive и решение о переподключении принадлежат ПЛК. ESP не разбирает MQTT, не хранит эти настройки в NVS и не повторяет публикации.

В ESP добавлен только транспортный режим **«TCP-клиент ПЛК через ESP»**. Сеть Wi-Fi/LAN и UART настраиваются как раньше. В этом режиме ESP не слушает входящий TCP-порт прозрачного моста/Modbus. Поле порта службы отключено: адрес и порт назначения приходят из ПЛК. Настройки ESP остаются на 8080.

**Ограничение первого прототипа:** режим занимает UART целиком. Доступ к данным веба ПЛК через 8081 и другие службы UART приостановлены, настройки самой ESP доступны. Совместное обслуживание MQTT и веба с общим сеансом ещё не реализовано; переключение разных владельцев с разными HELLO разрывало бы TCP-соединение. Наличие веб-загрузчика на 8081 не означает доступности данных ПЛК в этом режиме.

## Программный интерфейс ПЛК

Новые переносимые заголовки:

- `FLProgTcpBridge.h` — служба 5, один незавершённый запрос;
- `FLProgBridgeTcpClient.h` — кооперативный поток с ограниченными RX/TX-буферами по 220 байт.

```cpp
FLProgTcpBridge socketService;
FLProgBridgeTcpClient tcp(socketService);
// При настройке существующего UART Server:
socketService.attach(bridgeServer);
// В цикле, без delay/ожидания:
bridgeServer.pool(uart, millis(), 64);
tcp.pool(millis());
```

`tcp.connect(host, port)` ставит попытку открытия; результат проверяют через `tcp.connected()`. Это асинхронный контракт, не блокирующий Arduino Client. `tcp.write(data, size)` принимает до 220 байт в буфер и возвращает принятое количество, а не подтверждение доставки сервером. `available()/read()` читают полученные данные, `stop()` отменяет оставшуюся локальную передачу и закрывает соединение. При неизвестном исходе передачи буфер сбрасывается, данные не отправляются повторно автоматически.

Существующие FLProg MQTT-блоки не переключаются на этот транспорт автоматически: новый поток пока является отдельным API. Следующий шаг интеграции — адаптер транспорта для существующего MQTT-клиента ПЛК и блоков Basic/Professional. MQTT на стенде формирует сторона ПЛК, а не стандартные блоки FLProg. Это проверка работоспособности TCP-потока для MQTT, а не заявление о завершении интеграции всех MQTT-блоков.

## Протокол

Используется прежний COBS/CRC/сеансовый UART. ESP остаётся инициатором кадров и опрашивает службу 5 ПЛК; встречных неарбитрируемых отправок нет. Служба 3 «MQTT» не используется: транспорт передаёт произвольные TCP-байты.

- Операция 1 NEXT, пустой запрос: ответ `0` при отсутствии задания либо `requestId:uint32LE / operation:uint8 / data`. Задание выдаётся один раз; до результата повторный NEXT не возвращает его заново.
- Задания: OPEN=1 (`hostLength:uint8 / port:uint16LE / host`, до127 байт имени), WRITE=2 (1..220 байт), READ=3 (запрашиваемый размер uint16LE, 1..220), CLOSE=4 (пусто).
- Операция 2 RESULT: `requestId:uint32LE / error:uint8 / connected:uint8 / data`. WRITE возвращает фактически записанное количество uint16LE, READ — байты. Ошибка — 1, успех — 0. Результат принимается только для выданного задания с совпадающим ID.

Один сокет, без TLS и без записи MQTT-настроек на ESP. Попытка соединения до8 секунд, задание ПЛК до10 секунд, UART-ответ до1500мс; работа UART до64байт за проход, опрос заданий не чаще10мс. При отсутствии службы5 повторная проверка ограничена, сокет закрыт. Потеря UART/сети, новый сеанс и reset ПЛК отменяют незавершённый обмен; очереди для последующего воспроизведения нет. Частичная подтверждённая TCP-запись продолжается только с ещё не принятых байт.

## Проверки

- Реальный localhost TCP с моделью MQTT-брокера: CONNECT с авторизацией из ПЛК, CONNACK, SUBSCRIBE/SUBACK, публикация400байт, входящее сообщение и закрытие — PASS. Нативный backend ограничивает write до7байт, UART — до7байт, проверяется продолжение частичных передач.
- Границы/занятость, потерянный RESULT ACK, отсутствие повторной записи после восстановления, таймаут задания, reset ПЛК, потеря сети и переполнение millis — PASS.
- Интерфейс ПЛК компилируется Cortex-M4 / C++11; это object compile, не прошивка FLE4D.
- Предыдущие чтение/ресурсы/команды WebUI, конфигурация, Modbus-runtime — PASS.

Настоящий Wi-Fi/LAN/UART и MQTT-блоки ПЛК требуют последующей проверки. Физический FLE4D по этой задаче не прошивается. Все результаты сохраняются в `E:\SAI\FLProg_Network\_work\esp32_tcp_client_20261029`.
