# Исправление готовности W5500 при сохранённой DHCP аренде

Рабочая папка: E:\SAI\FLProg_Network\_work\ethernet_link_20261028.
Основа: проверенная 1.0.9-BRIDGE-FLASH, пользовательский проект4, DHCP.
Кандидат: 1.0.10-BRIDGE-LINK. Старые сборки и установленные IDE-библиотеки не изменены.

## Причина

В updateEthernet() ранний выход до следующей проверки линка выставлял _ethernetReady=true при bound DHCP. После физического обрыва это отменяло обнаруженную ошибку линка. Наличие аренды не означает наличие физического соединения.

## Изменение

Ранний выход сохраняет результат последней проверки; только плановая проверка линка может снова подтвердить готовность. DHCP обслуживается как прежде, IP аренды не сбрасывается из-за одного обрыва. Новых полей, буферов и дополнительных SPI-проверок в каждом цикле нет. Обнаружение обрыва и восстановления ограничено существующим периодом проверки, а не мгновенное.

## Регрессия

Компилируется фактическая функция updateEthernet(), извлечённая из исходника, с управляемыми часами и аппаратными заглушками. На старом коде тест падает на первом промежуточном цикле после обрыва. Исправленный код проходит: обрыв с действующей арендой,99 промежуточных вызовов без дополнительных чтений линка, возврат кабеля, потерю и получение аренды, SPI busy, DHCP failure, статический IP, запуск, W5100 с неизвестным линком, неизвестное оборудование и переполнение millis.

Это программная проверка логики, не аппаратное испытание. Результат сборки и аппаратные проверки фиксируются отдельно.
