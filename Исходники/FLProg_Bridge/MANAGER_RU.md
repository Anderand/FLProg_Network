# Менеджер прошивок 0.8.0-preview.5

При выборе графического STM32CubeProgrammer.exe используется соседний
STM32_Programmer_CLI.exe. Если CLI отсутствует, операция останавливается с
понятным сообщением; графическое приложение не запускается. CLI также ищется
в стандартном каталоге установленного STM32CubeProgrammer. Внешний пакет ST
не входит в переносимый комплект и нужен только для SWD/UART, не для OTA и веб-моста.

Текущий профиль FLE4D-30MT получен из пользовательского `4/4.ino`:
1.0.8-BRIDGE-WEB, DHCP, UART6 для полного веба COM. Проект и BIN заменены в
менеджере до установки по OTA. Рабочий исходник и библиотеки лежат отдельно
в `Проект_профиля`; исходный файл4 сохранён. Поле IP по умолчанию пустое —
адрес DHCP находят сканером, фиксированная подсеть в профиль не зашита.

Новое общее название прежнего STM32 OTA-менеджера. Задача программы — сборка
приложений и загрузчиков, управление профилями и прошивка контроллеров.
OTA остаётся одним из способов, а не названием всего продукта.

В программе доступны:

- сборка BIN и пакетов под платы каталога, проверка совместимости;
- сборка одного или всех загрузчиков;
- FLProg STM32 OTA и первичная установка через ST-Link/SWD;
- поиск OTA и существующая политика проверенных/непроверенных профилей;
- вкладка **COM / UART**: выбор COM-порта, скорости, обновление списка;
- запуск отдельного COM-моста с выбранным портом и папкой веб-проекта;
- проверка системного ROM-загрузчика и первичная UART-запись загрузчика и приложения.

Запустите FLProg_Firmware_Manager.exe. Сохранённые settings.json прежнего менеджера
совместимы, но в этот комплект личные настройки не копируются. Загрузчики прежние.
Приложение профиля FLE4D — **1.0.8-BRIDGE-WEB**, проверенное на нашем ПЛК:
DHCP, полный веб через COM, чтение I/O, команды, HTTP и OTA с автосбросом.
UART6 PC6/PC7 115200 выделен мосту; консоль и Modbus RTU на UART6 исключены.
DO/AO разрешаются отдельно в мосте и режиме управления страницы «Выходы».
Другие UART и алгоритмы I/O сохранены.
Профиль не содержит статического IP; в другой сети адрес выдаст роутер.
Перед прошивкой выбирайте свой ПЛК: MAC из исходного проекта пока фиксированный,
для нескольких одновременно подключённых контроллеров MAC должны отличаться.

## Первичная прошивка по COM / UART

1. На вкладке «Прошивка» выберите профиль, BIN приложения или программу профиля
   и путь к STM32CubeProgrammer CLI. IP для UART и SWD не требуется.
2. Откройте **COM / UART**, обновите список и выберите свой порт и скорость.
3. Переведите MCU в системный загрузчик. Для F407: BOOT0=1, BOOT1=0, RESET;
   подключение USART1 PA9 TX / PA10 RX либо USART3 PB10 TX / PB11 RX
   (также PC10/PC11). UART6 PC6/PC7, используемый для нашего веба, ROM не поддерживает.
4. Закройте программы, занявшие выбранный COM. Нажмите «Проверить ROM-загрузчик».
   Проверяются Device ID и объём Flash, без записи.
5. Нажмите «Записать загрузчик и приложение по UART» и подтвердите профиль,
   порт и адреса. Каждый образ проверяется после записи; массового стирания нет.
6. Верните BOOT0=0 и выполните RESET. Самостоятельно запускать программу
   при оставленном BOOT0=1 менеджер не пытается.

ROM использует 8E1; веб-мост — 8N1. Подключайтесь к TTL-выводам MCU, не к RS-485.
Для другого STM32 проверьте интерфейсы и вход в ROM в
[ST AN2606](https://www.st.com/resource/en/application_note/an2606-stm32microcontroller-system-memory-boot-mode-stmicroelectronics.pdf).
UART-запись проверена программными тестами команд и отказов; аппаратная первичная
прошивка по UART пока не выполнена. COM-мост и OTA на FLE4D проверены аппаратно.

Новые MCU, USB DFU и прошивка через универсальный мост — последующие этапы.
Для сборки нужна ваша Arduino IDE/core/библиотеки; для SWD/UART — STM32CubeProgrammer.
Обновлять IDE/библиотеки автоматически этот комплект не будет.
