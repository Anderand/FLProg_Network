# HTTP API независимого моста

Основа `http://127.0.0.1:<порт>`. API версии `flprog.bridge/1`.
Программа выбирает свободный порт, если не задан `--http-port`.
Её можно запускать из любого приложения списком аргументов, без оболочки.

| Запрос | Ответ |
|---|---|
| GET /api/v1/status | online, session (строка!), device, demo, writesEnabled, exchanges, badFrames |
| GET /api/v1/channels/101/meta | number, id, type, direction, session |
| GET /api/v1/channels/101 | number, value, session |
| POST /api/v1/channels/101 | accepted, confirmed=false, session, message |

Пример команды (session взять из свежего ответа чтения):

```javascript
await fetch('/api/v1/channels/101', {
  method: 'POST',
  headers: {'Content-Type': 'application/json', 'X-FLProg-Bridge': '1'},
  body: JSON.stringify({session: lastRead.session, type: 'float', value: 30.5})
});
```

Session передаётся строкой: uint64 нельзя без потерь хранить в JavaScript Number.
HTTP 200 означает приём команды, не физическое выполнение. Используйте отдельные
каналы обратной связи; не повторяйте POST автоматически. Смена session требует
полной синхронизации и нового решения пользователя о передаче команды.

Типы: bool, int32, float, text. Значения строго соответствуют типу; int32 имеет
знаковый диапазон, float конечный, текст максимум 63 байта UTF-8 без NUL.
Номер канала 0..255; запись 0..100 запрещена. HTTP-тело максимум 1024 байта.

Ошибки возвращают JSON `error`: 400 запрос, 403 запись/источник запрещены,
409 занято/смена сеанса/несовпадение проекта, 501 неподдерживаемая служба,
502 повреждённый ответ, 503 нет связи/неизвестный результат передачи.
После timeout/read error требуется явное переподключение в программе.

Нет CORS для чужих сайтов. Для POST обязателен X-FLProg-Bridge: 1, Origin при его
наличии должен совпадать с локальным адресом; Host проверяется также для GET.
Сайт размещается в папке --site (см. README); общий протокол и API не требуют
редактора. Полный текущий HTTP API Ethernet WebUI пока не эмулируется: это отдельный
адаптер следующего этапа, а не обещание совместимости произвольной готовой страницы.

Службы Modbus/MQTT не имеют публичных HTTP маршрутов в 0.1.0.
# Полный веб редактора в 0.2.0

При выбранной папке `bridge_web` доступны исходные маршруты интерфейса:
`/flprog-webui/item` (страницы и каталоги виджетов), `/flprog-webui/state`
(пакет чтения каналов страницы или отдельный канал) и `/flprog-webui/write`.
У записи должны быть JSON-тело, `X-FLProg-Bridge: 1` и `X-FLProg-Session`
из свежего чтения. Проверяются тип, диапазон, виджет и свежие busy/enabled.
Ответ202 подтверждает очередь, а результат перечитывается через state.

Полный контракт маршрутов воспроизводится адаптером существующего WebUI.
До выдачи ресурсов и команд проверяются ID проекта, Web API1 и SHA-256
ресурсов из HELLO. Несовпадение даёт409. `/api/v1/status` доступен и при
несовпадении, чтобы показать причину. Автовосстановление создаёт новый сеанс;
POST-команды автоматически не повторяются.
