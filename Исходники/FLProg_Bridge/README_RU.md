# FLProg Bridge 0.4.0-preview.1 — самостоятельный мост связи

Локальная предварительная версия нового компонента FLProg Network.
Редактор и менеджер могут запустить мост, но не нужны для его работы.
В комплекте три отдельные программы: `Мост_связи`, `Редактор`, `Менеджер_прошивок`.
Это рабочий прототип первого этапа, а не замена опубликованного r16.

Менеджер0.8.0-preview.4 имеет вкладку **COM / UART**: выбор порта и скорости,
запуск отдельного веб-моста и первичная STM32 ROM UART-запись. Первичная запись
по UART пока проверена программно, не на плате. [Руководство менеджера](MANAGER_RU.md).

## Новое в рабочей версии

[Автопривязка проекта к UART-блокам](docs/AUTO_BINDING_RU.md): экспорт создаёт сервер и службы, ID общий со стартовым блоком. [ESP32 Universal](docs/ESP32_UNIVERSAL_RU.md): универсальный прозрачный мост с настройками Wi-Fi/UART в NVS, без проекта ПЛК в BIN. ESP не прошивалась; пользовательский веб пока открывается через PC Bridge. Фактически установленная версия FLE4D —1.0.10-BRIDGE-LINK. Приведённые ниже ранние версии сохранены как история.

## Предыдущие проверки на FLE4D-30MT

Текущая локальная сборка **1.0.8-BRIDGE-WEB** получена из пользовательского
`4/4.ino`. Полный веб редактора работает через COM5/UART6: четыре страницы,
диагностика, входы и управление выходами. Исправлены отступы подпись/значение,
проверен узкий экран 360 px. Ethernet — DHCP. Менеджер **0.8.0-preview.3**
содержит этот BIN в профиле до его установки по OTA.

На стенде проверены подтверждения, DO1 и AO0 с чтением регистров GPIO/DAC,
возврат к логике ПЛК и автоматическое восстановление нового сеанса после reset.
Старые команды не повторились; первые 64 КиБ Flash совпали до/после.
Полный веб и программная команда проверены при физически отключённом Ethernet;
напряжение на клеммах не измерялось. [Полный веб: инструкция](docs/FULL_WEB_RU.md).

### Предыдущая проверка 1.0.6

28.10.2026 установлена **1.0.6-BRIDGE** и проверен настоящий COM5 через ST-Link
к UART6 PC6/PC7, 115200. Ethernet получает адрес по **DHCP**; на стенде выдан
192.168.100.19. В другой сети адрес будет другим.

По указанию пользователя UART6 исключён из консоли и Modbus RTU профиля и выделен
мосту. Прочитаны системные каналы и I/O, проверена программная команда 241→242
с отдельным счётчиком243, 100 чтений без ошибок кадров. Физические DO/AO через
COM запрещены. Работают HTTP, OTA и автоматический перезапуск; старый сеанс
после reset недействителен, команды не повторяются. Область загрузчика сохранена.
Профиль включён в Менеджер прошивок **0.8.0-preview.2**. Подробности:
[аппаратный отчёт](HARDWARE_RU.md).

## Как посмотреть без контроллера

1. Откройте `Мост_связи\FLProg_Bridge.exe`.
2. Нажмите **Демо без контроллера**, затем **Открыть веб-интерфейс**.
3. Прочитайте канал 101: это уставка. Канал 102 — переключатель, 10 — описание демо.
4. Чтобы проверить передачу команды, включите **Разрешить команды** в окне моста.
5. Измените значение в браузере, передайте и прочитайте снова.

Демо не открывает COM и не обращается к устройствам в сети.
«Принято» подтверждает очередь команд, а не работу физического выхода.
Прочитанное значение командного/duplex слота также само по себе не доказывает
выполнение. Для этого проект должен иметь отдельные обратные связи busy/result.

## Подключение настоящего ПЛК

Нужна прошивка с `firmware/FLProgBridgeProtocol.h` и адаптером
`firmware/FLProgWebUiBridge.h`. Установленные ранее прошивки автоматически
не приобретают поддержку моста. Сам мост не прошивает ПЛК — для этого используется
отдельный менеджер прошивок и совместимый профиль.
Адаптер требует FLProg_WebUI из папки `Библиотека` этого комплекта: добавлен
метод commandPending(), без изменения структуры каналов и без увеличения их RAM.
Установка библиотеки только вручную; комплект не копирует ничего в IDE.

Выберите COM и скорость, соответствующую прошивке. Порт не должен быть занят
монитором Arduino. Подключение — свободный UART TTL с совместимыми уровнями;
RS-232/RS-485 требуют своего преобразователя. Мост не переключает BOOT и не
посылает аппаратный reset. DTR/RTS запрашиваются выключенными до открытия порта;
некоторые драйверы могут дать импульс при открытии, поэтому не соединяйте их
с RESET/BOOT при испытании обычного UART-моста.

После таймаута/перезапуска нажмите **Подключить COM** и заново прочитайте данные.
Автоматического повтора команд и автоматического открытия найденных COM нет.
Открытие/закрытие редактора не управляет жизненным циклом моста.

## Свой сайт и запуск из других программ

Пример PowerShell (путь к EXE замените своим):

```powershell
& '.\FLProg_Bridge.exe' --site 'E:\MyPanel\web'
```

В папке сайта создайте `bridge.json`:

```json
{"api":"flprog.bridge/1","projectId":"my-plc","entry":"index.html"}
```

Сайт выдаётся только при совпадении projectId с подключённым ПЛК.
Встроенная сервисная страница всегда доступна по `/bridge`.
Папка должна содержать только публичные файлы сайта; не выбирайте корень проекта
со скетчами, настройками и секретами. `bridge.json` наружу не выдаётся.

Параметры: `--port COM5 --baud 115200`, `--http-port 0` (выбрать свободный),
`--allow-writes`, `--demo`, `--headless`, `--no-browser`, `--status-file <json>`.
При запуске без `--port` COM не открывается. Все HTTP-адреса слушают только 127.0.0.1.
Для кнопок запуска держите папки `Мост_связи`, `Редактор`, `Менеджер_прошивок` рядом.
Отдельную установку можно указать переменной окружения FLPROG_BRIDGE_EXE.

## Границы первого этапа и следующие работы

Полные страницы нашего проекта пока автоматически не экспортируются в мост;
кнопка в редакторе открывает отдельную программу, не переносит проект и не меняет
его транспорт. Пока доступны сервисная страница каналов и свой сайт по API.
Следующий этап: экспорт страниц/манифеста, служба чтения описаний из Flash и кеш,
блоки подключения UART в Basic и Professional. FLE4D/UART6 уже проверен;
длительные испытания, реальный обрыв кабеля и сравнение времени цикла ещё впереди.

После этого: ESP32, ESP8266, Modbus и MQTT. Для каждого нужен отдельный контракт
маршрутизации/таймаутов/буферов, а не простая передача произвольного сетевого потока.
Автоматическая прошивка по COM, новые семейства MCU и прошивка через мост — отдельные
этапы менеджера. В этой версии менеджер сохраняет существующие STM32 OTA/SWD.

См. [протокол](PROTOCOL_RU.md), [HTTP API](API_RU.md),
[схема](docs/FLProg_Network_Architecture_v1.png).
