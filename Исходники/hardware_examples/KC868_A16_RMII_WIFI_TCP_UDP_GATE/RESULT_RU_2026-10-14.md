# Результат: KC868-A16 RMII + Wi-Fi TCP/UDP gate

Статус: **PASS — 15.10.2026**.

## Аппаратный прогон KC868-A16

| Направление | Адрес | Порт | Результат |
|---|---|---:|---|
| RMII TCP echo | `192.168.100.12` | `5001` | PASS |
| Wi-Fi TCP echo | `192.168.100.15` | `5001` | PASS |
| RMII UDP echo | `192.168.100.12` | `5002` | PASS |
| Wi-Fi UDP echo | `192.168.100.15` | `5002` | PASS |
| HTTP diagnostics | оба IP | `80` | PASS, `httpShared=1` |

После прогона JSON подтвердил: оба интерфейса ready, RMII link up, `error=0`, отдельные счётчики RX/TX увеличились на каждом маршруте, `udpSendFailures=0`.

## Failover RMII → Wi-Fi → RMII

1. При отключении Ethernet: RMII перешёл в `ready=false`, `link=false`, IP `0.0.0.0`; Wi-Fi остался ready на `192.168.100.15`.
2. Во время отсутствия Ethernet Wi-Fi HTTP, TCP `:5001` и UDP `:5002` прошли успешно; `error=0`.
3. После возврата кабеля RMII автоматически получил прежний DHCP IP `192.168.100.12`.
4. RMII HTTP, TCP `:5001` и UDP `:5002` снова прошли успешно, без перезагрузки контроллера.

Итог: **двухтранспортный HTTP/TCP/UDP сервис и физический RMII ↔ Wi‑Fi failover подтверждены аппаратно.**

## Примечание ревизии

Проба принудительного `SO_BINDTODEVICE` для ESP32/lwIP оказалась несовместимой с Arduino core и была полностью отменена. Финальный PASS достигнут штатным route-fixed API библиотеки без этой привязки.
