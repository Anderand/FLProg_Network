# KC868-A16 RMII OTA hardware gate

Отдельная проверка ArduinoOTA через встроенный LAN8720/RMII на KinCony
KC868-A16. Wi-Fi намеренно не запускается: успешная передача прошивки должна
идти по кабелю. Используется публичный `FLProgNetworkOta` API.

## Подготовка

1. Установите обновлённую `FLProg_Network` в sketchbook Arduino IDE.
2. Откройте `KC868_A16_RMII_OTA_GATE.ino`.
3. В начале скетча замените временный `FLPROG_OTA_GATE_PASSWORD` на свой
   отдельный тестовый пароль. Не используйте пароль Wi-Fi.
4. Выберите ту же плату FLProg ESP32S-Dev-Module и ту же конфигурацию платы,
   что использовались для RMII gate. Разметка flash должна включать две OTA
   app-партиции (OTA_0 и OTA_1); схема только с одной app-партицией не подходит.
5. Первый раз прошейте скетч по USB.

RMII-параметры KC868-A16: PHY `0`, MDC `GPIO23`, MDIO `GPIO18`, clock
`GPIO17 OUT`, DHCP. Ожидаемый адрес в текущей сети — `192.168.100.12`, но
используйте IP из Serial Monitor.

## Проверка

1. В Serial Monitor на 115200 дождитесь:
   `RMII ready=1 link=1 ip=... OTA ready=1 state=4 error=0`.
2. В Arduino IDE выберите сетевой порт `kc868-a16-rmii-ota` / `.local`, если
   он появился, введите OTA-пароль и загрузите скетч через Ethernet.
3. Если mDNS-порт не показывается, соберите бинарный файл через **Скетч →
   Экспорт бинарного файла** и используйте `espota.py` из установленного
   ESP32 core, указав IP, файл и пароль. Например:

   ```powershell
   python "C:\FL\FLProg_9.8.1_Windows_Portable\ideV8\portable\packages\esp32\hardware\esp32\3.3.11\tools\espota.py" `
     -i 192.168.100.12 -p 3232 -a "ВАШ_OTA_ПАРОЛЬ" `
     -f "ПУТЬ_К_СКЕТЧУ.bin"
   ```

   Путь к Python можно взять из поставки FLProg либо запустить `espota.exe`
   с теми же параметрами.
4. PASS: компьютер завершил upload, плата перезапустилась, Serial Monitor
   снова показывает RMII и OTA ready, а `updateStartCount` и
   `updateEndCount` увеличились.
5. Повторите передачу ещё раз. Для негативного теста один раз укажите
   неправильный пароль: обновление должно быть отвергнуто, после чего OTA
   должен остаться доступным для правильного пароля.

## Безопасность и границы проверки

- ArduinoOTA не шифрует передаваемый firmware; пароль защищает процедуру
  авторизации, но не заменяет сегментацию сети. Используйте только доверенную
  локальную сеть.
- Этот gate проверяет только RMII/lwIP. Для отдельной проверки W5500 используйте
  `hardware_gates/ESP32_W5500_OTA_GATE`: там OTA принимает тот же `espota.py`,
  но передача идёт через SPI TCP/UDP backend библиотеки, а не через ArduinoOTA.
- Не загружайте обновление при нестабильном питании и не прерывайте питание
  во время записи flash.
