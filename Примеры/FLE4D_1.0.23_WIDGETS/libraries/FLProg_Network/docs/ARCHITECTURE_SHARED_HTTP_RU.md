# Архитектура единого WebServer для нескольких интерфейсов

## Назначение

Один набор FLProg Web-страниц должен быть доступен через несколько IP-адресов, но не должен создавать отдельный большой HTTP parser/context на каждый интерфейс. Это особенно важно для ESP8266.

## Схема

```text
                     один FLProgNetworkHttpServer
                     один HTTP parser/context
                                |
        +-----------------------+-----------------------+
        |                       |                       |
  primary TCP listener    shared TCP listener     shared TCP listener
        |                       |                       |
 Wi-Fi STA .217          W5500 #1 .218           W5500 #2 .219
        |
   SoftAP listener .4.1 (когда AP включён)
```

Первичный listener выбирается при запуске. Для обычной конфигурации с Wi-Fi-клиентом им является STA. Если Wi-Fi недоступен, сервер стартует на доступном W5500. Остальные пути подключаются как child/shared listeners и не создают новый HTTP context.

## Legacy FLProg-совместимость

FLProg может сгенерировать несколько `FLProgWebServer` на один визуальный Web-интерфейс, по одному на каждое сетевое устройство. При одинаковом TCP-порте библиотека:

1. оставляет первый объект владельцем HTTP-контекста;
2. переводит последующие legacy-объекты в followers;
3. подключает их интерфейсы к владельцу через `addSharedListener()`;
4. не запускает отдельные parser/context у followers.

Так generated `.ino` остаётся неизменным, а RAM не расходуется на дублирующиеся WebServer.

## Жизненный цикл

1. Network interfaces выполняют `pool()` и сообщают готовность.
2. Primary listener запускается на готовом маршруте.
3. Followers добавляют готовые интерфейсы как shared listeners.
4. Один активный HTTP context по очереди обслуживает клиентов всех listeners.
5. При потере транспорта TCP listener снимается и повторно привязывается после восстановления интерфейса.

## Ограничения

- `FLPROG_HTTP_SERVER_MAX_SHARED_LISTENERS=3`: один primary плюс до трёх дополнительных маршрутов. Текущая схема STA + AP + W5500 #1 + W5500 #2 укладывается точно.
- Автоматическое legacy-объединение применяется к объектам одного TCP-порта. Независимые Web-сервисы следует размещать на разных портах.
- Один parser/context означает последовательную обработку запросов. Это сознательная плата за предсказуемую RAM на ESP8266.

## Диагностика

Для тестовых скетчей используются поля: готовность каждого интерфейса, `listen`, `route`, `tcpError`, число shared listeners и счётчики HTTP. Нормальный готовый сервер: `listen=1`, `tcpError=0`.
