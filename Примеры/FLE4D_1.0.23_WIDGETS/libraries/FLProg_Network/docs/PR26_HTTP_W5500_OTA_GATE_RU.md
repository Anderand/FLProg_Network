# PR26: HTTP, W5500 и OTA — закрывающий gate

Дата: 27.09.2026.

## Конфигурация

- ESP8266 NodeMCU 0.9, ESP8266 core 3.1.2.
- Wi-Fi STA: `192.168.100.217`.
- W5500 #1: `192.168.100.218`.
- W5500 #2: `192.168.100.219`.
- SoftAP исключён из PR26.
- HTTP использует единый штатный профиль; компактный HTTP-профиль не
  поддерживается.
- OTA через Wi-Fi STA: PASS, устройство обнаруживается и прошивается по
  сети.

## Результаты

- Стартовая проверка Web: `HTTP 200` на всех трёх адресах, размер страницы
  4170 байт.
- W5500, контролируемый темп (750 мс между запросами): 10/10 успешных
  запросов на каждом W5500.
- После серии запросов все три HTTP-интерфейса восстанавливаются и отвечают
  `HTTP 200`.
- Свободная память с включённым Wi-Fi OTA: 4008 байт.

## Явный контракт legacy HTTP

Для сгенерированного `FLProgWebServer` сохранён один одновременный HTTP
контекст. Это исключает второй крупный parser context из DRAM ESP8266.
При burst-запросах без паузы новый TCP connect может попасть в короткое окно
между закрытием активного W5500-клиента и открытием нового LISTEN socket и
получить отказ. Это ограничение зафиксировано; нормальная браузерная работа и
контролируемая последовательность запросов проходят устойчиво.

Не увеличивать число legacy HTTP-контекстов без отдельного измерения RAM и
аппаратного soak-теста.

## Не входит в этот gate

- OTA по W5500/RMII: не реализована; поддерживается только Wi-Fi OTA.
- RMII web gate: ожидает оборудование.
- Optical transport: ожидает выбора архитектуры и оборудования.
