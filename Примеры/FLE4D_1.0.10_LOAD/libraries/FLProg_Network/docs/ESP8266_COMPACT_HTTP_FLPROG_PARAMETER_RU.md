# Снятый эксперимент: параметр «Экономия RAM для ESP8266»

> Статус: удалён из поддерживаемой конфигурации PR22.

Компактный HTTP-профиль и макрос
`FLPROG_NETWORK_ESP8266_COMPACT_HTTP` были экспериментальными. После
аппаратной проверки конфигурации STA + SoftAP + два W5500 они исключены как
нестабильные. Библиотека использует единый штатный HTTP-профиль; генератор
FLProg не должен добавлять этот макрос в скетч.

Ниже сохранено исходное описание исключительно как историческая запись. Оно
не является спецификацией для генератора и не должно реализовываться.

## Назначение

Добавить в блок настройки сети FLProg параметр, включающий компактный HTTP-профиль библиотеки на ESP8266. Он нужен для проектов, где одновременно работают Wi-Fi STA, SoftAP, W5500 и legacy WebServer, а свободной RAM недостаточно для больших временных `String` веб-страницы.

Параметр не должен быть включён по умолчанию: обычные проекты сохраняют действующие лимиты HTTP.

## UI блока

- Раздел: `Интерфейсы → Встроенный модуль WiFi → Стандартные параметры`.
- Имя: `Экономия RAM для ESP8266`.
- Тип: BOOL-параметр.
- Значение по умолчанию: `Нет`.
- Показывать только для ESP8266.
- Подсказка: `Уменьшает буферы HTTP и оставляет один одновременный браузерный клиент. Рекомендуется для STA + точка доступа + WebServer при нехватке памяти.`

## Генерация

Если параметр включён, генератор должен записать **до всех `#include` библиотеки сети**:

```cpp
#define FLPROG_NETWORK_ESP8266_COMPACT_HTTP 1
```

Если параметр выключен, директиву не генерировать. Не задавать значение `0`: это позволит пользователю переопределить настройку вручную в специальном include, если это потребуется.

Корректное расположение:

```cpp
#define RT_HW_FLPROG_PRG "..."
#define RT_HW_FLPROG_PRJ "..."
#define FLPROG_NETWORK_ESP8266_COMPACT_HTTP 1

#include "flprogUtilites.h"
#include "flprogEthernet.h"
```

## Эффект профиля

На ESP8266 профиль уменьшает только внутренние лимиты HTTP:

- один одновременный HTTP-клиент;
- до 4 заголовков и аргументов;
- запросные заголовки до 1024 байт;
- тело запроса до 256 байт;
- внутренний response buffer до 1024 байт.

Legacy-страницы FLProg продолжают передаваться потоково и не ограничиваются response buffer. Shared HTTP через STA, SoftAP и W5500 сохраняется.

## Проверка реализации

1. Сгенерировать ESP8266-проект со STA, AP, двумя W5500 и WebServer.
2. Включить параметр и убедиться, что директива стоит до include.
3. Открыть страницу через STA, AP и оба W5500.
4. Убедиться, что при включении AP Wi-Fi-страница сохраняет CSS и полный вид.
5. Отключить параметр и убедиться, что директива исчезла, а существующий проект не меняется.
