# FLProg Web UI Editor — установка и работа

Локальный конструктор веб-интерфейса для проектов FLProg. Он хранит дизайн
отдельно от `FLProg_Network`, создаёт пакет библиотеки конкретного проекта и
не меняет общие файлы разработчика.

## 1. Что должно быть установлено

1. Распакуйте/скопируйте папку `FLProg_WebUI_Editor` в постоянное место на
   диске. Не размещайте её внутри `libraries`.
2. Установите в папку библиотек FLProg две библиотеки из комплекта:
   `FLProg_Network` и `FLProg_WebUI`.
3. Запустите FLProg Portable хотя бы один раз. Отдельный Python ставить не
   нужно: `Start_Editor.bat` умеет использовать Python, который входит в
   FLProg Portable. Если FLProg находится не в стандартной папке `C:\FL`,
   установите Python 3 или поправьте путь `FLPROG_PYTHON` в
   `Start_Editor.bat`.

## 2. Запуск редактора

В переносимой поставке откройте папку `FLProg_WebUI_Editor` и дважды щёлкните
`Start_Editor.bat`. Он сначала запускает
`portable\FLProg_WebUI_Editor\FLProg_WebUI_Editor.exe`; отдельный Python
устанавливать не нужно. Не переносите один EXE отдельно: рядом с ним должна
оставаться папка `_internal`.

Если переносимого EXE нет, BAT попробует системный Python, а затем Python из
FLProg Portable. После запуска браузер откроет `http://127.0.0.1:8766/`.
Это локальный адрес; интернет, регистрация и облачный сервис не требуются.
Окно редактора оставьте работающим до окончания работы. Чтобы закрыть редактор,
закройте его окно программы.

Если в браузере сохранилась старая версия, нажмите `Ctrl+F5`.

## 3. Создание страницы

1. Нажмите **Новый** для пустого проекта либо **Демо** для образца.
2. Слева задайте **ID проекта**. Используйте латинские буквы, цифры и `_`,
   например `boiler_room`.
3. Добавьте пользовательские каналы кнопками `+ Bool`, `+ Float`, `+ Int`,
   `+ Text`. Их номера начинаются с 101. Номера 0–100 зарезервированы для API
   `FLProg_Network`.
4. Нажмите `+ Wi‑Fi`, `+ Точка доступа`, `+ Сканер Wi‑Fi` или
   `+ Диагностика`, когда нужна готовая системная страница. Редактор добавит
   совместимые API-каналы автоматически.
5. Добавляйте **элементы** для структуры страницы: заголовок, текст,
   разделитель, ссылку. Добавляйте **виджеты** для обмена с FBD: индикаторы,
   вводы, переключатели, графики и другие.

## 4. Настройка виджета

Двойной щелчок по карточке открывает настройку.

- **Основное** — подпись, описание, значок, тип.
- **Данные** — основной канал и дополнительные связи с ролями `setpoint`,
  `alarm`, `busy`, `result`, `series1`, `series2`. Для органов управления
  `setpoint` задаёт канал записи; состояния показываются в карточке, а
  `series1/series2` строятся отдельными линиями графика. Связь `value`
  позволяет выбрать другой канал для отображения. Роли должны ссылаться на
  существующие каналы, иметь подходящее направление и не повторяться внутри
  виджета.
- **Поведение** — варианты, минимум, максимум и шаг.
- **Вид** — акцентный цвет карточки.
- **Сетка** — точные X/Y/W/H и кнопки быстрого перемещения/изменения размера.
- **Код отображения** — HTML-шаблон с `{{label}}`, `{{value}}`, `{{icon}}`.
  Это не изолированная безопасная среда: используйте только доверенный код.
  Отображение выполняет браузер, а не микроконтроллер.

Один щелчок выбирает карточку, перетаскивание меняет её положение.
**Фокус: вкл** временно скрывает левую панель и оставляет только макет.

## 5. Сохранение и сборка

- **Сохранить** — сохраняет исходный проект `.flpui` в папке `projects`.
  Этот файл переносите между компьютерами или храните в архиве проекта.
- **Открыть** — загружает ранее сохранённый `.flpui`.
- **Собрать и установить** — создаёт отдельную Arduino-библиотеку
  `FLProg_WebUI_Project_<ID>` и устанавливает её в папку библиотек FLProg.
  Общие `FLProg_Network` и `FLProg_WebUI` при этом не перезаписываются.

После сборки перезапустите FLProg, если библиотека не появилась в списке.

## 6. Использование в FLProg

1. Откройте или создайте FBD-проект для нужного контроллера.
2. Добавьте сетевой интерфейс из `FLProg_Network` (например Wi‑Fi STA) и
   настройте его обычными средствами FLProg.
3. Импортируйте **один раз** файл
   `FLProg_WebUI_Universal_Blocks.ubl` из `FLProg_WebUI/user_blocks`. Он создаёт
   папку блоков `FLProg Web UI` с блоками Publish и Command для Bool, Int, Float
   и Text. Не импортируйте восемь отдельных `.ubi`, если нужен весь комплект.
4. После **«Собрать и установить»** найдите созданную библиотеку
   `FLProg_WebUI_Project_<ID>` в `sketchbook/libraries`. Импортируйте из неё
   `FLProg_WebUI_Configure_<ID>.ubi` и поместите блок
   `FLProg Web UI Configure <ID>` в FBD **ровно один раз**. Это обязательный
   конфигуратор: он включает descriptor проекта и запускает HTTP-интерфейс на
   выбранном транспорте. Не добавляйте старый/общий Web UI Core.
5. В блоке конфигуратора транспорт уже выбран редактором. В FBD должен быть
   добавлен соответствующий интерфейс `FLProg_Network` (для обычного Wi‑Fi —
   Wi‑Fi STA). Если интерфейс изменить в редакторе, пакет нужно пересобрать и
   повторно импортировать проектный `.ubi`.
6. Для обмена данными добавляйте только нужные канальные блоки из папки
   `FLProg Web UI`:

   | Направление канала | Блок | Подключение |
   |---|---|---|
   | `publish` | `Publish <тип>` | `EN=true`, `CHANNEL=номер`, `VALUE=переменная FBD` |
   | `command` | `Command <тип>` | `EN=true`, `CHANNEL=номер`; `NEW` — импульс новой команды, `VALUE` — принятое значение |
   | `duplex` | оба блока одного типа | `Publish` отправляет фактическое значение; `Command` принимает новое значение по тому же номеру |

   Номер `CHANNEL` берите из левого списка каналов конструктора: API — №0…100,
   пользовательские — №101 и выше. Например, в демо `light` — Bool, №102:
   `Command Bool` с `CHANNEL=102` передаёт новую уставку в логику реле; после
   обработки командами публикуйте `Publish Bool` с тем же номером и фактическим
   состоянием реле. `NEW` используйте как признак однократного события, а не
   как постоянный уровень.

7. Выполните в FLProg генерацию скетча. Откройте сгенерированный скетч в Arduino
   IDE, выберите целевую плату и COM-порт, нажмите **Проверить/Скомпилировать**,
   затем **Загрузить**. После прошивки откройте IP контроллера в браузере.
8. При изменении только оформления или расположения виджетов откройте прежний
   `.flpui`, пересоберите пакет и прошейте новый скетч. Канальные блоки заново
   импортировать не нужно. При изменении ID проекта или транспорта повторно
   импортируйте новый `FLProg_WebUI_Configure_<ID>.ubi`.

Если FLProg не показывает импортированную библиотеку, перезапустите FLProg.
Если сборка жалуется на отсутствующий descriptor или адаптер, проверьте, что
пакет проекта установлен в `sketchbook/libraries`, а библиотека `FLProg_WebUI`
установлена рядом с `FLProg_Network`.

## Важно

- Дизайн принадлежит проекту: не храните `.flpui` внутри `FLProg_Network`.
- Не редактируйте сгенерированную библиотеку вручную; изменения делайте через
  `.flpui` и повторную сборку.
- Страницы и ответы контроллера передаются порциями, поэтому большой интерфейс
  не должен упираться в ограничение одного HTTP-ответа ESP8266.
