# FLE4D-30MT — тест WebUI 1.7.0 + OTA

Версия прошивки: **1.0.6-WEBUI1.7**. Плата: FLE4D-30MT / STM32F407VG, Flash 1 MiB.
Сборка выполнена 24.10.2026. Установлена по OTA; защита busy проверена на ПЛК. См. [аппаратную проверку](BUSY_GUARD_RESULT.md).

## Загрузка

1. Откройте OTA-менеджер. Выберите проверенный профиль своего FLE4D-30MT.
2. Укажите IP `192.168.100.8`, порт `3233`, пароль оставьте пустым.
3. В поле BIN приложения выберите **FLE4D_WEBUI_1_0_6.bin** из этой папки.
   Проверьте имя в логе отправки: не используйте старый application.bin из профиля.
4. Отправьте по OTA и дождитесь автоматического перезапуска и DHCP.
5. В UART6 (TX PC6 / RX PC7, 115200) должна появиться строка
   `FIRMWARE VERSION: 1.0.6-WEBUI1.7`, затем `WEB begin=1`.
6. Откройте `http://192.168.100.8/`. При необходимости обновите страницу с Ctrl+F5.
   Если DHCP выдал другой IP, используйте адрес из UART или OTA-сканера.

## Что проверять

- Вверху страницы — связь и возраст данных; видны группы «Поля ввода», «Команды», «Диагностика».
- Измените уставку (0…100, шаг 0,5) и нажмите «Применить» или Enter.
  Должно появиться подтверждение приёма, а «Применённая уставка» обновится.
  Значение вне диапазона или не по шагу не отправляется.
- Введите имя (до 30 байт UTF-8). Черновик не должен пропадать при опросе.
  Enter применяет, Escape отменяет. Для кириллицы обычно нужно 2 байта на букву.
- Нажмите «Тестовая команда»: сначала отмените диалог — счётчик не изменится.
  Затем подтвердите: `Выполняется: да`, через 5 с `Выполняется: нет`, `Выполнено: да`, флаг переключится,
  счётчик увеличится. Перед следующим тестовым запуском дождитесь `Выполняется: нет`.
  UART дополнительно выводит приём и завершение команды.
- Отключите Ethernet на 10 с: статус должен показать отсутствие свежих данных,
  а кнопки/поля заблокироваться. Верните кабель — опрос и управление восстановятся.
  Если IP изменится после DHCP, откройте новый адрес.

Команды демонстрационные: меняются только значения в RAM, физические выходы ПЛК
не переключаются. После перезапуска значения и счётчик сбрасываются.
Квитанция приёма отличается от выполнения: выполнение здесь показывает тестовая логика,
аналогичная публикации busy/result из FBD.

## Сеть и загрузчик

Сохранены проверенные настройки: W5500, SPI0 PB13/PB14/PB15, CS PB12,
MAC 78:AC:C0:40:A3:3C, DHCP, UART6 115200, OTA 3233 без пароля и автоперезапуск.
BIN связан для приложения с адреса **0x08010000**, максимум 458752 байта.
Это файл приложения для существующего загрузчика, а не объединённый образ.
Загрузчик отдельно переустанавливать не нужно. Не загружайте этот BIN по адресу 0x08000000.

Размер, начальный стек, адрес запуска и SHA-256 проверены в VERIFICATION.json.
Скетч в папке Скетч/FLE4D_WEBUI_1_0_6, описание макета .flpui и лог компиляции находятся рядом.
Этот BIN включён в локальный общий комплект r5. GitHub не обновлялся.

## Сборка из исходника

Установите FLProg_WebUI и FLProg_Network из этого комплекта вручную. Откройте `Скетч/FLE4D_WEBUI_1_0_6/FLE4D_WEBUI_1_0_6.ino`. Используйте OTA-профиль FLE4D-30MT: приложение с 0x08010000, параметры профиля как у проверенной 1.0.1. Макет .flpui описывает веб; тестовую логику RAM-команд реализует скетч, это не готовый проект .flp.
