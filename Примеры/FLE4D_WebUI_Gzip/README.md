# Проверенный gzip на FLE4D-30MT

Вариант **gzip/FLE4D_WEBUI.bin** проверен по OTA на STM32F407VG/W5500.
Обычный вариант для сравнения: **plain/FLE4D_WEBUI.bin**.
Оба рассчитаны на приложение с 0x08010000 и существующий OTA-загрузчик.
В менеджере выберите BIN вручную; приложение профиля не заменено этим тестом.

| Показатель | Обычный | Gzip | Разница |
|---|---:|---:|---:|
| Flash | 137040 | 130856 | −6184 байта |
| Статическая RAM | 16112 | 16112 | 0 |
| BIN | 137524 | 131340 | −6184 байта |
| Статические ресурсы | 17063 | 9560 | −7503 байта |

RAM — данные компоновщика; пик heap/стека отдельно не измерялся.
Версия 1.0.7-WEBUI1.7 сохранена для чистого сравнения, варианты различаются
SHA-256 и HTTP Content-Encoding. Скетч меняет RAM, физические выходы не трогает.

## Воспроизведение

Используйте скетч из Скетч/FLE4D_WEBUI_1_0_7 и библиотеки из корня комплекта.
Только три библиотеки проекта устанавливаются вручную; RT_HW_00_BASE,
Flprog_Utilites и Wire берутся штатные из IDE. Профиль FLProg_FLE4D_30MT_OTA,
STM32 core 3.0.0, -Os, offset 0x10000, maximum_size 458752.
Для сравнения задайте FLPROG_WEBUI_GZIP_ASSETS=0 или =1 через build.extra_flags.
Исходные команды и логи обеих сборок сохранены в plain и gzip: пути в командах
относятся к машине испытания и при переносе заменяются вашими путями.

HTTP-проверка check_device.py выполняет только чтение по фиксированному
тестовому адресу 192.168.100.8; её запускают только для согласованного FLE4D.
Данные plain_device.json/gzip_device.json — снимки проведённых испытаний.
Для C++-теста tools/host/test_sender.cpp добавьте tools/host в include path;
заголовок flprogNetwork.h там — только имитация HTTP API для host-теста.
