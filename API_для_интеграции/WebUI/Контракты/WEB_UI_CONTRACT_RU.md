# Контракт FLProg Web UI 1.0 — черновик

## Объекты

`WebUiProject` — файл дизайна `<id>.flpui` рядом с проектом FLProg.

`WebUiChannel` — стабильный идентификатор данных между FBD и браузером. У него
есть `id`, тип (`bool`, `int32`, `float`, `text`), направление (`publish`,
`command`, `duplex`) и человекочитаемая подпись.

`WebUiDescriptor` — генерируемый C++-файл из проекта. Он описывает только
страницы, виджеты и каналы; не содержит Wi-Fi-параметров или FBD-логики.

## Совместимость изменений

| Изменение | Нужна новая `.fvl`/связь FBD | Нужен новый конфигуратор |
|---|---:|---:|
| Подпись, стиль, порядок, страница | нет | нет |
| Диапазон/шаг виджета | нет | нет |
| Новый канал | да | нет |
| Удаление канала | да | нет |
| Смена типа/направления | да | нет |

## Правило памяти

В коде, вызываемом каждый цикл FLProg, запрещены `String`, `new`, `delete`,
`malloc`, формирование JSON и рост буферов. Событие команды хранится в
фиксированном slot и извлекается один раз.

## HTTP-протокол (первый слой)

`FLProgWebUiHttpProtocol` формирует JSON ответа `GET /flprog-webui/state` в
буфер, который предоставляет транспорт. Команда браузера передаётся методом
`write(channel, value)` и превращается в одно типизированное событие канала.

Класс не открывает сокеты и не включает Wi-Fi/Ethernet. За приём HTTP-запроса,
URL-декодирование, размер входного запроса и отправку ответа отвечает отдельный
платформенный transport-адаптер. Это отделение позволяет проверить протокол и
модель до интеграции с ESP8266/W5500.

## ESP8266 transport v0.1

`adapters/FLProgWebUiEsp8266Http.h` — первый реальный transport. Он не
подключает Wi-Fi и не управляет SSID/IP: приложение FLProg делает это само,
создаёт `ESP8266WebServer`, затем вызывает `begin(server)` и `poll()`.

Маршруты: `GET /`, `GET /flprog-webui/state`,
`POST /flprog-webui/write?channel=...&value=...`. Буфер ответа имеет
фиксированный размер 768 байт и при переполнении возвращает HTTP 507. `String`
допускается только внутри обработки фактического HTTP-запроса ESP8266 core,
но не в FBD-цикле.

## Основной transport для FLProg

`FLProgWebUiFlprogNetworkHttp` — целевой transport. Он использует
`FLProgNetworkHttpServer` и принимает любой готовый `FLProgNetworkInterface`.
Следовательно, Web UI не реализует второй Wi-Fi-стек и не дублирует TCP/HTTP:
Wi‑Fi, W5500 и другие сети обслуживаются единообразно библиотекой
`FLProg_Network`. Проектные descriptors и дизайн при этом в неё не записываются.


## Ограниченные шаблоны полей

Необязательные pattern (до63 ASCII) и validationMessage (до96 байт UTF-8)
добавлены последними полями descriptor. Для text-input/password-input
применяется полное совпадение ограниченного подмножества; оно одинаково
в браузере и STM32. См. [PATTERN_RU.md](../PATTERN_RU.md).
