# Один профессиональный стартовый блок Web UI

Актуализировано 27.10.2026. Требование пользователя: один универсальный блок; проект
выбирается параметром ID, а не импортом отдельного конфигуратора каждого проекта.

## Проверенный образец формата

Разобран предоставленный CRMui3_v.6.1_(WebServer.h)_(Code_-_Professional).ubi.
Это UTF-16 XML с корнем UserCodeMultiBlockBlockLibraryElement и mainBlock
типа UserCodeMultiBlock. Размер файла 23750596 байт. Формат прочитан как
данные; вложенные библиотеки не исполнялись и не устанавливались.

В примере обнаружены:

- UserCodeMultiBlockStandartParametr — именованный параметр;
- UserCodeMultiBlockInputFieldParametrSpecies — поле ввода с defaultValue;
- isInsertWithoutBrackets — подстановка без кавычек;
- UserCodeMultiBlockUseInCodeStandartParametrTag — ссылка из кода на тот же
  объект параметра, а не ненадёжная замена совпадающего текста;
- UserCodeMultiBlockEditorCodeObject — части обычного текста и параметров;
- отдельные declare/setup/loop/function секции и общий/индивидуальный код;
- conditionsLibrary — условия генерации;
- isUseItOnce — ограничение стартового блока одним экземпляром.

Непосредственно в declareSection примера есть последовательность:

```cpp
#define SPEED_UART_CRM [параметр скорости UART]
#define NAME_PROJECT [параметр «Название проекта»]
```

Квадратные вставки здесь обозначают объекты-параметры XML, не буквальный C++.
Это подтверждает наличие параметризованного формирования объявлений.
Одного чтения XML недостаточно, чтобы считать новый блок испытанным в FLProg.

## Выбранная схема для нашего проекта

Один профессиональный блок «FLProg Web UI Start» со стабильным ID самого
блока и параметром PROJECT_ID. Он задаётся до компиляции; это не изменяемый
строковый вход во время работы ПЛК.

Параметр «ID проекта»: 2–64 символа, латинская буква в начале, далее
буквы/цифры/подчёркивания/дефис; без пробелов, кавычек, расширения и пути.
Файловый ID сохраняется буквально, C++ namespace использует safe_identifier.

Редактор генерирует проектный header-обёртку, который сам подключает
descriptor, устанавливает polling и выбирает интерфейс FLProg по transport.
Таким образом универсальный блок не содержит настроек SPI/Ethernet и не
нуждается в отдельном типе блока для Wi-Fi/W5500.

Для ID a123 FLProg создаёт:

```cpp
// Declare — сформировано профблоком из PROJECT_ID.
#include <a123_webui.h>

// Setup — стабильная точка входа header-обёртки.
FLPROG_WEBUI_BEGIN_SELECTED();
```

Header-обёртка создаёт стабильный alias/точку входа выбранного проекта;
сетевой макрос разворачивается только при вызове в конце setup(), поскольку
FLProg объявляет интерфейс и его макрос после include. Пины и параметры сети
к этому моменту уже настроены.
символы его собственного namespace формируются генератором через
safe_identifier. Это позволяет ID с допустимым дефисом остаться именем
файла, не превращая дефис в недопустимое C++-выражение в блоке.

В declare профблока подключение состоит из трёх частей:
обычный текст `#include <`, ссылка-тег PROJECT_ID без кавычек,
обычный текст `_webui.h>` и перевод строки. Имя проекта не зашивается
в постоянную строку блока.

При нескольких установленных пакетах подключается ровно выбранный header;
прочие макеты не нужно включать в прошивку и выделять под них RAM.
При изменении страниц с тем же ID пересобирается пакет и прошивка;
стартовый блок остаётся тем же. При смене ID меняется только параметр.

## Проверки перед заменой текущей схемы

1. Минимальный собственный профблок: один ID, один экземпляр, без чужих
   вложенных библиотек и прикладного веб-кода.
2. Импорт и генерация настоящего скетча в FLProg: пустой ID, отсутствующий
   пакет, два установленных проекта, смена ID, ID с дефисом.
3. Проверка wrapper/namespace/transport, однозначная ошибка компиляции
   вместо выбора первого попавшегося макета.
4. Сборка обоих вариантов и подтверждение, что чужой descriptor не включён.
5. После этого изменение генератора/подсказок редактора и инструкции перехода
   со старых проектных конфигураторов. Старые сохранённые проекты не ломать
   молчаливой заменой их стартовых блоков.

Текущий статус: v3 импортирован пользователем в FLProg; в реальном скетче
подтверждены a123_webui.h и вызов после SPI/Ethernet. Исправлены обратные
ссылки SIXx и Text/RunArray справки блока. Положительный путь собран для FLE4D
и проверен по OTA на 1.0.20-A123 и 1.0.21-FLE4D. Один блок генерируется для
всех ID; пакеты с дефисом/подчёркиванием проверяются тестами генератора.
Нативные отрицательные сценарии пустого ID, отсутствующего пакета и повторного
экземпляра ещё не проверены полностью. Одной проверки XML для них недостаточно.
Исходники чужого CRMui3 не переносились в наш runtime.

Отдельные папки описаны в EXTERNAL_PROJECT_RU.md. Номера и направления каналов
для подключения Publish/Command — в CHANNEL_CONTRACT_RU.md.
