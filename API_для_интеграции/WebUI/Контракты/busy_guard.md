# Блокировка повторной команды — FLE4D-30MT

Версия 1.0.6-WEBUI1.7 установлена по OTA на 192.168.100.8.

## Поведение

- Связь роли busy с bool-каналом: при true блокируется управление соответствующим виджетом.
- Проверка перед подтверждением и после диалога не позволяет отправить команду,
  если busy включился во время подтверждения.
- На контроллере повторная запись в этот канал отклоняется HTTP 409, включая запросы
  без ID виджета. Канал используется виджетом с активной bool-связью busy.
- После busy=false управление снова доступно. Прочие виджеты не блокируются
  сигналом busy другого элемента. Обычная блокировка на время HTTP-запроса сохранена.
- Подписи: «Выполняется», «Выполнено», «Авария», bool отображается как «да/нет»;
  отсутствующее значение — «нет данных». result остаётся значением схемы, а не квитанцией с ID команды.

Связь busy — именно bool. Для элементов без такой связи поведение прежнее.
Защита на сервере относится ко всем записям в связанный командный канал.

## Проверено

- JS-тесты: busy до отправки; busy, включившийся во время диалога; отключение и
  обратное включение кнопки; русские подписи всех трёх ролей.
- Реальный ПЛК: «Выполняется: да», кнопка отключена, независимое поле уставки доступно.
- Синхронизированный повторный POST при busy=true получил 409 «Команда уже выполняется».
  Счётчик был 2, после завершения стал 3: заблокированный запрос не добавил выполнение.
- При завершении «Выполняется: нет», «Выполнено: да», кнопка снова доступна.
- Первый ручной запрос повтора пришёл уже после окончания предыдущего выполнения и
  был законно принят; поэтому окончательная проверка синхронизирована с busy=true.
- Подпись «Авария» проверена JS-тестом, физическая авария на ПЛК не создавалась.
- HTTP-лимит сохранён: 14 маршрутов; максимальный статический ответ 1965 байт из 2048.
- Компиляция: Flash 135320, RAM 16112 байт; против 1.0.5 прирост Flash 704 байта, RAM 0.
- В тестовой прошивке команда занимает 5 секунд для наблюдения блокировки.
  Физические выходы ПЛК не переключаются, изменяется только RAM.

Пользователь отдельно подтвердил, что после проверки потери связи связь восстановилась.
Агент не измерял длительность этого отключения; подтверждение сохранено как сообщение пользователя.

Git/GitHub и готовый комплект r4 не менялись. Новые исходники хранятся в рабочей
flprog_webui_next и в библиотеке рядом с этой тестовой прошивкой; в r4 остаётся 1.0.5.
