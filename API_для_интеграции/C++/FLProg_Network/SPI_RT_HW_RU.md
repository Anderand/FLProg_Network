# Штатный SPI RT_HW для FLProg

flprogEthernet.h всегда подключает RT_HW для проводного профиля. Номер SPI и CS берутся из конструктора сгенерированного проекта и без преобразования передаются RT_HW. Выбор по модели контроллера или наличию ранее подключённого заголовка удалён.

Пример штатного кода — FLProgWiznetInterface(PB6,1). Он использует логическую шину RT_HW 1 с CS PB6. Отображение шины на аппаратные выводы задаёт проект и RT_HW. Значение bus=255 и отрицательный CS в вызовах по умолчанию берутся из getBusETH0/getCsETH0.

Каждый интерфейс содержит отдельный RT_HW-дескриптор. Его время жизни охватывает очистку DHCP и сокетов. Копирование запрещено во избежание переноса указателей backend.
При наличии spiGetLink отсутствующая шина возвращает FLPROG_SPI_STATUS_UNAVAILABLE до обращения к устройству. Для совместимых старых RT_HW без lookup API сохранён прежний контракт.
В исправлении нет delay и циклов ожидания.

Самостоятельные Arduino-проекты подключают flprogNetwork.h и используют его существующий явный SPI/backend API.
RT_HW_00_BASE и Flprog_Utilites устанавливаются штатно из FLProg. В эту библиотеку они не включаются.
RESET W5500 задаётся скетчем, отдельно от выбора SPI. Аппаратная проверка FLE4F ещё требуется.
