# API FLProg Network — комплект для интеграции Сергею

Срез r12 от 25.10.2026; код и прошивка соответствуют проверенному r11 / 1.0.9-NOTICES. Это справочный комплект, а не четвёртая устанавливаемая библиотека.

## С чего начать

1. Установите вручную три библиотеки из [Библиотека](../Библиотека). Заголовки из этой папки отдельно в IDE не копируйте: реализация `.cpp` находится в исходных библиотеках.
2. Возьмите готовый `FLProgNetworkInterface` проекта FLProg. SPI, Ethernet, DHCP/IP настраивает проект; WebUI и OTA используют его интерфейс.
3. [Машинный каталог сетевого API](WebUI/Каталог/flprog_network_api_catalog.json), [контракт проекта WebUI](WebUI/Контракты/WEB_UI_CONTRACT_RU.md), [связи виджетов](WebUI/Контракты/WIDGET_IO_CONTRACT_RU.md).
4. Для актуального HTTP-контракта смотрите [HTTP и команды](HTTP_И_КОМАНДЫ.md). Первоначальный WEB_UI_CONTRACT — исторический черновик; при расхождении приоритет у кода текущего адаптера.
5. [Все заголовки C++ и их источники](ИНДЕКС.md). Включены три библиотеки, сетевые transport/service/socket, WebUI и Modbus. Внутренние заголовки также перечислены для полноты; наличие в списке не обещает стабильного публичного API.
6. [Локальный API редактора](API_РЕДАКТОРА.md). Редактор: [сервер и его маршруты](../Исходники/WebUI/editor/server.py), [генератор пакета](../Исходники/WebUI/tools/build_project_package.py), [проверка проекта](../Исходники/WebUI/tools). Локальные `/api/*` редактора не являются API контроллера; сервер предназначен для localhost.
7. OTA STM32: [приёмник](../Библиотека/FLProg_Network/src/service/flprogNetworkOtaStm32Wiznet.cpp), [загрузчик по сети на Python](../Исходники/hardware_gates/STM32_W5500_GATE/OTA_APP_FLE4D/upload_fle4d_ota.py), [универсальный блок](../Библиотека/FLProg_Network/src/flprogOtaUniversalBlock.h). Формат бинарных пакетов и identity берите из этих реализаций; ESP ArduinoOTA — другой протокол.
8. [Примеры проекта](../Исходники/WebUI/projects), [проверенный FLE4D 1.0.9](../Примеры/FLE4D_1.0.9_NOTICES), [блоки FLProg](../Блоки_FLProg).

## Ограничения интеграции

Сохраняйте стабильные ID и типы каналов bool/int32/float/text, направления publish/command/duplex. Командное событие FBD извлекает один раз. Не добавляйте динамическую память в циклический FBD-код. Подтверждение приёма не равно выполнению; busy/result заполняет логика проекта. Нет идентификатора корреляции команды: параллельные операторы могут менять тот же канал.

Для W5500 сохранены 14 HTTP-маршрутов и фиксированные буферы; Flash-ресурс передаётся порциями без буфера размером с файл. Статические Flash-данные должны жить до закрытия ответа. Gzip готовится на ПК; макрос по умолчанию выключен. OTA требует правильного профиля и адреса приложения, не BIN по адресу загрузчика. Аппаратно проверен FLE4D-30MT / STM32F407VG / W5500; остальные конфигурации требуют отдельных испытаний.

Копии API зафиксированы в `MANIFEST_API.json`: путь к исходнику и SHA-256. Ссылки внутри скопированных старых справок могут быть относительно исходной библиотеки; используйте индекс для перехода к оригиналу. Инструкции ручной установки и запуска EXE — в [общем руководстве](../Инструкция.md).
