# Таблица каналов для FLProg

Нажмите **«Каналы FLProg»** в редакторе. Таблица строится по открытому макету,
включая ещё не сохранённые изменения. Она не меняет макет, номера CHANNEL и файлы проекта.

Для каждого канала показаны:

- стабильный номер **CHANNEL**, ID и название;
- тип `bool`, `int32`, `float` или `text`;
- направление данных относительно программы ПЛК;
- подходящие универсальные блоки Publish/Command;
- страницы, виджеты и роли связей: значение, уставка, busy, result, enabled и другие.

Фильтр **«Подключение к FBD»** оставляет пользовательские каналы №101–255.
Фильтр **«Автоматические»** показывает системные №0–100. Для системных каналов
блоки Publish/Command не нужны: их обслуживают библиотеки.

## Что подключать

| Направление | Блоки | Смысл |
|---|---|---|
| ПЛК → веб | Publish нужного типа | Фактическое значение из программы |
| Веб → ПЛК | Command нужного типа | Новая команда через выходы NEW и VALUE |
| ПЛК ↔ веб | Publish и Command с одним CHANNEL | Приём команды и возврат фактического значения |

Например, для `setpoint`, float, duplex, №101 нужны **Publish Float** и
**Command Float**, у обоих `CHANNEL = 101`. `NEW` — признак получения команды;
выполнение отслеживается отдельными каналами busy/result.

Номера не совпадают обязательно с позициями в массиве descriptor. Используйте
именно столбец CHANNEL, а не номер строки. Канал без виджета тоже попадает в отчёт:
он может быть нужен для FBD или следующей страницы.

## Файлы

В окне таблицы доступны **«Скачать Markdown»** и **«Скачать JSON»**. Браузер
сохраняет их в свою папку загрузок под именами `<ID>_channels.md` и `<ID>_channels.json`.

При сборке пакета редактор автоматически создаёт:

```text
libraries\FLProg_WebUI_Project_<ID>\
  CHANNELS_RU.md
  CHANNELS.json
```

Оба способа используют один генератор отчёта. JSON имеет схему
`flprog.webui.channel-contract/1.0` и содержит только описание каналов и связей.
Текущие значения, содержимое полей пароля и настройки подключения в отчёт не входят.
Пароли нельзя писать в названиях или подписях: эти поля являются публичным описанием макета.

## Границы проверки

Отчёт показывает, **какие блоки нужны**, но не читает `.flp` и не доказывает,
что они уже добавлены или правильно соединены. Сначала исправьте ошибки типов
и отсутствующие связи через **«Проверить проект»**. Несохранённые изменения
отражаются только в новом отчёте; уже скачанный файл — отдельный снимок.

Функция работает на компьютере и не добавляет код, Flash или ОЗУ в прошивку ПЛК.
