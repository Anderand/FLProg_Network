# Разработчику

## Где находятся исходники

| Компонент | Путь в репозитории |
|---|---|
| Network | `Библиотека/FLProg_Network/src` |
| Runtime WebUI | `Библиотека/FLProg_WebUI/src` |
| Modbus | `Библиотека/Flprog_Modbus/src` |
| Редактор | `Исходники/WebUI/editor` |
| Генератор пакетов | `Исходники/WebUI/tools` |
| Менеджер | `Исходники/hardware_gates/STM32_W5500_GATE/STM32_OTA_MANAGER` |
| Сборщик и загрузчик | `Исходники/hardware_gates/STM32_OTA_PORTABILITY` |
| OTA-блок | `Исходники/hardware_gates/FLProg_OTA_Block_v0_4` |

Готовые EXE, BIN и профили скачиваются из Releases. Штатные библиотеки RT_HW и Flprog_Utilites, полная IDE и toolchain в этот комплект не включаются.

## Проверки редактора

В каталоге `Исходники/WebUI`:

```powershell
python tools/verify_release.py
python tools/check_http_assets.py
python tools/test_audit_fixes.py
node --check editor/public/app.js
```

Эти команды проверяют структуру пакетов, отдельные ошибки генерации и синтаксис JS. Они не заменяют запуск EXE и аппаратную проверку веб-интерфейса устройства.

## Сборка EXE

Для опубликованных EXE использовались Python 3.8 x64 и PyInstaller 5.13.2. Совместимость с Windows 7 отдельно не испытывалась.

Менеджер собирается как `--onefile --windowed`, точка входа `flprog_stm32_ota_manager.py`. В пути поиска добавляются каталоги `STM32_OTA_PORTABILITY` и `OTA_APP_FLE4D`; нужен импорт `profile_policy.py`. `build_unified.bat` предполагает подготовленный `build_env_win7` и готовые артефакты сборщика. Сначала прочитайте его пути. `package_unified.py` упаковывает каталог загрузчиков; готовый проверенный профиль FLE4D необходимо сохранять в `portable_v6/profiles` из текущего комплекта.

Редактор собирается как `--onedir --windowed`, точка входа `editor/server.py`, hidden import `build_project_package`, путь импорта `tools`. Ресурсы: `editor/public → public`, `tools → tools`, `integration → integration`, `runtime → runtime`, `projects → projects`. Готовая папка целиком размещается в `Редактор`.

При переименовании README обновляйте `package_unified.py` и другие копирующие скрипты. Служебные `keywords.txt`, `boards.txt`, `boards.local.txt`, `boards_ota_append.txt` и конфигурационные фрагменты сохраняют исходные имена.

## Правила проверки OTA

Проверенность профиля не выставляется вручную по названию. В 0.7.7 политика `profile_policy.py` сопоставляет ID и точные хэши двух известных артефактов FLE4D. Новый BIN не наследует статус испытанного только потому, что был собран для той же модели.

Раздельно фиксируйте: сборка, контроль BIN/разметки, передача, старт новой версии, готовность сети после старта, повторное обновление. Для обнаружения ESP используйте DNS-SD-запросы; не начинайте обновление для проверки наличия OTA.

## Публикация

1. Обновите инструкции по изменившемуся поведению и таблицу версий.
2. Выполните проверки, соответствующие изменению; запишите ограничения и результат.
3. Исключите личные проекты, настройки, секреты, кэши и промежуточные сборки.
4. Сформируйте манифест SHA-256 файлов комплекта и ZIP.
5. Проверьте ZIP и соответствие файлов манифесту.
6. Опубликуйте исходники в Git, готовый ZIP и `.sha256` — в Releases.
7. При изменении опубликованного ZIP обновляйте обе контрольные суммы и описание релиза.
