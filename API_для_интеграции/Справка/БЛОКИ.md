# Справочник блоков FLProg

Файлы для импорта находятся в `Блоки_FLProg`. `.ubi` содержит отдельный блок, `.ubl` — комплект. Названия пунктов импорта зависят от версии FLProg. Копирование библиотек C++ и импорт блоков выполняются отдельно.

## OTA v0.4

Файл: `OTA/FLProg_OTA_Universal.ubi`. Добавляйте один OTA-блок на проект. Он использует уже настроенную сеть FLProg.

| Вход | Назначение |
|---|---|
| `EN` | Разрешение работы OTA |
| `NET_NUM` | Номер сети проекта; обычно 1 |
| `PASSWORD` | Пароль; пустая строка допускается |
| `VERSION` | Строка версии, например `1.0.1`; до 31 байта UTF-8 |

| Выход | Значение |
|---|---|
| `SUPPORTED` | Для платформы доступен backend OTA |
| `READY` | Приёмник готов к обновлению |
| `BUSY` | Идёт обновление |
| `FAULT`, `ERR` | Признак и код ошибки блока |
| `STATE` | Текущее состояние |
| `RX_BYTES` | Принятые байты текущего обновления |

Состояния адаптера: `0` — платформа не поддерживается; `1` — отключён; `2` — ожидание сети; `4` — готов; `5` — обновление; `6` — ошибка. Коды адаптера: `0` — нет ошибки, `1` — неподдерживаемая платформа, `2` — интерфейс не найден, `3` — конфигурация заблокирована, `4` — ошибка backend. Другие диагностические счётчики сетевой библиотеки имеют собственные значения и не должны трактоваться по этой таблице.

Настройте SPI/Ethernet штатными средствами проекта; блок не задаёт собственную распиновку. Модель STM32 поступает из профиля сборки, версия — из `VERSION`. Разметка и правильное смещение приложения проверяются при сборке.

Текущий STM32 backend охватывает F407 512/1024 KiB и F103 256/512 KiB с W5500. Импорт XML через интерфейс FLProg и аппаратная проверка каждой платы не объявляются выполненными. Подробности — в README папки OTA и [руководстве менеджера](OTA_МЕНЕДЖЕР.md).

## Диагностика W5500

Файл: `W5500_Diagnostic/FLProg_W5500_Diagnostic.ubi`. Входы — `EN`, `NET_NUM`. Сеть, SPI и консоль должны быть настроены в проекте FLProg.

Для быстрой проверки соедините выход **`LINE`** со строковым каналом **RT_HW Console**. Он содержит короткую строку: найден ли интерфейс, чип, SPI, счётчик обменов, link, готовность, IP и состояния DHCP/сети.

| Что нужно узнать | Выходы |
|---|---|
| Найден ли интерфейс | `FOUND`, `MODE`, `WIZNET`, `RMII` |
| Конфигурация и обмен SPI | `SPI_BUS`, `SPI_EFF_BUS`, `CS_PIN`, `SPI_STATUS`, `SPI_TX` |
| Чип и линк | `CHIP`, `CHIP_CODE`, `HW_STATUS`, `LINK` |
| Адрес получен | `ETH_READY`, `IP`, `IP_ASSIGNED` |
| DHCP и сеть | `DHCP_STATE`, `DHCP_ERROR`, `DHCP_SERVER`, `NET_STATUS`, `NET_ERROR` |
| Сводный результат | `RESULT`, `LINE`, `SEQ`, `MS` |

`RESULT=1`, когда интерфейс найден, код чипа равен 55, Ethernet готов и IP не равен `0.0.0.0`. При `EN=0` выходы сбрасываются. Блок сам не пишет в UART; выбранные значения передаются в консоль схемой пользователя.

## MQTT

Импортируйте `FLProg_Network_MQTT_Core.ubi`, `…_Publish.ubi`, `…_Subscribe.ubi`. Заголовок `flprogMqttUserBlocks.h` уже включён в библиотеку FLProg_Network комплекта.

Этот набор ожидает существующий Network Core с объектом `flpNetwork`, обслуживанием `flpNetwork.pool()` и настроенным WiFi A2. Для другого имени/контракта Core нужна адаптация. MQTT Core размещается один раз; Publish и Subscribe могут повторяться.

1. Задайте адрес Broker без `mqtt://`, Port (0 означает 1883) и уникальный ClientID.
2. Подайте `EN=1`. При необходимости задайте User/Password; пустой User означает работу без авторизации.
3. Дождитесь `Connected=1`, затем подайте положительный фронт Subscribe с Topic.
4. Для публикации подайте положительный фронт Send. При `ERR=1` (BUSY) повторите позже.
5. На приёме `Received` выдаётся на один проход; Message/RxTopic сохраняют последнее значение.

Ограничения набора: MQTT 3.1.1, QoS 0, текстовые сообщения, без TLS; входной буфер не является очередью всех сообщений. `Accepted` означает принятие команды, а не подтверждение доставки брокером. Поддерживаются фильтры `+` и `#`; успешные подписки восстанавливаются после потери связи.

Для этих блоков подтверждены проверки XML и ссылок; аппаратная работа именно FBD-блоков MQTT пока не подтверждена. Не переносите статус отдельного native-примера на весь набор блоков.

## WebUI

Файл `WebUI/FLProg_WebUI_Universal_Blocks.ubl` содержит общий комплект. Отдельно доступны восемь `.ubi`: Publish и Command для Bool, Float, Int и Text.

| Блок | Подключение |
|---|---|
| Publish | `EN`, `CHANNEL`, `VALUE`: отправка переменной схемы в интерфейс |
| Command | `EN`, `CHANNEL`; выходы `NEW`, `VALUE`: команда из интерфейса в схему |

`NEW` истинен один цикл при новой команде. `CHANNEL` — числовой номер из модели редактора. Конфигуратор `FLProg_WebUI_Configure_<id>.ubi` создаётся **редактором для конкретного проекта** и подключает его модель. Его нельзя заменить случайным конфигуратором от другого ID.
