# Описания виджетов одним ответом на страницу

27.10.2026. FLE4D-30MT / STM32F407VG / W5500, a123,
прошивка **1.0.23-WIDGETS**, IP `192.168.100.17`.

## Что изменилось

Генератор пакета записывает JSON описаний каждой страницы в сжатые
константы `PROGMEM` внутри существующего `<ID>_descriptor.h`.
Каталог содержит глобальные индексы и полные свойства каждого виджета.
Паспорт совместимости по-прежнему проверяет весь этот заголовок по SHA-256.

Метаданные страницы сообщают `widgetCatalog:true`. Браузер читает её
описания одним запросом `/flprog-webui/item?widgets=<ID страницы>`.
Сервер использует прежний Flash stream с порциями до 256 байт.
В a123 каталог 24 виджетов имеет 11669 байт JSON / 1306 байт gzip.
Большого RAM-буфера или новых полей объекта адаптера не добавлено.

RAM-очередь HTTP остаётся **2048 байт**, JSON-буфер — **1024 байта**,
HTTP-клиент один, маршрутов 14. Старые проекты без каталога и Network
без Flash stream продолжают читать виджеты по одному. Сборка без gzip
может передавать тот же постоянный JSON из Flash; аппаратно испытан gzip.

Каталог возвращается с `Cache-Control: no-store`: изменение проекта с тем
же ID не должно оставлять старые описания в кеше браузера. Данные каналов
по-прежнему читаются отдельно, а управление ПЛК не менялось.

Браузер проверяет страницу, количество, порядок индексов и обязательные
поля. Каталог применяется целиком после проверки; при неполном или чужом
ответе остаётся ошибка с повтором чтения. До успешной синхронизации
управление блокируется прежним механизмом.

## Сообщение «100%… Чтение данных ПЛК»

Раньше это сообщение оставалось и на время 24 чтений описаний.
Теперь показываются отдельные этапы: «Чтение списка страниц», «Чтение
описаний элементов» и «Синхронизация с ПЛК». Для старого протокола виден
счётчик элементов. Сообщения не стирают отрисованные поля и черновики.

В аппаратной проверке обнаружено, что запоздавший GET старой страницы
мог оставлять надпись синхронизации после восстановления связи. Исправлено:
первый успешный снимок снимает только сообщение этапа загрузки, сохраняя
отдельные сообщения команд. Финальный BIN повторно собран и установлен;
промежуточные измерения и квитанции сохранены в `initial_ota`.

## Сравнение

Прямой HTTP-клиент без кеша, последовательные запросы, полное чтение
ответов, gzip, одна и та же страница диагностики. Базовые три опыта взяты
из непосредственно предыдущей проверки 1.0.22; после финальной прошивки
выполнены три новых опыта. Фоновый опрос браузера на время замеров остановлен.

| Показатель | 1.0.22-BUNDLE | 1.0.23-WIDGETS |
|---|---:|---:|
| Всего запросов до первых данных | 29 | 6 |
| Чтений описаний 24 виджетов | 24 | 1 |
| Холодные проходы, секунды | 15.966 / 15.389 / 14.903 | 4.921 / 2.832 / 2.840 |
| Медиана | 15.389 с | **2.840 с** |
| Flash по компилятору | 167816 байт | 170360 байт |
| BIN | 168300 байт | 170844 байта |
| Статическая RAM | 19392 байта | **19392 байта** |
| Динамически занято по диагностике | 7304 байта | **7304 байта** |

Ускорение медианы — **5.419 раза**, сокращение времени — 81.55%.
Flash выросла на 2544 байта. Один опыт содержит сетевую задержку;
исправление не меняет цикл повторного TCP-соединения W5500.
Измерения прямого клиента не смешиваются с браузерным `data-load-ms`.
Актуальные показания браузера и снимок находятся рядом с протоколами проверки.
В финальном первом открытии встроенный браузер показал 976 мс после
получения HTML, 24 элемента и «На связи». Это одиночный браузерный замер;
его нельзя подменять медианой прямого холодного прохода. После переходов
между страницами сообщение синхронизации скрыто, данные обновляются.

## Проверки и файлы

- 95 автоматических тестов и `verify_release.py` прошли, включая проверку
  повреждённого каталога, порядка, атомарного применения, сохранения
  черновика и снятия этапа после запоздавшего чтения.
- Все свойства 24 виджетов сначала сверены с реальными отдельными ответами
  старой прошивки, затем с объединённым ответом новой — совпали полностью.
- Все ответы трёх финальных проходов — HTTP 200; `no-store` подтверждён.
- Перед OTA проверены модель, разметка, векторы и SHA BIN; получен `OKAY`.
  Автоматический перезапуск, версия, веб и идентификация OTA подтверждены.
- После финальной установки проверены браузер, 24 элемента, обновление
  системных данных и переходы между страницами. Выходы ПЛК не переключались.
- Проверка RAM относится к размеру программы и наблюдавшимся выделениям,
