# Пользовательские MQTT-блоки v0.1

Установка: импортировать три .ubi в библиотеку пользовательских блоков FLProg.
Скопировать flprogMqttUserBlocks.h в src установленной FLProg_Network.
На этом компьютере заголовок установлен при подготовке комплекта.

В проекте необходим существующий FLProg Network Core, создающий flpNetwork
и вызывающий flpNetwork.pool(), и настроенный WiFi A2. Данный комплект не
подходит без адаптации к варианту Core с другим именем объекта сети.
MQTT Core размещать один раз. Publish и Subscribe допускают повторение.

Core: EN=1 включает клиент автоматически. Broker — адрес без mqtt://;
Port — обычный TCP-порт, 0 означает 1883; ClientID — уникальное имя.
User/Password — данные брокера, пустой User означает без авторизации.
CON и DIS — команды по положительному фронту, DIS имеет приоритет.
Настройки применяются при включении EN или фронте CON.

После Connected=1 подать фронт Subscribe с нужным Topic. Accepted=1 означает
принятие команды, подтверждение подписки отдельно не выводится.
Затем подать фронт Send на Publish. При ERR=1 (BUSY) повторить команду позже.
Приём выдаёт Received на один проход блока, Message/RxTopic сохраняют данные.
Поддерживаются фильтры + и #. До четырёх фильтров по умолчанию в библиотеке.
Успешные подписки восстанавливаются MQTT-клиентом после потери соединения.

Ограничения: MQTT 3.1.1, QoS 0, без TLS; текстовые сообщения. Входной буфер
содержит последнее сообщение за проход сети: при пакете сообщений предыдущие
могут быть заменены. Это не очередь гарантированной доставки.
Accepted публикации не означает подтверждение доставки брокером.
Для WQTT использовать персональный адрес/обычный порт и учётные данные.
Обычный TCP передаёт их без шифрования; для защищённого подключения нужен TLS.

Проверено: XML, уникальность идентификаторов и разрешимость ссылок .ubi.
Импорт и генерация в FLProg, компиляция и аппаратная работа именно этих
блоков пока не проверены. Ранее проверялся отдельный native MQTT-пример.
Версия v0.1 предназначена для проверки импорта и генерации.
