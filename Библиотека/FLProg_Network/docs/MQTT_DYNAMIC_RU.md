# MQTT: период обслуживания и блоки Basic / Professional v0.3

В r15 снят прежний фиксированный предел в четыре фильтра. Таблица расширяется
при добавлении нового фильтра, по одному месту; при повторном фильтре не растёт.
По умолчанию `SUB_LIMIT=0`: число подписок ограничивает доступная RAM.
Пределы длины темы (127 байт), пакета (768 байт), MQTT 3.1.1/QoS 0 остаются.
TLS, QoS 1/2 и постоянная очередь сообщений в этой версии не добавлены.

## Установка

Обновите **FLProg_Network целиком** из папки `Библиотека` комплекта.
Ручная установка: закройте FLProg/IDE, замените только папку FLProg_Network в
`<IDE>\portable\sketchbook\libraries`. Штатные библиотеки не заменять.
Для STM32 требуется core 3.0.0. При сборке нашим менеджером можно использовать
внешнюю папку libraries, проверив, что именно новая FLProg_Network выбрана сборщиком.

Доступны два самостоятельных комплекта, в каждом Core, Publish и Subscribe:

- `Блоки_FLProg\MQTT\Basic` — базовый редактор пользовательских блоков.
- `Блоки_FLProg\MQTT\Professional` — профессиональный редактор. Входы и выходы
  оформлены штатными тегами редактора, код выполняется в месте установки блока.

Импортируйте UBI нужного комплекта через открытие библиотеки пользовательских
блоков FLProg. В проекте используйте **один Core**; Publish и Subscribe можно
размещать многократно. Не добавляйте одновременно Basic Core и Professional Core:
оба работают с одним клиентом. У профессионального варианта тот же набор входов
и выходов; это настоящий формат Code - Professional, а не переименованный Basic.

У Core v0.3 появился POLL_MS. При замене старого блока переподключите его входы.
Старые вызовы helper v0.1/v0.2 поддерживаются, с периодом по умолчанию 10 мс.
SPI, Ethernet и Wi-Fi настраивает существующий проект FLProg.

**Вызывайте сетевой интерфейс и все MQTT-блоки каждый цикл программы.**
Блоки проверяют фронты команд, а MQTT сам решает, когда обслужить свой сокет.
Не нужен отдельный диспетчер задач для замедления MQTT-блоков. Если вызывать
блок Send раз в 10 мс, короткий сигнал между вызовами можно пропустить.

## Core

| Вход | Значение |
|---|---|
| EN | Разрешение; фронт включает подключение и автоматическое восстановление |
| CON / DIS | Положительный фронт подключения / отключения; DIS имеет приоритет |
| NET_KIND | 1 — W5500, 2 — Wi-Fi, 0 — существующий реестр NetworkDevice |
| NET_NUM | Номер интерфейса FLProg 1..8; в режиме реестра его зарегистрированный ID 0..254 |
| POLL_MS | 0 — стандартные 10 мс; 1..1000 — период опроса MQTT в простое, мс |
| SUB_LIMIT | 0 — динамическое расширение; положительное число — добровольный предел |
| Broker / Port | Имя или IP брокера, порт 1..65535 (обычно 1883) |
| ClientID | Непустой уникальный ID клиента |
| User / Password | Учётные данные брокера, могут быть пустыми |

Настройки применяются при фронте EN/CON. Изменив параметры, подайте новый
фронт CON. При ошибочной конфигурации старая сессия закрывается.
`Connected` означает MQTT-сессию; `Busy` — текущую протокольную операцию;
`ERR`/`Error` — диагностику, `State` — состояние клиента.
`Subscriptions` — число фильтров, подтверждённых SUBACK;
`SubBytes` — байты выделенной таблицы (без служебных данных аллокатора).
Во время восстановления подписок новый запрос может вернуть BUSY:
повторите его новым фронтом позднее.

## Subscribe и Publish

Subscribe: Topic — фильтр, например `home/+/temperature` или `home/#`;
положительный фронт Subscribe ставит запрос в очередь. Accepted — местное
принятие запроса, не SUBACK. Подтверждение видно по Subscriptions/ERR Core.
При BUSY=1 запрос автоматически не повторяется; подайте новый фронт позже.
Received выдаёт импульс при получении подходящего текстового сообщения;
RxTopic/Message/Retained содержат его данные. Это последнее сообщение за цикл,
а не очередь без потерь. Одновременные частые сообщения могут заменять друг друга.

Publish: фронт Send, Topic без +/#, Message и Retain.
Accepted означает принятие клиентом в отправку; QoS 0 не имеет подтверждения
доставки брокером. При занятости повторите фронт после освобождения клиента.
Не используйте Accepted как подтверждение выполнения команды оборудованием.

Пример: Core EN=1, NET_KIND=1, NET_NUM=1, SUB_LIMIT=0, POLL_MS=0, Port=1883,
Broker=адрес вашего брокера, ClientID=уникальное имя ПЛК. Дождитесь Connected.
Подавайте фронты Subscribe для фильтров последовательно, после завершения
предыдущей операции. Пятый и последующие фильтры теперь принимаются.

## RAM, ошибки и жизненный цикл

На один сохранённый фильтр выделяется 128 байт при стандартной длине темы.
4 фильтра — 512 байт; 8 — 1024; 16 — 2048. До первой подписки таблица не
выделяется. Постоянные буферы MQTT и память String в эти числа не входят.
При ожидающем или отклонённом SUBACK возможно одно дополнительное место.
Увеличение таблицы иногда требует временно старый и новый участок RAM;
поэтому свободная память и её фрагментация влияют на доступный размер.

| ERR | Причина / действие |
|---|---|
| 1 | BUSY: повторить запрос позднее новым фронтом |
| 8 | Превышен размер пакета; это больше не ошибка числа подписок |
| 11 | Брокер отклонил подписку |
| 14 | Неверный/слишком длинный фильтр |
| 15 | Нет подключённой MQTT-сессии |
| 17 | Достигнут явно заданный предел SUB_LIMIT |
| 18 | Не удалось выделить RAM; сохранённые фильтры остаются |
| 19 | Core: выбранный сетевой интерфейс не найден |
| 20 | Core: отрицательный SUB_LIMIT, некорректный порт или POLL_MS вне 0..1000 |

При разрыве сети подтверждённый список сохраняется и восстанавливается
по одному фильтру. end()/begin() также сохраняют список, как раньше.
Для его явного удаления в C++: mqtt.end(); mqtt.clearSubscriptions();
деструктор освобождает память. Нельзя копировать владеющий памятью клиент.
setSubscriptionLimit(N) задаёт необязательный предел во время исполнения;
снижение ниже уже подтверждённых/ожидающих фильтров отклоняется без потери списка.
Старый FLPROG_MQTT_MAX_SUBSCRIPTIONS теперь задаёт только начальный предел,
по умолчанию 0. Для настройки используйте метод, а не define только в .ino.

## Период обслуживания и нагрузка

По умолчанию в простое опрашивается только MQTT-сокет раз в **10 мс**.
TCP-сокет и протокольный автомат используют одно расписание: общий обход
сокетов не выполняет второй независимый опрос MQTT каждый цикл.
Во время подключения, отправки, ожидания ответа и дочитывания пакета период
сокращается до **1 мс**. За проход — не более одного чтения или одной записи,
до **64 байт**. Чтение выполняется массивом, а не отдельным обращением к
W5500 за каждым байтом. `delay()` и ожидания в цикле не добавлены.

Принятые Send/Subscribe/CON/DIS будят обслуживание при ближайшем вызове
network.pool(), без ожидания 10 мс. Это не очередь произвольного числа команд:
если клиент занят, по-прежнему возвращается BUSY. Таймауты считаются по
исходному сроку операции; посторонние сообщения не продлевают ожидание SUBACK.
Keepalive и время повторного подключения также не ждут длинного POLL_MS.

Настройка POLL_MS влияет на начальную задержку входящего сообщения:
обычно до выбранного периода плюс время циклов программы и обработки сети.
Порции длинного сообщения затем читаются с интервалом 1 мс. Если PLC сам
выполняет цикл медленнее, библиотека не может обеспечить более частые вызовы.
64 байта ограничивают объём за проход, но не гарантируют конкретное число
микросекунд: оно зависит от SPI, драйвера и остальной программы.

HTTP, Modbus, OTA и общее обслуживание Ethernet этим таймером не замедляются.
Поэтому сокращение числа опросов MQTT не равно такому же ускорению всего цикла.
Таблица подписок продолжает динамически расширяться; постоянные буферы
пакетов остаются по 768 байт. Добавлено 12 байт статической RAM в контрольной
сборке F407 и локальный массив 64 байта на стеке чтения; общего измерения
пикового стека и динамической RAM на устройстве в этом этапе не было.

Для прямого C++ API: `mqtt.setPollInterval(10)`; `mqtt.pollInterval()` читает
период. Значение **0 в C++ API** отключает ограничение частоты для диагностики.
Вход **POLL_MS=0 в блоке** означает стандартные 10 мс. Эти два случая различаются.
Макросы READ_BUDGET/WRITE_BUDGET остаются верхними пределами; порция дополнительно
ограничена FLPROG_MQTT_IO_CHUNK_SIZE=64. Менять compile-time макросы нужно для
всей библиотеки, не только define в скетче. Для обычной настройки используйте POLL_MS.

## Проверено в r16

Полный C++ класс MQTT со стендом транспорта: 300 фильтров, переполнение счётчика
после 255, дубликаты, предел, искусственная нехватка RAM, повтор, отказ SUBACK,
восстановление 301 фильтра, очистка. Дополнительно: общий владелец сокета,
периоды, команды между опросами, короткие/нулевые чтения и записи, части и
несколько пакетов, таймауты, rollover millis(), keepalive и переподключение.

Все шесть UBI проверены структурно, включая направления/типы выводов и
обратные ссылки профессионального формата. Код обоих комплектов извлечён
из UBI и собран для F407/core 3.0.0; для профессионального варианта дополнительно
проверены повторные экземпляры Publish и Subscribe.
Это проверка кода и структуры; она не заменяет проверку генерации скетча
самим FLProg. Нативный импорт и генерация скетча в GUI FLProg ещё не включены
в подтверждённые результаты этого отчёта.

[Сравнение обращений к транспорту и памяти](MQTT_PERFORMANCE_RU.md).
Аппаратное измерение времени цикла с настоящим MQTT-брокером ещё предстоит.
ПЛК в этой операции не перепрошивался; рабочие устройства .116/.117 не затрагивались.
