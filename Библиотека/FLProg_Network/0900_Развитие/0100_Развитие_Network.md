# Развитие FLProg_Network: правила сопровождения

Редакция локальных правил от 05.11.2026. Это документация библиотеки, не исполняемый слой и не автоматически установленный навык Codex.

## 1. Принятый подход

1. При интеграции RT_HW физические SPI-операции выполняются общими сессиями RT_HW_BASE. Не копировать в сетевой адаптер последовательности lock/CS/transaction и не хранить второе состояние открытой сессии.
2. Использовать существующий FLProgRtHwSpiBackend, FLProgSpiBackend и готовый реестр flprogNetworkDevices. Не вводить параллельные адаптеры и реестры без доказанной необходимости.
3. Новые функции результата возвращают uint8_t. Указывать контракт: 1/0 или перечисление состояний. Не проверять перечисление с OK=0 как логический успех.
4. Старые virtual bool и busy-callback остаются только ради совместимости текущего сетевого API. Изменение контрактов всех backend — отдельная миграция.
5. Конструкторы и настройка в setup() пассивны. Обмен начинается после пользовательской платы «Инициализация». Временные выдержки — по millis/micros, без delay()/spin.
6. Аппаратный RESET имеет ровно одного владельца. NONE: схема модуля; EXTERNAL: приложение/профиль; MANAGED: библиотека. Для EXTERNAL завершить внешний сброс до первого сетевого pool().
7. Начальная выдержка восстановления — 500 мс, настраивается до старта. В MANAGED она начинается после отпускания RESET. Сам импульс по умолчанию 2000 мкс; это выбранный запас для теста, не универсальное требование всех Ethernet-чипов.
8. num — логический Ethernet-объект; bus — ресурс SPI RT_HW; CS и RESET — параметры профиля. Эти номера не подменяют друг друга.
9. Разные логические маршруты одного аппаратного SPI не считать независимыми шинами. Отображение и общая блокировка принадлежат RT_HW.
10. Частоту по умолчанию задаёт библиотека сети. Старый setSpiSpeed() сохраняет resetInit(); новый runtime-метод предназначен для вызова из loop между pool(), без сетевого сброса.
11. Текущий основной заголовок — flprogEthernet.h: RT_HW-фасад и фабрика теперь внутри него, RT_HW_BASE подключается явно. flprogRtHwEthernet.h — только перенаправление для ранних скетчей. Подробности окончательного решения — раздел 9. Arduino-backend сохраняется явным выбором объекта.
12. Модель платы и пины размещаются в описании/скетче, не в универсальном SPI-адаптере. RMII не получает фиктивный SPI-backend.

## 2. Что проверять перед выпуском

- Три режима RESET: управляющий GPIO используется только в MANAGED; NONE/EXTERNAL не вызывают writer.
- Нет GPIO/SPI-действий в setters и конструкторах. При отказе writer фиксируется ошибка, импульсы бесконечно не повторяются.
- RESET выполняется один раз при старте. resetInit()/DHCP retry не переармляют импульс.
- Сборки: DHCP NONE, DHCP MANAGED, EXTERNAL, полный проект и прежний Arduino-backend без optional header.
- Проверка SHA-256 RT_HW до/после; проверка только согласованных файлов сети; сохранённые исходные файлы и diff.
- Аппаратно: холодное питание, повторный запуск MCU, подключение кабеля, DHCP/static IP, Modbus TCP, смена частоты, другое SPI-устройство.
- Различать компиляцию, проверку логики на моках и аппаратное подтверждение. Ни одно не выдавать за другое.
- Хранить комментарии о временных решениях и причинах сохранения старых API. Не переписывать опубликованные архивы.

## 3. Накопленные наблюдения

- Отдельный RT_HW_Base.spiBegin(bus) не привязывает FLProg_Network к RT_HW. Требуется явный setWiznetSpiBackend()/ethBindRtHw().
- В установленной RT_HW сокращённый getCsETH0() возвращал bus; новый адаптер использует getETH_cs(0) при fallback. Рабочая RT_HW этим патчем не изменяется.
- spiInitDevice() уже вызывает spiBegin(), но требует custom=1. Нельзя возвращать успех, игнорируя status/err/codeErr.
- spiBeginSession() уже выполняет lock/transaction/CS. Повторный захват вокруг него — ошибка.
- Старое spiBeginSession() возвращает 1/0. Нельзя заменить отказ на RT_HW_BUSY=2 без миграции старых вызывающих функций.
- Повторный аппаратный RESET не является средством исправления отсутствующего кабеля или DHCP-сервера.
- Ошибка CRLF при генерации копий делала diff нечитаемым. Генератор должен нормализовать переводы строк до формирования patch; C++ сохранять UTF-8 без BOM.

## 4. Отложенные решения

1. Измерить цену виртуального вызова передачи каждого байта; рассмотреть поблочный интерфейс, сохраняя формат кадров разных Wiznet.
2. После аппаратного подтверждения оценить ссылку вместо _base-указателя и необходимость двух параметров шаблона.
3. Уточнить общий контракт аппаратных результатов RT_HW без размножения перечислений в сетевых модулях.
4. Включить optional-интеграцию в генератор FLProg: не требовать ручной правки каждого нового скетча.
5. Отдельно определить restart lifecycle для горячего отключения/включения питания модуля. Текущая последовательность — однократная при старте приложения.
6. Проверить другие MCU, Wi-Fi-only profiles, DMA/RTOS и несколько маршрутов одного физического SPI. Нынешний runtime-setter не является межпоточной очередью.

## 5. Политика принятия

Следующее архитектурное упрощение выполняется после подтверждения текущего Ethernet на железе. Не расширять общий RT_HW API только ради удобства одного сетевого адаптера. Изменения сначала проходят отдельную копию, затем устанавливаются с резервной копией и проверкой целостности.


## 6. Единый формат пинов · EIS 05.11.2026 v.02 · локальная редакция 1.6.1

Все новые API аппаратных пинов и их состояние используют uint8_t; 255 означает отсутствие пина. Не вводить новые int/-1 там, где пин передаётся в RT_HW. Тип результата функции также uint8_t, но его смысл указывать отдельно: у RESET setters/writer 1=успех, 0=отказ.

RESET согласован по всей цепочке: ethSetReset → setResetMode → _resetPin → FLProgEthernetResetWriter → ethRtHwResetWrite → GPIO RT_HW. MANAGED с pin=255 отклоняется до старта. NONE/EXTERNAL сохраняют 255 и nullptr writer; GPIO не используется. Собственный RESET-writer теперь обязан иметь сигнатуру uint8_t(uint8_t,uint8_t). Старый writer(int,...) нельзя подключать приведением указателя функции.

Передача широкого int в uint8_t API сужает значение до входа в функцию: 256 превращается в 0, -1 в 255. Поэтому данные из файлов, UI, внешних протоколов и переменных широкого типа проверять ДО сужения. Проверка pin<0 для uint8_t всегда ложна и запрещена как способ обнаружения отсутствующего пина.

Прежний virtual FLProgSpiBackend::configure(...,int requestedCs,...) сохранён для совместимости всех backend. Только в реализации RT_HW значения -1 и 255 выбирают CS первого Ethernet-профиля; остальные значения проверяются в int до преобразования. Отрицательные значения, отличные от -1, и значения >255 отклоняются; невалидный CS самого профиля тоже отклоняется. Внутренний CS имеет тип uint8_t. Прежний virtual int cs() возвращает -1 до конфигурации ради старых потребителей. Это явная граница совместимости, не новый формат пинов.

Важно различать отсутствие RESET и отсутствие явно заданного CS: для RESET MANAGED отсутствие — ошибка; для CS это запрос fallback к профилю, после которого необходим действительный CS. Молча превращать 255 в физический пин нельзя.

Старые CS/SCK/MISO/MOSI всей сетевой библиотеки в этой редакции не мигрируются; общий RT_HW и Arduino-backend не меняются. Полная миграция прежнего int API требует отдельного согласованного изменения интерфейсов и вызывающего кода.

Изменение 1.6.1 функциональное, поэтому сборки и бинарные файлы выпускаются отдельно от 1.6. Компиляция не подтверждает аппаратную работу. Результаты и границы проверки фиксируются в комплекте 2620.


## 7. Настройка до первого pool · EIS 05.11.2026 v.03 · локальная 1.6.2

Скетч задаёт параметры выбранного Ethernet-объекта: setPinRST(uint8_t pin=255), setSpeedSPI(uint32_t hz). uint8_t результат: 1 принято, 0 отказ. Эти методы можно вызывать в setup и в пользовательской плате «Инициализация», повторно до первого pool; последний принятый пин и последняя заданная частота определяют запуск. До первого pool только сохраняются параметры, без GPIO/SPI и без привязки backend. Назначение пина после первого pool возвращает 0 и не меняет сохранённую конфигурацию. Ноль Hz ошибочен; если отказ проигнорирован до первого pool, он останется виден как ошибка конфигурации. После старта setSpeedSPI допускает смену частоты между pool существующим runtime API, без resetInit/RESET/DHCP-restart.

Явный include flprogRtHwEthernet.h включает optional-автопривязку RT_HW. При загрузке программы регистрируются лишь две функции: фабрика существующего backend и writer RESET. RT_HW_Base в глобальной инициализации не используется. Первый pool чистого SPI Wiznet создаёт отдельный backend в статическом выровненном хранилище, привязывает его существующим setWiznetSpiBackend и применяет отложенные параметры. Физический SPI и RESET выполняют прежние библиотечные автоматы через RT_HW. До первого сетевого pool должна завершиться плата «Инициализация».

Фиксированных слотов столько же, сколько FLPROG_NETWORK_MAX_DEVICES. Это хранилище существующих backend, не новый реестр num, не драйвер и не вторая копия состояния SPI. Объекты живут всё приложение; слоты не переиспользуются при динамическом удалении/копировании интерфейсов. Исчерпание слотов возвращает ошибку, без heap и без совместного использования одного backend двумя интерфейсами. Горячее создание/удаление интерфейсов не поддержано этой локальной доработкой.

RMII/Wi-Fi исключены из автоматической SPI-привязки. Без optional-header остаётся прежний Arduino-backend. Явные setWiznetSpiBackend, useArduinoWiznetSpiBackend, setSpiObject и setSpiPins не подменяются автоматикой. Для setPinRST с MANAGED в новой интеграции требуется RT_HW writer; явно выбранный Arduino/custom backend без подходящего writer даёт отказ конфигурации, а не переключение GPIO чужим API. Старые ручные фасады и пользовательские writer сохраняются как совместимость.

Ошибка первого pool сохраняется внутри объекта: poolConfigurationStatus=2, isReady=false, status=5,error=3; повторной попытки выделения/частичной настройки нет. В скетче нет eisEthernetConfigOk и if вокруг pool. ModbusSlaveTCP::pool сам проверяет isReady до begin; его обычный вызов сохраняется и после потери сети. Возврат сетевого pool — прежний SUCCESS/WAIT/ERROR, его не путать с 1/0 новых setters.

Для setPinRST(255) выбран NONE: GPIO не используется, библиотечная выдержка восстановления 500 мс остаётся. Для назначенного пина выбран MANAGED: LOW не менее 2000 мкс, затем не менее 500 мс от фактического отпускания (кооперативный pool может удлинить интервалы); RESET однократный. Внешний RESET по профилю по-прежнему возможен через прежний EXTERNAL API, без второго владельца. В новой простой конфигурации прежние pinMode/digitalWrite RESET из сгенерированного setup нужно убрать/закомментировать.

Выбор Ethernet производится объектом, а не подменой num номером bus. Автохранилище не назначает сетевые num молча: прежние фасады по num используют существующий flprogNetworkDevices при явной регистрации. Официальный library.properties не меняется. Сборка и проверки типов не означают аппаратного подтверждения; генератор/CDI ещё не менялись.


### 7.1. Имена include: рекомендуемый и совместимый вход

Новые версии RT_HW-проектов подключают #include <flprogRtHwEthernet.h>. В новом полном pr3 именно эта строка активна, прежний #include "flprogEthernet.h" оставлен комментарием EIS_OLD. Оба пути работают в 1.6.2.

#include "flprogEthernet.h" (также угловые скобки) оставлен и помечен в шапке как вариант ДЛЯ СОВМЕСТИМОСТИ старого генератора. Если RT_HW_BASE.h уже присутствует до этого include, включается та же фабрика первого pool. Наличие RT_HW фиксируется до внутренних include, поскольку flprogUtilites сам включает RT_HW косвенно. Иначе обычный Arduino-проект неожиданно получил бы RT_HW-backend. FLPROG_NETWORK_RT_HW_AUTO=0 до header позволяет явно сохранить Arduino/manual путь. Рекомендуемый optional-header подключает RT_HW сам и не требует знания порядка остальных include.

Старую одноимённую библиотеку владелец удаляет/выносит самостоятельно; до этого дубликаты могут влиять на выбор Arduino IDE. Агент старые библиотеки не удаляет. В протоколе проверять фактически выбранный FLProg_Network и отсутствующие посторонние пути. Новый совместимый сценарий проверяется отдельной сборкой с кавычками и без явного optional-header.


## 8. Зависимость от Flprog_Utilites · 05.11.2026

Прямой #include "flprogUtilites.h" из src/flprogEthernet.h убран как избыточный; прежняя строка оставлена комментарием. Это не избавляет сеть от Utilities: активные include остаются в tcp/flprogEthernetClient.h, tcp/flprogEthernetServer.h, udp/flprogUdp.h и udp/flprogDns.h. Legacy-адаптеры используют определённые там числовые коды FLPROG_ERROR=0, FLPROG_SUCCESS=1, FLPROG_WAIT=2 и старые Ethernet/DNS/socket ошибки. Их нельзя автоматически заменить на FLPROG_NETWORK_SUCCESS=0/WAIT=1/ERROR=2: смысл чисел различается.

Полный pr3 дополнительно использует FlprogDiscreteOutputPin/FlprogDacOutputPin, flprog::isTimer, macAddresToString, ipToString, specialSetup/specialPool. Flprog_Modbus также включает Utilities через flprogModbusUtilites.h. Поэтому удалять папку Utilities из libraries сейчас нельзя считать проверенным действием: убрать redundant include и убрать библиотеку целиком — разные изменения.

План дальнейшего удаления зависимости: выделить явную границу старых сетевых констант совместимости без изменения значений; обеспечить самодостаточность header каждого TCP/UDP-адаптера; отдельно проверить зависимости Modbus; заменить применяемые в сгенерированном коде GPIO/DAC/таймеры/форматирование на согласованные API RT_HW и обновить генератор. Не переносить весь большой Utilities внутрь сети и не дублировать драйверы RT_HW. Полное удаление подтверждать сборками с действительно отсутствующей Utilities в отдельном изолированном комплекте, а не удалением одного include при продолжающемся транзитивном подключении. Физическую установленную библиотеку в рамках этого анализа не удалять.


### 7.2. Минимальный итоговый pr3 v.03

В итоговом полном pr3 сохранены исходные вызовы Ethernet pool и Modbus pool без дополнительных условий. Добавлены только рекомендуемый include и два пассивных назначения на плате «Инициализация»; ранний spiBegin и ручной RESET оставлены комментариями. Исправлены две подписи уже существующей диагностики, расширенный EIS-диагностический массив удалён. Старый подробный тест v.02 сохранён отдельно. Обратное восстановление всё ещё даёт весь исходный pr3 строка в строку.

В библиотеке граница первого входа в pool отдельно фиксирует запрет позднего назначения RESET; подготовка SPI выполняется только для выбранного чистого Wiznet. Это позволяет не связывать работу Wi-Fi/RMII с подготовкой SPI и не терять отложенный выбор backend при переключении транспорта. Эти поля — конфигурация объекта, не копия SPI sessionOpen. Компиляция не подтверждает аппаратное переключение транспорта.


## 9. Объединённый основной header · окончательное уточнение 05.11.2026 v.04

ЭТО УТОЧНЕНИЕ ЗАМЕНЯЕТ прежние рекомендации пунктов 7/7.1 о выборе optional-header. Основной вход для нового и прежнего кода теперь #include <flprogEthernet.h> или #include "flprogEthernet.h". Весь фасад ethBindRtHw/ethSetStartupDelay/ethSetSpiSpeed/ethSetReset, RESET-writer и фабрика существующих RT_HW-backend физически находятся в этом файле. Отдельного скрытого include flprogRtHwEthernet.h из него больше нет и цикла включения нет.

flprogRtHwEthernet.h оставлен только коротким перенаправлением на основной header для ранее выпущенных скетчей. Новому pr3 этот второй header не требуется. RT_HW_BASE включается основным header явно: это контроллерный RT_HW-вариант. Автоматическая RT_HW-привязка по умолчанию включена и выполняется только первым pool выбранного SPI Ethernet. Определение пинов/частоты остаётся пассивным до первого pool, обычные сетевой и Modbus pool в скетче сохранены.

Для прежнего Arduino SPI существует явный useArduinoWiznetSpiBackend() у выбранного объекта до первого pool. Дополнительный FLPROG_NETWORK_RT_HW_AUTO=0 отключает регистратор в данном TU; для всего приложения его нужно задавать всем TU, поэтому явный выбор backend предпочтительнее. Проверка Arduino-сценария — проверка выбора backend, а не доказательство отсутствия библиотеки RT_HW: новый объединённый header зависит от неё явно. RMII/Wi-Fi автоматически не получают SPI.

Прямой include flprogUtilites.h остаётся убранным из основного header; четыре legacy TCP/UDP-зависимости и зависимости Modbus/pr3 пока сохраняются, как описано в пункте 8. Содержимое Utilities не переносится внутрь Ethernet. Объединение header не означает устранение Utilities целиком.

Итоговый минимальный pr3 v.04 использует единственный основной сетевой header и две настройки на плате «Инициализация». Старые заменённые строки сохранены комментариями; весь исходник восстанавливается обратным преобразованием. Предыдущие варианты скетча сохранены отдельно. Матрица сборок должна включать прямой основной header, кавычки, старое перенаправление, MANAGED/NONE/EXTERNAL, явный Arduino и два интерфейса. Успешная сборка не заменяет испытание на контроллере.


Уточнение минимального pr3 v.04: исходная строка #include "flprogEthernet.h" сохранена без изменения. Дополнительный сетевой include отсутствует. Старые комментарии EIS_OLD относятся только к отключённым SPI/RESET и исправленным подписям.


## 10. Уточнение имени SPI API — 05.11.2026

Единственное имя метода настройки частоты — `setSpeedSPI(uint32_t hz)`. Ошибочный псевдоним удалён из API и актуальных скетчей.
