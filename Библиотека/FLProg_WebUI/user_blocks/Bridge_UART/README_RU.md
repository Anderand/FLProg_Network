# Автоматическая привязка проекта к FLProg Bridge

UART-блоки v0.2 используют проект, созданный редактором. Объект Server, службы WebUI и ресурсов Flash больше не нужно объявлять и регистрировать вручную.

## Обычный проект с Ethernet и вебом

1. Откройте .flpui новым редактором и выполните «Экспорт для моста».
2. Используйте созданную папку libraries этого проекта. Там находятся согласованные FLProg_WebUI и FLProg_WebUI_Project_<ID>. Штатные библиотеки не заменяются.
3. В существующем Web UI Start задайте ID, например FLE4D-30MT. Этот же ID автоматически выбирает проект для моста; повторять его во втором поле не нужно.
4. Добавьте один UART-блок Basic или Professional из папки Bridge_UART экспортированного пакета. Задайте EN, UART, BAUD, BUDGET, VERSION и MODEL.
5. Для FLE4D: UART=6, BAUD=115200, BUDGET=64. Пины PC6/PC7 задаются проектом FLProg. UART должен быть свободен от консоли и Modbus RTU.

## Проект только с UART

Используйте FLProg_Bridge_UART_Project_Professional.ubi. В параметре «ID проекта» укажите ID экспорта без кавычек, пути и расширения. Блок подключает <ID_bridge_entry.h> и не запускает HTTP-сервер. Отдельный Web UI Start для этого режима не нужен. Это тот же универсальный блок для разных ID, а не отдельный UBI на каждый проект.

## Версия и модель

VERSION — непустая строка версии. MODEL — строка модели; пустая даёт нейтральное FLProg controller. Не подставляйте название FLE4D для другой платы. Значения фиксируются при включении; для применения новых выключите EN и включите снова.

HELLO имеет ограниченный размер кадра. Слишком длинная идентичность или пустая версия дают ERR=7 до открытия UART; строки экранируются как JSON. Данные не обрезаются молча.

Другие коды, входы и счётчики описаны в руководстве UART-блоков. Вызывайте блок каждый цикл. READY означает запущенный UART, CONNECTED — активный сеанс моста, а не датчик USB-кабеля.

## Безопасная политика команд

Автоматическая привязка по умолчанию разрешает только чтение. Для команд проект должен явно установить свою политику и, при необходимости, обновление данных перед чтением:

```cpp
flprog_bridge_selected::binding().setHooks(myWritePolicy, myBeforeRead);
```

Сигнатуры совпадают с FLProgWebUiBridge::WritePolicy и BeforeRead. Это дополнительный проектный код для разрешения конкретных команд, а не ручная сборка сервера. На FLE4D контрольная сборка сохраняет ранее проверенные обработчики выходов. Сам UART-блок физическими DO/AO не управляет.

## Состав экспорта

<ID>_bridge_entry.h автоматически связывает модель каналов, идентичность и ресурсы. <ID>_bridge.h содержит сжатый сайт и SHA-256. HTTP-каталог виджетов вынесен в отдельный заголовок: UART-only не тянет HTTP-зависимость, обычный Web UI Start продолжает подключать каталог. Модель и слоты каналов общие для HTTP и UART, не дублируются.

Паспорт совместимости учитывает catalogApi=1 и bridgeBlockApi=1 и проверяет SHA всех новых заголовков. Для сборки таких пакетов нужен новый редактор/менеджер; старый менеджер может правильно отказаться от неизвестного состава паспорта.

## Проверено

Два разных ID, неизменность универсального UBI, обратные XML-ссылки и параметр Professional. Восстановленный код Basic/Professional совпадает; оба исполнялись на нативном стенде. Проверены HELLO, экранирование модели, запрет записи без политики, чтение каналов и полный сайт из Flash. Контрольный F407 1.0.12-BRIDGE-AUTO собран: Flash367404 байта, static RAM51948 байт (+848/+304 к1.0.10), BIN367912 байт. Это не аппаратное испытание: BIN не установлен, на ПЛК остаётся1.0.10.

Новейшие файлы находятся в рабочем комплекте. GitHub и ранее выпущенные архивы не изменены.
