# NTP: часовые пояса и летнее/зимнее время

Версия дополнения0.1. Это расширение библиотеки FLProg_Network и два новых блока
FLProg: Basic и Professional. Редактор, менеджер и прошивки мостов менять не нужно.

## Что добавлено

- Смещение стандартного времени от UTC в минутах: -720..840 (UTC-12..UTC+14).
- Постоянный пояс без сезонного перевода; дробные пояса также поддерживаются.
- Правила ЕС: последнее воскресенье марта/октября,01:00 UTC, перевод60минут.
- Правила США: второе воскресенье марта02:00 стандартного времени и первое
  воскресенье ноября02:00 летнего времени, перевод60минут.
- Собственные ежегодные правила в C++: месяц, номер недели1..4 или5=последняя,
  день недели0=воскресенье, час, минута и базаUTC/стандартное/местное до перевода.
  Поддерживаются южное полушарие и изменение на30минут, а также отрицательный сдвиг.
- Местная дата, действующее смещение и признак летнего времени.

Выбор «ЕС» или «США» означает конкретное правило, а не автоматическое определение
страны. Некоторые регионы не переводят часы. Это не встроенная историческая база
IANA: для дат прошлых законодательных режимов и после изменения закона правила
нужно задавать отдельно. Настройки не обновляются из Интернета автоматически.

Правила сверены29.10.2026 по первичным источникам:
[Директива2000/84/EC](https://eur-lex.europa.eu/legal-content/EN/TXT/PDF/?uri=CELEX%3A32000L0084)
и [NIST](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst).

## Совместимость

NTP, unixTime(), dateTime(), hour()/minute() и legacy unixID продолжают выдавать UTC.
Новые методы не переписывают часы контроллера и не меняют период/сеть NTP.
Пояс по умолчанию UTC, перевод отключён. Конфигурация отклоняется целиком при
ошибке: прежний пояс сохраняется; C++ setter возвращает false.

Состояние пояса занимает16байт на экземпляр NTP. Сам расчёт пояса не использует
String, malloc, системную TZ или дополнительные UDP-запросы. Блок хранит местную
дату и пересчитывает её только при изменении UTC-секунды или настройки. Строка
имени NTP-сервера в блоке хранится отдельно; весь блок не является zero-heap.

localUnixTime — знаковые64бит для представления местного календаря, включая
31.12.1969 при UTC=0 и отрицательном поясе. Это НЕ UTC Unix timestamp.
Для журналов/интервалов используйте ntp.unixTime(); осенью местный час повторяется.
Проверяйте hasTime()/VALID перед использованием даты.

## Блок NTP LocalTime

Импортируйте ОДИН нужный UBI из Basic либо Professional в соответствующий редактор.
Существующий сетевой блок проекта должен обслуживать network.pool(). Новый блок
не вызывает сетевой опрос сам и не меняет SPI, Ethernet или Wi-Fi.

| Вход | Значение |
|---|---|
| EN | Включить сервис |
| SYNC | Положительный фронт запроса синхронизации; при Busy запрос отклоняется, повторить фронт позже |
| NET_KIND |1=W5500,2=Wi-Fi,0=реестр сетевых устройств |
| NET_NUM | Номер интерфейса1..8; для реестра — ID0..254 |
| SERVER | Имя сервера, например pool.ntp.org |
| PERIOD_S | Период в секундах;0=3600;1..4294967 |
| TIMEOUT_MS | Таймаут ответа;0=15000;100..60000 |
| UTC_MIN | Стандартное/зимнее смещение в минутах |
| DST_MODE |0=без перевода;1=ЕС;2=США |

Для UTC+7: UTC_MIN=420,DST_MODE=0. Для UTC+5:30:330,0.
Для центральноевропейского стандартного UTC+1 с переводом:60,1.
Для восточного стандартного UTC-5 с правилами США:-300,2.

YEAR/MONTH/DAY/HOUR/MINUTE/SECOND — местная дата и время.
WEEKDAY:0=воскресенье..6=суббота. OFFSET_MIN — фактическое смещение, включая DST;
DST_ACTIVE — действует сезонная поправка. VALID — время ранее получено и блок
включён, а не гарантия связи с сервером сейчас. SYNCED — импульс успешного ответа.
При VALID=false календарные выходы0. Busy — обмен NTP. Error=(ERR!=0).
ERR100=интерфейс не найден;101=неверные параметры/пустой сервер;
102=неверный пояс/режим;1..13=существующие ошибки NTP.

Собственные правила доступны через C++ API; в этих двух блоках выбираются
постоянный пояс и два готовых правила. Автоматическое сохранение настроек в EEPROM
не добавлялось: значения подаются проектом.

## C++

```cpp
FLProgNetworkNtp ntp;
// Выбранную сеть передать как обычно: ntp.begin(network).
ntp.setServer("pool.ntp.org");
ntp.setTimeZone(420, 0); // UTC+7, без сезонного перевода
// Либо: ntp.setTimeZone(60, 1); // ЕС
// Либо: ntp.setTimeZone(-300, 2); // США
if (ntp.hasTime()) {
    const auto local = ntp.localDateTime();
    // local.year/month/day/hours/minutes/seconds/weekDay
    // local.offsetMinutes, local.daylight
}
```

Пример своего южного сезона (стандартUTC+10, поправка+60минут):

```cpp
bool ok = ntp.setDaylightRules(600, 60,
    FLProgNtpDstRule(10,1,0,2,0,FLProgNtpDstRule::Wall),
    FLProgNtpDstRule(4,1,0,3,0,FLProgNtpDstRule::Wall));
```

В Wall начало считается по стандартному времени, окончание — по времени
с сезонной поправкой. В Standard оба перехода считаются по стандартному времени;
в UTC — поUTC. Настраиваемая поправка от-180 до180минут, кроме0; итоговый пояс
тоже должен оставаться в диапазонеUTC-12..UTC+14.

## Ручное обновление из GitHub

Скопируйте обновлённую `Библиотека/FLProg_Network` поверх вашей FLProg_Network
в `<IDE>\portable\sketchbook\libraries`, не удаляя остальные собственные библиотеки.
Штатные RT_HW_00_BASE, Flprog_Utilites и Wire не заменяются. Установщика/BAT нет.
Импортируйте нужный UBI из `Блоки_FLProg/NTP/Basic` либо `Professional` и пересоберите
свой проект. Новый блок требует FLPROG_NTP_TIMEZONE_API=1.

Готовый архив r16 с EXE выпущен раньше этого дополнения и NTP0.1 пока не содержит.
Для NTP возьмите актуальную библиотеку и блоки из main (Code → Download ZIP).
Редактор и менеджер для этого изменения пересобирать не требуется.

## Проверки и ограничения

12592 сравнений реального C++ с независимым Python zoneinfo/IANA: границы сезонов,
дробные пояса, южное полушарие,30минут DST, високосные годы,2036/2038/2100,
границы uint32 UTC. Дополнительно: отрицательный сезонный сдвиг через Новый год,
ошибочные параметры сохраняют предыдущую настройку. Basic/Professional XML и
ссылки проверены, извлечённый из обоих UBI код скомпилирован и выполнен на нативных
заглушках. Проверен цикл2000 вызовов без повторного begin/сброса периода запроса.

и живой импорт UBI в FLProg отдельно не испытывались. Никакие ПЛК/ESP не прошивались.
Готовый общий релиз, IDE и GitHub не изменены.
