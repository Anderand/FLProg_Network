# HTTP 500 при загрузке controls.js — исправление 1.6.3

## Симптом

На странице контроллера выводится «Ошибка загрузки: controls.js». В консоли браузера запрос к этому ресурсу завершается `500 Internal Server Error`. Случай передан пользователем для STM32 с W5500.

## Причина в библиотеке

`FLProgNetworkHttpServer` ограничивает **весь HTTP-ответ** 2048 байтами: заголовок и тело находятся в одной очереди. Если ответ превышает этот размер, сервер выдаёт HTTP 500 с телом `response too large`.

В FLProg_WebUI 1.6.2 несколько JavaScript-ресурсов превышали этот предел. Размер одного только тела `controls.js` составлял 2014 байт, а вместе с заголовком — 2112. После него загрузка также остановилась бы на `widgets.js` или `boot.js`.

| Ресурс | Ответ до исправления, байт | Ответ 1.6.3, байт |
|---|---:|---:|
| controls.js | 2112 | 1967 |
| widgets.js | 2822 | 1887 |
| boot.js | 2571 | 1616 |
| elements.js | — | 1128 |
| boot-init.js | — | 1052 |

Исправление распределяет код между небольшими ресурсами. Буфер остаётся 2048 байт; используются 14 обработчиков при штатном лимите 14. Порядок загрузки сохранён: запуск интерфейса происходит после загрузки всех модулей. Удалено лишнее экранирование кавычек в HTML стилей управляющих виджетов.

Для каждого встроенного ресурса добавлена проверка размера при компиляции с резервом 128 байт под HTTP-заголовок. Статическая проверка `check_http_assets.py` также контролирует реальные ответы и ссылки загрузчика.

## Что сделать пользователю

1. Скачайте актуальный [общий архив релиза](https://github.com/Anderand/FLProg_Network/releases/latest).
2. Закройте FLProg и IDE. Скопируйте **`Библиотека/FLProg_WebUI`** из архива в `portable/sketchbook/libraries` своей реальной IDE с заменой файлов.
3. Проверьте `version=1.6.3` в `FLProg_WebUI/library.properties`.
4. Заново откройте FLProg, особенно если он использует виртуальный диск `Z:`.
5. **Пересоберите и заново загрузите прошивку своего проекта.** JavaScript встроен в бинарник контроллера; обновление только файлов редактора на компьютере не заменяет ресурсы работающей прошивки.
6. Откройте страницу контроллера и выполните обновление без кэша (`Ctrl+F5`).
7. В Network браузера проверьте ответы 200 у `controls.js`, `widgets.js`, `boot.js`, `elements.js` и `boot-init.js`. Новый загрузчик использует ключ кэша `webui39`.

Повторный импорт универсальных блоков и изменение схемы ради этого исправления не требуются: их контракт не менялся. Для записи используйте обычный согласованный способ прошивки именно этой платы. Не переносите BIN другого контроллера.

## Что подтверждено

Старые встроенные ресурсы воспроизвели ту же ошибку в локальном стенде с ограничением ответа 2048 байт. Исправленные ресурсы загрузили две страницы и виджеты без ошибок JavaScript. Проверены размер всех ресурсов, лимит обработчиков и генератор пакетов.

Это проверка причины и исправления на компьютере. Подтверждение на контроллере пользователя нужно после пересборки и записи его проекта. На рабочие ESP из текущей сети прошивки и команды сброса не отправлялись.
