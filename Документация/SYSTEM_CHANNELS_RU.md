# Системные каналы: что и через что передаётся

## Два диапазона

- **№0–100 — системные каналы.** Их источники — сетевые библиотеки,
  OTA identity и диагностика платформы. Дополнительный Publish-блок FBD
  для автоматических диагностических значений не нужен.
- **№101+ — пользовательские каналы.** Они связываются с логикой FBD:
  уставками, командами, значениями процесса, busy/result и т. п.

Модель, версия, IP, MAC, готовность сети, шлюз, маска, время работы и память
передаются как значения системных каналов. В текущем тесте даже счётчики
самопроверок перенесены в системные №98 и №99. Это тестовые поля, не новые
обязательные каналы обычного проекта.

## Путь значения

Источник в библиотеке → слот системного канала в FLProgWebUiModel →
HTTP `/flprog-webui/state` → привязанный виджет. Интерфейс и пользовательская
FBD-логика используют одну модель. Отдельной скрытой передачи памяти или
модели контроллера для виджетов нет.

У канала два идентификатора: числовой `index` в проекте/descriptor для FBD
и устойчивый текстовый `id` для привязок и HTTP. В HTTP-JSON ключом служит ID,
например `ram_static_used`. Номер не равен внутреннему порядку слота в массиве.
Номера назначаются при добавлении каналов, сохраняются в .flpui и при экспорте.
Не переименовывайте ID и не перенумеровывайте готовую FBD-схему произвольно.
В другом старом проекте свободные номера могут отличаться; список ниже —
точный контракт текущего FLE4D-теста, не обещание глобальной нумерации всех проектов.

Системные данные publish заполняются автоматически; системные command и
duplex, например применение Wi-Fi, идут из веба в библиотеку и обратно.
Редактор теперь подписывает эти направления на карточках каналов.
Числа памяти представлены десятичным текстом, чтобы отсутствие источника
можно было отличить от настоящего нуля; пустое значение → «Недоступно».
Время работы — int32, секунды из millis()/1000, без отдельного таймера.

Служебное обрамление HTTP (`revision`, `since`, корневой `uptime`, статусы
ACK, описание виджетов) остаётся частью транспортного протокола. Оно нужно
для кеша, синхронизации и распознавания перезапуска, а не заменяет каналы
данных интерфейса. Для виджета времени используется `system_uptime`.

Пользовательские №101+ в этом проекте — setpoint/title/run/actual/busy/result/
commands/running/permit. Полный машиночитаемый список — SYSTEM_CHANNELS.json
рядом с BIN; готовый редактируемый макет — projects/fle4d_current.flpui.

Диагностика памяти, флаги сброса, uptime, модель/версия защищены от POST,
включая ошибочное duplex-направление. Система не сообщает недоступные данные
как нулевые. Занятость CCM пока не измеряется: поле «Недоступно».
