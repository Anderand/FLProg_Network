# Шаблоны текстовых полей и собственные ошибки

25.10.2026. На FLE4D-30MT / STM32F407VG / W5500 установлена по OTA
**1.0.14-PATTERN**, адрес **192.168.100.12**, STM32 core3.0.0.
Git, EXE и общий опубликованный r13 не изменялись.

## Настройка

В свойствах виджета откройте «Поведение»:

- «Шаблон текста (ASCII)»: например `[A-Z]{2}-[0-9]{3}`.
- «Текст ошибки»: например «Введите код вида AB-123».

Шаблон применяется к text-input и password-input. Это ограниченное
подмножество регулярных выражений, одинаковое для браузера и STM32.
Без шаблона обычный текст по-прежнему поддерживает UTF-8.
С шаблоном значение ограничено ASCII; русские буквы в нём не поддерживаются.
Сообщение об ошибке может быть русским: до 96 байт UTF-8, одна строка.

JSON-параметры виджета: `pattern` и `validationMessage`.
Оба необязательны; старые проекты и C++-инициализаторы совместимы.
Нужны новые генератор и runtime FLProg_WebUI; готовая старая прошивка
от обновления одного редактора новых правил не получает.

## Поддерживаемые правила

| Правило | Значение |
|---|---|
| `AB-` | Литералы, регистр учитывается |
| `[A-Z]`, `[0-9]`, `[abc]` | Диапазон или набор ASCII-символов |
| `[^0-9]` | Любой ASCII-символ вне набора |
| `\d`, `\w`, `\s` | ASCII-цифры, буквы/цифры/подчёркивание, пробельные символы |
| `.` | Один ASCII-символ, кроме CR/LF |
| `?`, `*`, `+` | 0–1, 0–63, 1–63 повторения предыдущего элемента |
| `{n}`, `{n,m}` | От 0 до 63 повторений; n не больше m |
| `^`, `$` | Допустимы только в начале/конце; полное совпадение и так обязательно |
| `\.`, `\[`, `\` | Экранированные специальные символы |

Шаблон — максимум 63 печатных ASCII-символа. Значение — максимум 63 байта
и не больше maxLength поля. Группы, альтернативы, обратные ссылки,
просмотры вперёд/назад, флаги и `{n,}` не поддерживаются: проект выдаёт
ошибку с переходом к виджету. Для ограниченного диапазона используйте `{n,63}`.

Примеры: `[A-Z]{2}-[0-9]{3}` → AB-123;
`[A-Za-z0-9_.-]{1,16}` → user_01; `\d{4}` → 1234.
Пустой шаблон отключает дополнительную проверку, но сохраняет штатные
ограничения длины/диапазона/шага.

## Работа проверки

Браузер оставляет неверный ввод как черновик, показывает заданную ошибку
и не отправляет поле. После исправления старая ошибка снимается.
На ПЛК значение проверяется до записи в модель. Неверное значение получает
HTTP422 с JSON-ошибкой, без изменения канала. Отсутствие widget в URL
не обходит шаблон: проверяются связанные с командным каналом правила.
Для нескольких полей одного канала действуют все заданные шаблоны.
Пароль в тексте ошибки или уведомлении автоматически не подставляется.

На STM32 используется ограниченный matcher с двумя 64-битными масками:
без heap, рекурсии и возвратного перебора. Стек отдельно не измерялся.
В браузере тот же алгоритм обхода состояний; тяжёлый неоднозначный шаблон
не передаётся в полноразмерный движок регулярных выражений.

## Исправление HTTP-декодера

Тест обнаружил, что `%00` обрезал аргумент до проверки шаблона. В новой
FLProg_Network такие запросы отклоняются HTTP400 до декодирования.
Значение `%2500` остаётся буквальным `%00`, а не повторно декодируется.
Это отдельное исправление включено в библиотеку из данного набора проверки.
Для следующего релиза брать обе библиотеки отсюда, а не только WebUI.
IDE и прежние релизы не изменялись.
