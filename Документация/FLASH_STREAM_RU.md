# Порционная выдача из Flash — FLE4D

25.10.2026. Реализован `FLProgNetworkHttpServer::sendStreamProgmem()` для
нативного HTTP-сервера. Проверено по OTA на FLE4D-30MT / STM32F407VG / W5500.
Готовый общий релиз r9 и Git не изменялись.

## Как работает

```cpp
static const char page[] PROGMEM = "...неизменяемый ресурс...";
server->sendStreamProgmem(200, "text/html; charset=utf-8", page, sizeof(page)-1);
```

Последний необязательный аргумент — `"gzip"`. Длина всегда задаётся явно:
двоичные нулевые байты допустимы. Согласование Accept-Encoding выполняет
вызывающий код; WebUI gzip-обработчик уже делает это перед вызовом API.
Указатель должен оставаться действительным до закрытия соединения, обычно
это статический PROGMEM. Локальный массив на стеке обработчика передавать нельзя.

Обработчик формирует заголовки прямо в прежней очереди ответа, без отдельного
временного массива на стеке, и запоминает указатель, длину и
смещение. Сетевая передача идёт после возврата обработчика, в `pool()`.
За проход — не более одной записи; очередная порция тела — до 256 байт
и не больше настроенного writeBudget. Частично отправленная порция остаётся
в прежнем буфере до завершения. Нет циклов ожидания сети или компрессора.

Курсор использует union с уже разобранной строкой запроса. Поля URI,
аргументы, заголовки и тело запроса остаются отдельными. Защитный код не
затирает курсор после возврата из обработчика. Размер ClientContext на
STM32 остался **6120 байт**, что проверено `static_assert` против структуры r9.
Флаг режима занимает тот же байт, что прежний флаг structured response.

Очередь ответа остаётся **2048 байт**. Прежние `send`/`sendProgmem`
по-прежнему ограничивают полный ответ её размером. Новый API позволяет
общему телу быть больше очереди. После `sendStreamProgmem` дописывать
ответ через `print/write` нельзя. Legacy direct WebServer не меняется:
новый метод в этом режиме возвращает false. Проверяйте возвращаемый bool.

## Результаты на устройстве

- Ресурс 131072 байта передан точно по SHA-256 за 0.453 с.
- Gzip-ресурс 17255 байт передан точно за 0.063 с и распакован в те же 128 КиБ.
- Медленное чтение по 257 байт, окно 4096 байт: весь ресурс получен за 7.922 с
  в окончательном прогоне (8.015 с в предыдущем).
- Четыре обрыва TCP/RST: следующий HTTP-запрос успешно обслужен.
- Получатель прекратил чтение: соединение освобождено, следующий запрос принят.
- Во время остановленного HTTP-чтения восемь запросов идентификации OTA
  обслужены за 0–32 мс каждый. Основной цикл продолжал обслуживать другую службу.
- Все 15 обычных gzip-ресурсов WebUI после перехода на новый API совпадают
  с исходными. Уставка, подтверждение команды и busy/result проверены в браузере.

Тесты времени относятся к этой локальной сети и не являются гарантией скорости.
HTTP имеет один клиентский слот: второй веб-запрос может ждать завершения
текущего; непрерывное обслуживание FBD/OTA не означает параллельный HTTP.

## Исправление закрытия W5500

Первый тест узкого окна обнаружил обрыв при медленном чтении без HTTP-таймаута.
Принудительное завершение graceful close через 500 мс оказалось слишком коротким.
В новой библиотеке предел `FLPROG_WIZNET_SERVER_GRACEFUL_CLOSE_MS` — 5000 мс.
После изменения тот же тест проходит целиком. Ожидание выполняется состояниями
в `pool()`, без sleep и без дополнительного буфера. При незавершённом закрытии
слот может освобождаться дольше, чем в r9; граница ожидания остаётся конечной.
Предел настраивается макросом, физический обрыв линка по-прежнему закрывается локально.

## Память финальной сборки без стресс-данных

| Показатель | Gzip r9 | Stream 1.0.8 | Разница |
|---|---:|---:|---:|
| Flash по компилятору | 130856 | 131136 | +280 байт |
| Статическая RAM | 16112 | 16112 | 0 |
| HTTP ClientContext | 6120 | 6120 | 0 |
| BIN | 131340 | 131620 | +280 байт |

Контекст выделяется существующим механизмом сервера; нового выделения памяти
для потока нет. Пик всей кучи/стека отдельно не измерялся. Стресс-сборка содержит
большие тестовые массивы только во Flash и не является финальной прошивкой.
На ПЛК после испытаний установлена обычная **1.0.8-STREAM** без этих массивов
и без тестового HTTP-переключателя.

Исходники, обе сборки, протокол испытаний, host-тесты настоящих методов сервера,
проверка равенства контекстов и BIN сохранены в
`E:\SAI\FLProg_Network\Прошивки_для_проверки\FLE4D_FLASH_STREAM_FINAL`.
Для переноса нужны изменённые FLProg_Network и FLProg_WebUI вместе.
Остальные платы аппаратно не проверялись; установленные библиотеки IDE не менялись.
