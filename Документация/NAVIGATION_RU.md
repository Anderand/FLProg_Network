# Навигация и повтор чтения — проверка на FLE4D

25.10.2026. **1.0.12-NAV** установлена по OTA на FLE4D-30MT / STM32F407VG /
W5500, адрес **192.168.100.12**. Git, опубликованный r13 и EXE не изменялись.

## Поведение

Браузер сохраняет ID выбранной страницы в localStorage и восстанавливает
его после обновления. Ключ разделён по origin, пути и составу меню
(ID/названия). Если ID удалён или хранилище запрещено — первая страница.
Значения каналов и пароли не сохраняются.

После исчерпания трёх штатных GET-попыток загрузки меню/descriptor появляется
«Повторить чтение». Автоматического бесконечного цикла нет. Меню заменяется
целиком после успешного чтения, descriptor страницы фиксируется после чтения
всех её виджетов. При переходе управление блокируется до полного снимка
состояния без since. Запоздавший ответ предыдущей страницы отбрасывается
через epoch. Повтор чтения не отправляет и не повторяет команды.

## Проверено

- 33 автоматических теста и verify_release.py: восстановление страницы,
  удалённый ID, запрет хранилища, ошибка меню без дублей при повторе,
  атомарное чтение descriptor, full sync и отсутствие POST.
- На реальном FLE4D в IAB: «Управление» и «Диагностика», переходы и возврат
  на «Диагностику» после reload, в том числе напрямую на .12.
- Через временный локальный прокси: по три HTTP 503 для второй страницы
  меню и второго descriptor диагностики. После исправления — ручной повтор,
  меню без дублей, полный снимок состояния. Все пять прежних полей/кнопок
  отключены при ошибке descriptor. Успешные ответы прокси не менял.
- Тестовая вкладка отправила **0 POST**. Другие клиенты могли работать с ПЛК;
  этот счётчик относится только к тестовой вкладке. Выходы этим тестом не менялись.
- 22 gzip-ресурса считаны с ПЛК и побайтно совпали с исходниками; 14 маршрутов,
  прежний лимит 2048 байт, RAM-буфер HTTP не увеличивался.
