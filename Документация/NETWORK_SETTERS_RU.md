# Совместимость setPinRST и setSpeedSPI

12.11.2026. В исходники FLProg_Network добавлены методы, которые использует
сгенерированный проект `pr1`. До исправления компиляция останавливалась с ошибкой
отсутствующего члена класса: генератор использовал дополнение EIS от 05.11.2026,
а установленный комплект Network не содержал этих двух методов.

```cpp
WiznetInterface_10903301.setPinRST(255);
WiznetInterface_10903301.setSpeedSPI(20000000UL);
```

Исходник проекта менять не требуется. Обновите `FLProg_Network` из папки
`Библиотека` и пересоберите проект. Это обновление исходников после r17;
ранее опубликованный архив r17 и его готовые прошивки сохраняются без изменения.

## Настройка RESET

`setPinRST(255)` означает отсутствие пина RESET: GPIO не вызывается. До первого
SPI-доступа выполняется однократное неблокирующее ожидание 500 мс.

`setPinRST(pin)` для Arduino SPI backend назначает реальный GPIO. Вызов только
сохраняет параметры; первый `pool()` запускает импульс LOW не менее 2 мс и затем
ожидание восстановления не менее 500 мс. Цикл программы продолжает работать;
при редком вызове `pool()` фактические интервалы увеличиваются. Повторная
инициализация Ethernet или DHCP не повторяет импульс.

Метод вызывают в `setup()` до первого `pool()`. После начала обслуживания
перенастройка отклоняется. RESET не должен совпадать с CS; 255 никогда не
передаётся GPIO writer. Для RT_HW или пользовательского GPIO реальный сброс
задаётся явно через `setResetMode(..., writer)` низкоуровневого Wiznet-драйвера.
Высокоуровневый `setPinRST(pin)` с реальным пином отклоняет backend, отличный
от Arduino. `setPinRST(255)` допускается и для RT_HW.

Проекты, которые не вызывают новые методы RESET или задержки, сохраняют прежний
запуск без добавленной паузы.

## Частота SPI

`setSpeedSPI(hz)` принимает частоту в герцах: `20000000UL` — 20 МГц. До первого
`pool()` настройка сохраняется и применяется при подготовке сети. После запуска
её можно менять между вызовами `pool()`; новая частота действует со следующей
SPI-сессии без аппаратного RESET, `resetInit()` или перезапуска DHCP.

Метод не предназначен для ISR и внутренних SPI callback. Он отклоняет изменение
при захваченной этим Wiznet-драйвером SPI-сессии, частоту 0 и пользовательские
backend с неизвестным контрактом `configure()`. Поддерживаются штатные Arduino
и RT_HW backend. Старый низкоуровневый `setSpiSpeed()` сохраняет прежнее поведение
с `resetInit()`; заменять им новый метод нельзя.

Оба метода возвращают `1`, если настройка принята, иначе `0`. В Wi-Fi и RMII
они возвращают `0`. Если до запуска передана частота 0, первый `pool()` сообщает
ошибку конфигурации; её можно исправить повторным корректным вызовом до запуска.

## Состав исправления

- `src/flprogNetwork.h` и `.cpp`: совместимые методы, сохранение параметров,
  однократная подготовка перед обслуживанием Ethernet.
- `src/hardware/flprogWiznetHardware.h` и `.cpp`: RESET без блокирующих ожиданий,
  защита от поздней перенастройки, смена частоты без переинициализации.
- Публичные заголовки в `API_для_интеграции` синхронизированы с библиотекой.

Выбор SPI backend, остальные протоколы Network и штатные RT_HW-библиотеки
сохраняются. Обновление не меняет таблицы плат и не прошивает контроллер.
