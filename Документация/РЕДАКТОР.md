# Web UI редактор

Редактор создаёт интерфейс контроллера и пакет C++-библиотеки для проекта FLProg. Редактор на компьютере и веб-интерфейс прошитого контроллера открываются по разным адресам.

## Запуск и файлы

Запустите `Редактор/FLProg_WebUI_Editor.exe`. Через BAT `START_WEB_EDITOR.bat` запускается тот же EXE. В браузере откроется `http://127.0.0.1:8766/`.

| Файл или папка | Назначение |
|---|---|
| `.flpui` | Сохранённая модель: страницы, каналы, виджеты и оформление |
| `Редактор/projects` | Проекты, сохранённые локальным сервером |
| `Редактор/project_packages` | Пакеты при пустом поле «Папка пакетов» |
| `FLProg_WebUI_Project_<id>` | Сгенерированная библиотека проекта |
| `FLProg_WebUI_Configure_<id>.ubi` | Проектный конфигуратор для схемы FLProg |

Сохраните `.flpui` перед обновлением редактора. Пользовательские проекты не следует включать в публичный комплект без проверки содержимого.

## Создать проект

1. Откройте «Демо» для знакомства с возможностями либо «Новый» для пустого проекта.
2. Задайте ID проекта: 2–64 символа, латинская буква в начале, затем латинские буквы, цифры, `_` или `-`.
3. Выберите транспорт. Он должен соответствовать сетевому интерфейсу проекта FLProg.
4. Создайте каналы данных и разместите виджеты на страницах.
5. Свяжите виджеты с каналами подходящих типов.
6. Настройте подписи, размеры, положение и тему; сохраните проект.
7. Нажмите «Собрать и установить» и прочитайте итог внизу окна.

Каналы №0–100 зарезервированы для публичного сетевого API. Пользовательские каналы начинаются с №101. Номер `CHANNEL` в FLProg должен совпадать с номером канала модели.

Доступность виджета в палитре не означает, что каждое его сочетание с транспортом проверено на оборудовании. Ограничения генератора и фактические проверки находятся в `Исходники/WebUI/specification` и `Проверки`.

## Установить пакет и подключить схему

Автоустановка **сгенерированного пакета проекта** рассчитана на `C:\F-981\FLProg\ideV8\portable\sketchbook\libraries`. Это действие кнопки редактора; три базовые библиотеки комплекта устанавливаются вручную.

Для другой IDE можно заранее задать `FLPROG_LIBRARIES` с путём к её `portable\sketchbook\libraries`. Либо скопируйте созданную папку `FLProg_WebUI_Project_<id>` туда вручную. Итог сборки сообщает путь пакета и результат установки.

1. Импортируйте `FLProg_WebUI_Configure_<id>.ubi` из созданного пакета.
2. Добавьте конфигуратор в проект FLProg.
3. Импортируйте нужные универсальные Publish/Command-блоки из `Блоки_FLProg/WebUI`.
4. Свяжите переменные схемы с каналами, указав числовые `CHANNEL`.
5. Скомпилируйте и прошейте проект для своей платы.
6. Откройте **IP контроллера** и проверьте отображение и обмен.

## Что нужно пересобирать

| Изменение | Действие |
|---|---|
| Тема, подписи, положение или размер | Сохранить модель, пересобрать пакет и прошивку |
| Каналы, их номера или типы | Дополнительно проверить соответствие `CHANNEL` и связей FBD |
| ID проекта | Использовать пакет и конфигуратор нового ID |
| Библиотека runtime или контракт конфигуратора | Следовать README обновления; может понадобиться замена конфигуратора |

## Если редактор не открывается

Убедитесь, что архив распакован и EXE находится рядом с DLL и папками ресурсов. Проверьте, не открыта ли уже другая копия на порту 8766. Для диагностики доступен запуск EXE с другим портом, например `FLProg_WebUI_Editor.exe 18766`; откройте `http://127.0.0.1:18766/`.

Если сборка вернула ошибку, сохраните её текст и `.flpui`. Не считайте пакет установленным без успешного итога сборки.

## Новое в 1.7.0: связь, команды, поля и группы

Эти возможности относятся к странице **контроллера**, сформированной редактором.
Локальный редактор на `127.0.0.1` показывает макет, а не текущую связь с ПЛК.
После обновления установите FLProg_WebUI 1.7.0 вручную, пересоберите пакет проекта
и прошивку. Обновление EXE само по себе не изменяет уже прошитый контроллер.
SPI и Ethernet по-прежнему задаются в проекте FLProg.

### Статус связи

Вверху страницы контроллера отображаются «На связи» и возраст последнего успешного
обновления данных. Через 5 секунд без свежего ответа появляется «Нет свежих данных»;
поля и кнопки управления блокируются. Старые показания остаются видимыми вместе с
их возрастом. После восстановления опроса управление включается автоматически.
Опрос выполняется примерно каждые 1,3 секунды; тайм-аут отдельного запроса — 4,5 секунды.
Запросы выполняются последовательно: это сохраняет один клиентский слот HTTP на W5500.

### Приём и выполнение команды

На вкладке **Поведение** задайте текст «Подтверждение команды». Перед отправкой
появится диалог с этим текстом; пустое поле отключает диалог. У старых проектов
кнопка сохраняет прежний вопрос «Отправить команду?».

Во время ожидания ответа управление блокируется от повторного нажатия.
Ответ `202` с `queued:true` показывает «Принято контроллером». Эта надпись остаётся
после очередного опроса. Это подтверждение помещения команды в модель, а не
подтверждение физического выполнения оборудованием.

Для результата добавьте связь **result** с bool-каналом publish из FBD. Для занятости
и аварии используйте **busy** и **alarm**. Они выводятся под элементом. Эти значения
публикует ваша схема; они не являются автоматически связанными с номером команды
квитанциями. Не считайте прежнее `result=true` доказательством нового действия.

При тайм-ауте результат считается неизвестным. Команда автоматически **не повторяется**:
сначала проверьте состояние механизма. Отказ сервера отображается отдельным сообщением.

### Поля ввода

На вкладке **Поведение** задаются подсказка, единица измерения и максимальная длина.
Числовое поле также использует минимум, максимум и шаг. Отправка — кнопкой
**Применить** или клавишей **Enter**; **Escape** отменяет несохранённый ввод.
Обычный опрос не затирает редактируемый черновик даже после потери фокуса.
После отказа сервера черновик сохраняется для исправления.

Пустой текст допустим. Для чисел проверяются непустое значение, диапазон и шаг;
для даты/времени/цвета — формат браузера. Ноль отображается как `0`, а не пустая строка.
Длина текста — от 1 до 63 **байт UTF-8**, а не букв: кириллица обычно занимает два байта.
Пароль после подтверждённой отправки очищается в поле.

Сервер дополнительно проверяет тип команды, конечность и переполнение чисел,
длину текста. Для запросов редактора, содержащих ID виджета, также проверяет его
канал, числовой диапазон и шаг. Прямой API без ID виджета проверяет тип канала,
но не выбирает ограничения произвольного виджета. Это проверка корректности,
а не механизм авторизации или защиты сетевого доступа.

### Группы элементов

Откройте настройки элемента двойным щелчком и на вкладке **Основное** заполните
**Группа элементов**, например «Насосная». Задайте то же имя другим элементам.
Появится общая секция с заголовком. В списке предлагаются уже использованные имена.
Пустое имя оставляет элемент вне группы. Секции упорядочены по первому появлению
их элементов; вложенных групп пока нет.

В каждой группе независимая сетка из 12 колонок. X/Y отсчитываются внутри секции;
перетаскивание и W/H работают как прежде. Совпадающие координаты в разных группах
не являются пересечением. При назначении одной группы старым элементам проверьте
их локальные координаты. На узком экране контроллера карточки идут в одну колонку.

Пример: `Редактор/projects/grouped_controls.flpui`. Откройте его кнопкой **Открыть**.
Он демонстрирует уставку, подтверждение пуска, связь result и две группы, без сетевых паролей.

### Совместимость и ограничения

Старые `.flpui` открываются без конвертации. Новые свойства необязательные;
старые C++-инициализаторы дескрипторов продолжают компилироваться.
Каждый статический ответ ограничен 2048 байтами вместе с HTTP-заголовками.
JS разбит на части общего маршрута; лимит 14 HTTP-маршрутов не увеличен.
Не добавлены SSE, WebSocket, внешние CDN или новые зависимости.

## Проверка на STM32 — диалог подтверждения

В актуальных исходниках подтверждение использует HTML-диалог внутри страницы вместо блокирующего window.confirm. Опрос связи продолжается, доступны «Отмена», «Отправить» и Escape. На FLE4D-30MT проверены уставка, отмена, приём и переходы busy/result; [аппаратный отчёт](../Проверки/WEBUI_COMMANDS_FLE4D_2026-10-24.md). Изменение включено в локальный комплект r5.

## r5 — блокировка повтора и русские статусы

Свяжите роль **busy** с bool-каналом состояния из FBD. Пока значение true,
управление соответствующим виджетом заблокировано. Проверка повторяется после
диалога подтверждения. Другие виджеты остаются доступны, если у них нет активной busy-связи.

Контроллер проверяет тот же сигнал: повторная запись в связанный командный канал
получает **HTTP 409 «Команда уже выполняется»**, в том числе без ID виджета.
После busy=false кнопка снова доступна. Для элементов без busy-связи поведение прежнее.
Серверная защита относится ко всем записям в этот командный канал.

Подписи состояния: **«Выполняется»**, **«Выполнено»**, **«Авария»**;
bool отображается как «да/нет», отсутствующее значение — «нет данных».
Подпись появляется при наличии соответствующей связи busy/result/alarm.
result публикует схема: это не автоматически связанная с ID команды квитанция.

В тестовой прошивке **1.0.6-WEBUI1.7** команда занимает 5 секунд, чтобы было видно
блокировку. На ПЛК проверены отключение/включение кнопки и отказ повторного POST с 409;
счётчик вырос с 2 до 3, заблокированный запрос не добавил выполнение.
«Авария» проверена программным тестом; реальная авария на ПЛК не создавалась.
Пользователь подтвердил восстановление связи после своего отключения Ethernet.

[Подробный отчёт](../Примеры/FLE4D_WebUI_1.0.6/BUSY_GUARD_RESULT.md).

## r6 — состояния полей и синхронизация

Каждое поле показывает «Синхронизировано», «Есть изменения», «Отправляется…»,
«Принято контроллером» или «Ошибка: …». Рядом — последнее прочитанное значение ПЛК.
При связи value используется её канал, иначе основной канал; ввод адресуется
setpoint, если эта связь задана. Значение модели ПЛК не является измерением
физического выполнения механизма. Для пароля факт скрыт.

Опрос не затирает черновик после потери фокуса. Ошибка сохраняет ввод.
Enter/«Применить» отправляют, Escape возвращает последнее прочитанное значение ПЛК.
Подтверждение приёма команды не означает её выполнения оборудованием.

Уменьшение времени работы или счётчика ревизий вызывает полный запрос состояния.
После ошибки связи следующий запрос тоже полный, даже если новый счётчик больше
старого. Чистые поля обновляются; несохранённый ввод сохраняется и не отправляется сам.
После перезапуска прежнее подтверждение приёма чистого поля сменяется синхронизацией.

На FLE4D проверено повторной OTA-загрузкой 1.0.7 без обновления страницы браузера:
уставка 30.5 стала стартовыми 25, текстовый «Черновик» остался, а факт ПЛК — FLE4D test.
Если OTA меняет сам макет страниц/виджетов, страницу нужно обновить обычным способом.

[Аппаратный отчёт](../Примеры/FLE4D_WebUI_1.0.7/FIELD_SYNC_RESULT.md).

## r7 — проверка проекта и предпросмотр

**Проверить проект** показывает ошибки типов каналов, отсутствующие связи,
направления, дубликаты и предупреждения о пересечениях. Переход открывает
страницу и нужный раздел настроек виджета. Сборка автоматически повторяет
проверку. Ошибки блокируют сборку; намеренные наложения можно подтвердить.

**Предпросмотр** открывает настоящий веб-интерфейс с локальной моделью:
редактирование каналов, команды, потеря связи, перезапуск и busy/result.
FBD и оборудование не исполняются. Изменения модели не сохраняются в проекте.
Для этих двух функций обновление прошивки ПЛК не требуется.

[Проверка проекта](PROJECT_VALIDATION_RU.md) · [Предпросмотр](PREVIEW_RU.md).

Кнопка **«Демо: уставка и busy/result»** открывает готовый макет и сразу запускает предпросмотр. Макет preview_busy_demo.flpui включён рядом с редактором и в исходники.

## r9 — gzip

Пересобран EXE с генератором и runtime gzip. Режим FLPROG_WEBUI_GZIP_ASSETS=1 включается при компиляции скетча; по умолчанию 0. [BIN и память](../Примеры/FLE4D_WebUI_Gzip/README.md), [полный отчёт](GZIP_RU.md). Необходим обновлённый FLProg_Network из этого же комплекта. Предпросмотр продолжает использовать исходные распакованные ресурсы и не обращается к ПЛК.

## r10

Включена порционная Flash-выдача. В редакторе сохраняются проверка проекта и демо-предпросмотр. Gzip включается флагом FLPROG_WEBUI_GZIP_ASSETS=1 при компиляции; новый EXE не меняет контроллер автоматически. Отчёт FLASH_STREAM_RU.md находится в Документация и рядом с EXE.

## r11 — уведомления

Предпросмотр использует новый runtime с уведомлениями. Отправка, приём и чтение данных различаются; эти этапы не доказывают физическое действие оборудования. [Описание](NOTIFICATIONS_RU.md). Для контроллера нужно пересобрать/обновить прошивку; один EXE его веб не меняет.
